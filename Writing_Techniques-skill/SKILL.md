# Writing Techniques — 写作技法技能包

> **版本**：V1.0 —— 模板库架构 + 工程化深化（设定模板 schema 化；Core 程序化架构 `norms/` 按需加载 + 写作偏好库 + 字段级精确化 + 检测规则数据化；版本变更记录见仓库 CHANGELOG.md）

此技能是 Writing Techniques (WT) 体系的统一入口，覆盖小说创作的全生命周期。根据用户意图自动分发到对应子技能处理。

## 执行规则

1. **识别意图**：根据用户消息和上方路由规则，确定对应子技能
2. **读取子技能**：使用 Read 工具读取对应路径的 SKILL.md（路径相对于本技能根目录 `Writing_Techniques-skill/`）
3. **执行子技能**：严格按照子技能 SKILL.md 中的指令执行（包括是否进入计划模式、询问用户哪些信息等）
4. **歧义处理**：如果用户意图同时匹配多个子技能（如"写小说"可能触发创建新书或基础写作辅助），优先询问用户具体想做什么，或根据上下文（是否已有项目/是否在创作流程中）推断最合适的选择；**分卷润色相关**：「分卷写作配置」→ 剧情编辑（创建/编辑剧情时分卷配置），「调整分卷润色」→ 设定编辑（随时调整已有写作配置）
5. **跨技能调度**：子技能之间可按需互相调度（如创建新书后自动建议创建人物或编辑剧情；NSFW项目创建后触发NSFW偏好配置；人物创建涉及NSFW字段时协调NSFW技能做词汇选择；Write-Router 检测到零提示词指定章节时调度提示词增强先生成提示词再执行写作）。**创建阶段 Core 调度**：创建人物/设定编辑/剧情编辑/快速创建/提示词增强在产出供人阅读的文本后、写入文件或输出到对话前，将文本传入 Write-Router（轻量模式 `mode: "creation_phase"`），由 Write-Router 调度 Core 加工后返回——一切供人阅读的文本均受 Core 写作规范约束，一切正文类技能调度均经过 Write-Router

6. **标准写作流水线**：接收到用户创作意图后，路由至 Write-Router，由其按以下固定线路编排——`内容检测与判断` → `段落预分配` → `Core（基础文本加工）+ 专项技能（战斗/言情/NSFW）`→ `结果整合` → `长篇专项（伏笔/回忆）`→ `成品输出校验（校验+落盘）`。整个流水线由 Write-Router 独家驱动，各写作技能仅处理已分配的文本段落，不参与调度决策

7. **Write-Router 为所有正文类技能的文本加工调度唯一入口**：用户不直接调用 Core/Combat/Romance/NSFW 进行文本加工，创建阶段技能也不直接调用——所有正文类技能调度统一经过 Write-Router（`body/Write-Router/SKILL.md`）。正文写作走标准模式（步骤 0-8），创建阶段文本走轻量模式（`mode: "creation_phase"`，步骤 L0-L3）。例外：Combat/Romance/NSFW 可被用户直接触发进行**只读分析**（分析战斗写法/分析情感描写/NSFW配置）——此类触发不涉及文本加工和落盘。Write-Router 是 Core/Combat/Romance/NSFW **文本加工调度**的唯一调度源

8. **成品输出校验为唯一落盘入口**：任何技能（Write-Router/基础写作辅助/NSFW/战斗描写/言情写作/提示词增强/创建新书/剧情编辑/创建人物/设定编辑/长篇专项等）在将内容写入本地文件系统前，**必须**将待写入数据传入成品输出校验技能，由校验技能根据文件类型自动路由：正文文本（CPS.json 标点 + Core 结构）→ JSON（语法/模式/引用一致性）→ 结构化 MD（字段完整性/跨文件引用）。校验通过后由校验技能统一执行落盘。**不依赖用户手动触发，不经校验直接写入 = 流程违规**

9. **NSFW偏好传播**：当 `项目信息.json` 中 `content_rating` 为 `NSFW` 时，创建新书/设定编辑/NSFW首次调用均应触发偏好配置询问；偏好数据（`nsfw_output_level` / `nsfw_character_tone` / `nsfw_tier_range`）写入同一文件后，所有后续技能自动读取

10. **创建阶段文本必经 Write-Router → Core 加工**：一切供人阅读的文本（人物性格/简介/身形特点、作品简介/核心设定/世界观分类/剧情点/梗概、**提示词增强产出的写作提示词**等）在写入文件或输出到对话前，**必须**先经过 Write-Router（轻量模式）→ Core（基础写作辅助）按大纲文本规范（规范 1.5/1.6/5）加工。创建阶段技能不得绕过 Write-Router 直接调用 Core，也不得将未经加工的文本直接输出。示例链路：创建人物（用户输入 → 按模板组装 → **Write-Router 轻量模式 → Core 加工** → 成品校验 → 落盘）

## 注意事项

- 子技能 SKILL.md 中标注"必须首先进入计划模式（EnterPlanMode）"的，务必遵守
- 子技能之间的调度通过读取对应 SKILL.md 并按其指令执行来完成
- 路径均为相对于本技能根目录的相对路径，实际读取时需拼接完整路径（`Writing_Techniques-skill/` + 子路径）
- 写作配置（`写作配置.json`）和项目信息（`项目信息.json`）是所有子技能共享的权威数据源；`写作配置.json` 支持全局（大纲/正文双轨）+ 分卷覆盖（`分卷.{卷号}`）两级结构，分卷未配置时继承全局；`项目信息.json` 同时承载 NSFW 偏好字段（由创建新书/NSFW技能/设定编辑维护）、分卷信息（由剧情编辑维护）和伏笔数据（由长篇专项维护）
- 提示词数据（`Prompt.md`）由提示词增强技能产出，供基础写作辅助/NSFW技能在零提示词写作时读取；是连接大纲规划与正文执行的桥梁文件
- **数据外置原则（V1.0 整体设计思路）**：技能模块细化（模板/数据/规则分层）的同时必须防止臃肿——大块数据性内容（词汇表、模板文本、字段定义）一律外置 `templates/`（结构定义）与 `data/`（数据内容），SKILL.md 只保留规则与流程。数据文件经 `data/data-registry.json` 注册、被技能引用才有效，禁止孤立文件；新增数据文件必须遵循"建文件 → 注册 → 引用"三步
- **规格数据加载策略（机器规格）**：协议/检查项清单/阈值类大块数据（`packet-schemas.json`、`proofreading-checklist.json`、`foreshadowing-spec.json` 等）为**给机器读的规格**——LLM/Agent 首次调度对应技能时完整读取一次进入工作记忆，之后按记忆执行、**不重复读取**；仅当规格数据变更（版本升级）或新会话首次调度时重新读取。各技能 SKILL.md 内均有对应"加载策略"小节
