# Write-Router — 写作流水线路由调度中心

此技能是写作系统的**唯一调度中心**，负责接收用户写作意图，完成内容检测、段落预分配、技能调度、结果整合、以及后续流水线（伏笔→校验→落盘）的全流程编排。

## 核心定位

- **唯一调度入口**：所有写作相关意图统一由此技能接收和分发——用户不直接调用 Core/Combat/NSFW，由 Write-Router 代为调度
- **判断与预分配**：在文本进入任何写作技能之前，先完成内容类型检测和段落分割——哪些段落是一般叙事、哪些是战斗、哪些是 NSFW，提前判定并分组
- **解放 Core**：Core 不再承担检测/分割/调度/整合职责，只做一件事——接收文本+上下文，按规范矩阵优化后返回
- **流水线编排**：Core/Special → 整合 → Long（伏笔/回忆）→ Proofreading（校验+落盘），全流程由此技能驱动

## 触发条件

当用户表达以下意图时，主技能将路由到此技能处理：

- "润色这段文字"、"优化写作"、"帮我改一下这段"
- "写正文"、"开始写正文"、"写章节"、"写这一段"
- "改写"、"润色"、"优化一下"、"帮我看看这段"
- "写一场战斗"、"写打斗场景"、"优化这段打斗"
- "写 NSFW 内容"、"写成人内容"、"写床戏"
- "继续写"、"往下写"、"接着写"
- 用户在对话中提供待写入的正文内容
- 任何表达"对文本进行优化/润色/创作"的表述

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `润色配置.json` | `大纲/` | 润色模式，传递给 Core/Special | 只读 |
| `项目信息.json` | `大纲/` | 内容分级 + 分卷信息 + NSFW 偏好 + 伏笔数据 | 只读 |
| `主要角色.md` / `次要角色.md` / `龙套角色.md` | `大纲/人物/`（或分卷子目录） | 传递给各技能的角色上下文 | 只读 |
| `设定.md` | `大纲/设定/` | 世界观约束，传递给各技能 | 只读 |
| `Prompt.md` | `大纲/剧情/` | 预生成的写作提示词，零提示词时读取 | 只读 |

## 执行模式

由主技能调度时：跳过计划模式，直接按步骤执行。
用户直接触发时：进入计划模式（EnterPlanMode），列出处理步骤后执行。

## 步骤 0：零提示词检测与 Prompt.md 读取

**仅当用户未提供正文/提示词内容时执行**（如"写第3章""写正文"但无任何剧情描述或写作方向）。

1. 从用户消息中提取章节号（如"第3章"）
2. **分卷感知章号定位**：读取 `项目信息.json` → `volumes`：
   - 分卷多文件模式 → 根据 `volumes.list[].chapter_range` 匹配章号所属卷
   - 不分卷/单文件 → 跳过卷号推算
3. **Prompt.md 定位**：`大纲/剧情/Prompt.md`（优先）或 `outline/plot/Prompt.md`。分卷与不分卷共用同一文件——提示词增强技能统一写入此路径，不按卷拆分子目录
4. 若 Prompt.md 存在 → 查找目标章的 `prompt_text`：
   - 命中 → 提取完整提示词，跳过步骤 1 直接进入步骤 2（上下文预读取）
   - 未命中 → 询问用户：是否调度「提示词增强」先生成提示词
5. 若 Prompt.md 不存在 → 同上，询问用户是否先生成提示词

**由提示词增强技能调用时**：收到的数据包中已包含完整提示词，跳过此步骤。

## 步骤 1：上下文预读取

在判断和分配之前，一次性拉取所有必要上下文——后续各技能不再重复读取。

### 1.1 读取清单

| 顺序 | 文件 | 提取内容 | 用途 |
|------|------|---------|------|
| 1 | `项目信息.json` | `content_rating`、`nsfw_*`、`volumes`、`foreshadowing` | 内容分级判定、卷号推算、NSFW 配置传递 |
| 2 | `润色配置.json` | `正文.polish_mode` + `分卷` 覆盖项 | 传递给 Core/Special |
| 3 | 角色文件（三类） | 出场人物性格、战斗风格、关系 | 传递给 Core/Combat/Romance/NSFW |
| 4 | `设定.md` | 相关世界观规则 | 传递给 Core/Combat/Romance |

### 1.2 润色配置确认

**仅当待处理内容为正文类且将写入 `正文/` 文件夹时执行。**

读取润色配置后，向用户展示当前有效配置（不分卷时展示全局，分卷时展示卷覆盖），询问是否沿用。用户选择调整时更新 `润色配置.json`（通过成品输出校验落盘）。

## 步骤 2：内容类型检测与判断（判断功能）

> 此步骤是 Write-Router 的核心——在文本进入任何写作技能之前，先判定"这段文本是什么类型"，为后续预分配提供依据。

待处理文本按以下优先级逐级扫描：

### 2.1 NSFW 内容检测（三级扫描）

检测到以下**任一条件**时，标记为 NSFW 专项内容：

**一级 — 显性性词汇（直接命中）：**
文本中出现性器官直称、性行为动词、性相关体液词汇（如：阴茎、阴道、做爱、高潮、精液、爱液、操、干等及其同义词/代称），直接判定为 NSFW。

**二级 — 性场景描写（场景命中）：**
- 床戏/亲密接触场景（接吻以上尺度的身体接触描写）
- 自慰场景（涉及性器官触碰的描写）
- 性暗示场景（脱衣、抚摸、喘息呻吟等前戏/边缘行为描写）
- 情色幻想/性幻想（角色脑内明确的情色想象内容）

**三级 — 语境渗透（语境命中）：**
- 文本包含连续的性挑逗/性暗示对话（≥3轮）
- 角色互动以性吸引力为核心驱动力（如勾引、诱惑场景）
- 用户在上文已明确指示当前章为 NSFW 章节

**不触发条件：**
- 仅出现"胸"/"腿"/"臀"等身体部位词且上下文为正常描写 → 不触发
- 接吻描写如无进一步身体接触暗示 → 不触发
- 医学/生理卫生语境下的器官名称 → 不触发

### 2.2 战斗内容检测（四级扫描）

检测到以下**任一条件**时，标记为战斗专项内容：

**一级 — 兵器/攻击动词命中（直接命中）：**
文本中出现明确的攻击性动作描写——兵器格斗动词（斩、刺、劈、削、挑、扫、砍、戳）+ 徒手格斗动词（拳、掌、踢、踹、肘击、膝撞、摔、锁）+ 超能力攻击动词（轰、炸、射、燃、冻、电击）+ 枪械动词（射击、瞄准、扣扳机、换弹）——且该动作有明确的攻击目标（人），直接判定为战斗内容。

**二级 — 攻防交替（场景命中）：**
- 两方或多方对峙后发生肢体/兵器/能力冲突
- 格挡/闪避/招架 + 反击的往复描写
- 比试/切磋/决斗场景（即使是点到为止）
- 追杀/逃亡中的直接对抗（非单纯逃跑）

**三级 — 伤势描写+攻击意图（语境命中）：**
- 文本以伤势描写为主，且上下文表明伤势来源于人与人的直接对抗
- 角色在战斗后的状态评估/战果确认场景

**四级 — 战斗准备/收束（边界命中）：**
- 对峙/蓄势描写（拔剑、摆开架势、气息对峙）
- 战斗后的收剑/离去/沉默

**不触发条件：**
- 单纯的武器描述/兵器鉴赏（无攻击动作和攻击目标）→ 不触发
- 角色练功/独自修炼（无对手）→ 不触发
- 体育竞技非格斗类 → 不触发
- 军队/大规模战争描写（百人以上）→ 不触发
- 暗杀/偷袭一击致命（无往复攻防）→ 不触发
- 魔兽/怪物狩猎（非人与人）→ 不触发

### 2.3 言情内容检测（三级扫描）

检测到以下**任一条件**时，标记为言情专项内容：

**一级 — 情感互动关键词命中（直接命中）：**
文本中出现明确的情感互动关键词——表白类（"喜欢""爱""在一起""交往"等，用于表达情感而非日常客套）+ 暧昧类（"心动""心跳加速""脸红""不敢看""偷看"等）+ 情感状态类（"暗恋""吃醋""在意""舍不得""放不下"等）——且该关键词发生在角色之间的情感互动语境中，直接判定为言情。

**二级 — 浪漫互动场景（场景命中）：**
- 具有浪漫含义的肢体接触（牵手、拥抱、靠肩、整理头发/衣领、擦眼泪等）
- 表白/确认关系的场景（不论结果）
- 约会场景（吃饭/看电影/逛街/散步/看日出等日常活动，但以情感互动为核心）
- 争吵后和好/冷战中的情感对峙
- 思念/触景生情的独处段落（角色的情感指向另一个特定的人）

**三级 — 单方情感体验（语境命中）：**
- 大段内心独白以对另一个角色的情感为核心内容
- 角色的行为动机明确由对另一人的情感驱动（如"为了让他注意到我""不想让他失望"）
- 回忆与另一个角色的过往互动（且回忆带有情感色彩——怀念/遗憾/甜蜜）

**不触发条件：**
- 日常社交礼仪中的"谢谢""不客气""再见"等客套用语 → 不触发
- 纯友谊/兄弟情/战友情（无浪漫暗示）→ 不触发
- 家人之间的关怀（父母/子女/手足）→ 不触发
- NSFW 性场景（由 2.1 三级扫描优先捕获）→ 不触发，由 NSFW 处理
- 角色对非人类对象的情感（如"我爱我的猫"）→ 不触发
- 职业关系层面的"欣赏""钦佩""信任"（无浪漫暗示）→ 不触发

### 2.4 内容类型判定结果

扫描完成后，按段落标记类型：

| 标签 | 含义 | 目标技能 |
|------|------|---------|
| `general` | 一般叙事/对话/描写 | Core（基础写作辅助） |
| `nsfw` | NSFW 成人内容 | NSFW 专项写作 |
| `combat` | 战斗对决内容 | 战斗描写专项 |
| `romance` | 言情/恋爱内容 | 言情写作专项 |

## 步骤 3：段落预分配（预分配功能）

> 在检测完成的基础上，将全文按段落拆分为独立的任务单元，标注每段的类型和边界，然后按类型分组打包——各写作技能接收到的是"已经分好的、只属于自己的那部分文本"。

### 3.1 段落分割

以段落为单位遍历全文，为每个段落打上类型标签（`general` / `nsfw` / `combat` / `romance`）。

### 3.2 边界合并

两个同类型的段落组之间如果仅隔 ≤2 个 `general` 段落，合并为同一段落组（避免因一句环境换气把同一场戏拆成两段）。

### 3.3 生成分配清单

```
[内部] 段落分配清单

段落组 1（L1-L3）：general → Core
段落组 2（L4-L12）：combat → 战斗描写专项
段落组 3（L13-L14）：general → Core
段落组 4（L15-L22）：romance → 言情写作专项
段落组 5（L23-L28）：nsfw → NSFW 专项写作
段落组 6（L29-L31）：general → Core
```

### 3.4 打包数据并分发

为每个段落组生成数据包，附加上下文信息（前后各一段非同类文本供语境参考），然后按目标技能并行/串行分发。

## 步骤 4：调度写作技能处理

### 4.1 分发到 Core（一般段落）

将所有标记为 `general` 的段落组打包，传递至 Core：

```
{
  "text": "{一般段落组文本（可能包含多个不连续的段落组，以分隔符标记）}",
  "context": {
    "chapter": "{当前章号/章名}",
    "volume": "{当前卷号或 null}",
    "content_type": "{叙事文本/对话文本/描写文本/大纲文本}",
    "prose_mode": "narrative"
  },
  "polish_mode": "{有效润色模式（已解析卷覆盖）}",
  "polish_config": { "{完整的润色配置 JSON}" }
}
```

Core 返回：`{ "processed_text": "{优化后文本}", "changes_summary": "{调整摘要}" }`

### 4.2 分发到战斗描写专项

将所有标记为 `combat` 的段落组打包，传递至战斗描写专项：

```
{
  "text": "{战斗段落组文本}",
  "context": {
    "chapter": "{当前章号/章名}",
    "volume": "{当前卷号或 null}",
    "combat_type": "{冷兵器/徒手/超能力/枪械/混合型}",
    "detection_level": "{一级/二级/三级/四级}",
    "involved_characters": ["{角色名}"],
    "surrounding_text": "{前后各一段非战斗文本}"
  },
  "polish_mode": "{有效润色模式}",
  "content_rating": "{项目信息中的 content_rating}"
}
```

战斗技能返回：

```
{
  "processed_text": "{处理后的战斗段落文本}",
  "combat_type": "{战斗类型}",
  "exempted_norms": ["规范2"],

}
```

### 4.3 分发到 NSFW 专项写作

## 步骤 5：结果整合

所有分发的技能返回结果后，Write-Router 执行整合。

### 5.1 段落拼合

按步骤 3.3 的分配清单，将各技能返回的 `processed_text` 按原位置拼回全文中。

### 5.2 豁免收集

收集所有专项技能返回的 `exempted_norms`，取并集。此并集将传递给成品输出校验，告知哪些规范已被专项技能覆盖。

### 5.3 专项元数据汇总

收集所有专项返回的元数据（`combat_type`、`nsfw_tier_used`、`sexy_value`、`romance_type`、`key_changes`、`ooc_warnings`、`combat_notes`、`romance_notes`），汇总为最终输出的元数据段。

### 5.4 全文一致性过检

对拼合后的全文做过检——确保专项段落与一般段落在整体节奏、换气频率上协调，不出现断层。

如有 `ooc_warnings`，向用户展示并确认。

## 步骤 6：调度长篇专项（伏笔/剧情回忆）

整合完成后，检查是否需要伏笔管理或剧情回忆：

1. **伏笔检测**：如战斗/言情/NSFW/一般段落中用户标注了伏笔提示，或文本中存在暗示后续发展的关键信息（隐藏实力、未展露的招式、遗留的伤势、暗恋未说出口、关系阶段变化等）→ 自动调度「长篇专项」进行伏笔登记
2. **剧情回忆**：如用户提及前文章节事件、或文本中涉及需要回溯的跨章线索 → 调度「长篇专项」进行情节回忆

传递数据包：

```
{
  "trigger_type": "{foreshadowing / recall / both}",
  "chapter": "{当前章号}",
  "volume": "{当前卷号或 null}",
  "hints": ["{检测到的伏笔提示或回忆需求}"]
}
```

长篇专项处理完成后返回确认信息。

## 步骤 7：调度成品输出校验（落盘）

流水线最后一步，自动调用「成品输出校验」技能。传递完整数据包：

```
{
  "type": "prose",
  "content": "{整合后的完整文本}",
  "file_path": "{目标写入路径，如 正文/第三章 初入江湖.md}",
```

## 注意事项

- **唯一调度入口**：所有写作相关意图必须经过此技能——不允许绕开 Write-Router 直接调用 Core/Combat/Romance/NSFW
- **判断优先于处理**：内容检测和段落预分配在调用任何写作技能之前完成——各写作技能收到的已是"已分类、已分组"的文本
- **Core 已解放**：Core 不再承担检测/分割/调度/整合职责，只做纯文本优化。Write-Router 不要将这些职责再传回 Core
- **并行与串行**：Core/Combat/Romance/NSFW 之间无依赖关系（各处理各自的段落组）→ 可并行调用。长篇专项和成品输出校验依赖整合结果 → 必须串行
- **专项技能之间的段落重叠**：同一段落不可能同时属于两个专项——NSFW 检测优先级高于战斗检测。如某段落同时命中 NSFW 和 combat，按 NSFW 处理（NSFW 场景中的肢体冲突属于情色语境，不属于对决）
- **始终以 Markdown 格式输出**文本内容
