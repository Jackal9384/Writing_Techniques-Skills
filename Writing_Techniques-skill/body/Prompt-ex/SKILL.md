# 提示词增强

此技能是写作系统的**提示词自动化引擎**，桥接剧情大纲与正文写作——将大纲中一两句话的章节描述，扩展为包含人物状态、段落结构、写作规范、伏笔指令的完整 LLM 可执行提示词。

## 核心定位

- **大纲→提示词转译**：读取 `剧情大纲.md` 中目标章的简短描述 → 融合人物/设定/润色配置/伏笔数据 → 输出结构化写作提示词
- **计划模式驱动**：所有操作必须先进入计划模式（EnterPlanMode），列出上下文预读取范围与扩充策略，用户批准后执行
- **多源上下文聚合**：同时读取剧情大纲、人物存档、设定文件、润色配置、伏笔数据、NSFW 偏好——一章提示词所需的全部上下文一次性拉齐
- **执行可选 + 批量持久化**：提示词输出后询问用户是否立即执行；批量处理时经用户允许后将全部提示词存储至 `剧情/Prompt.json`，供后续随时调用

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `剧情大纲.md` | `大纲/剧情/` 或 `outline/plot/` | 章节描述的唯一数据源 | 只读 |
| `Prompt.json` | `大纲/剧情/` 或 `outline/plot/` | 批量模式下经用户允许后持久化生成的提示词 | 读写 |
| `项目信息.json` | `大纲/` 或 `outline/` | `content_rating`、NSFW 配置、伏笔数据 | 只读 |
| `润色配置.json` | `大纲/` 或 `outline/` | `正文.polish_mode`（轻度/中度/重度） | 只读 |
| `人物存档.md` | `大纲/人物/` 或 `outline/characters/` | 出场人物性格、关系、当前状态 | 只读 |
| `设定.md` | `大纲/设定/` 或 `outline/settings/` | 世界观约束、核心设定、故事走向 | 只读 |

## 触发条件

### 直接触发

当用户消息中出现以下表述时，调用此技能：

**A. 自动补充类（单章）**：
- "你再帮我补一点" / "帮我补一下这章" / "补全这章"
- "扩充一下这章" / "展开这章" / "丰富一下"
- 用户提供了极简的章节提示（≤50 字），要求扩充为完整写作提示词

**B. 零提示词指定章节类**：
- "写XX作品的第XX章"（无任何额外提示词）
- "写第XX章"（当前项目下，无其他描述）
- "开始写第XX章" / "继续写下一章"（无章节内容描述）
- "生成第XX章的写作提示词"

**C. 批量生成类**：
- "批量生成章节提示词" / "自动生成第X到第Y章的提示词"
- "帮我把大纲所有章都转成提示词"
- "全自动写作" / "按大纲自动写"

### 由其他技能调度

当「基础写作辅助」(Core) 或「剧情编辑」检测到用户无提示词直接指定章节时，可调度此技能先生成提示词再执行写作。

## 执行模式

**必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出：
   - 目标章节范围（单章或多章）
   - 将读取的上下文文件清单
   - 扩充策略（轻度/中度/重度润色模式、NSFW 档位判断）
   - 输出提示词数量与结构
   - 如为批量处理：是否写入 `Prompt.json`
3. 等待用户批准计划后执行
4. 提示词输出后，询问用户是否立即执行；批量处理时询问是否写入 `Prompt.json`

---

## 步骤 0：上下文预读取

进入计划模式、用户批准后，第一步执行上下文预读取。

### 0.1 读取清单（按顺序）

| 读取顺序 | 文件 | 提取内容 | 用途 |
|---------|------|---------|------|
| 1 | `项目信息.json` | `content_rating`、`nsfw_output_level`、`nsfw_tier_range`、`foreshadowing` | 内容分级判定、NSFW 档位确定、伏笔关联 |
| 2 | `润色配置.json` | `正文.polish_mode` | 提示词中润色程度指令 |
| 3 | `剧情大纲.md` | 目标章的剧情要点描述 | 提示词的核心内容源 |
| 4 | `人物存档.md` | 目标章出场人物的性格、能力、关系、当前状态 | 人物行为边界与对话风格约束 |
| 5 | `设定.md` | 相关世界观规则、场景设定 | 场景描写约束 |

### 0.2 读取结果汇总（内部，不输出给用户）

```
[内部] 第X章提示词增强上下文

📋 项目：{书名} / {content_rating} / 正文润色模式：{polish_mode}
🔞 NSFW：{nsfw_output_level} / 值域：{nsfw_tier_range}
👤 本章出场人物：
  - {角色A} — 性格：{简述} / 当前状态：{简述} / 关系：{简述}
  - {角色B} — …
🔖 本章关联伏笔：
  - 第X章需放置的伏笔（如有）
  - 第X章需回收的伏笔（如有）
🌍 相关设定约束：{简述}
📖 剧情大纲原始描述：{原文引用}
```

### 0.3 内容分级交叉校验

根据 `content_rating` 和当前章的 NSFW 章节区域配置，判定本章的 NSFW 档位：

| content_rating | nsfw_tier_range 覆盖 | 本章 NSFW 档位 |
|---------------|---------------------|---------------|
| `一般向` | — | 不启用 NSFW |
| `NSFW` | 当前章在 chapters 范围内 | 使用对应档位 |
| `NSFW` | 当前章在 global 范围内 | 使用 global 中位值 |
| `NSFW` | 无配置 | 在计划中询问用户 |

## 步骤 1：解析剧情大纲原始描述

### 1.1 定位目标章节

在 `剧情大纲.md` 中定位目标章的剧情要点。大纲中章节描述通常以以下格式出现：

```
- **≈X—X章**：{一句话或多句描述}
```

或分条形式：

```
- 第X章：{描述}
```

### 1.2 提取原始描述

提取目标章的**原始描述全文**。这是提示词扩充的唯一剧情依据。

### 1.3 评估描述完整度

| 描述完整度 | 判定标准 | 扩充策略 |
|-----------|---------|---------|
| 极简描述 | ≤30 字，仅一句话提点事件名称 | 重度扩充——需从人物/设定中大量补充细节 |
| 中等描述 | 30-150 字，有事件框架但无细节 | 中度扩充——补人物行为、对话方向、场景氛围 |
| 详细描述 | ≥150 字，有事件+人物+场景 | 轻度扩充——转为结构化提示词格式，少量补充衔接 |

---

## 步骤 2：按描述完整度扩充提示词

### 2.1 提示词结构模板

所有扩充后的提示词统一使用以下结构：

```
## 第X章「{章名}」写作提示词

### 章节定位
- 所属阶段：{第X阶段 / 分卷名}
- 篇幅预期：{约多少字}
- 核心事件：{一句话}
- 内容分级：{一般向 / NSFW — N?档}

### 剧情要点
{从大纲描述扩充的 3-5 条具体剧情要点，每条含：场景+人物行动+情绪走向}

### 出场人物
{人物名}：{本章中的角色定位与行为边界}
{人物名}：{本章中的角色定位与行为边界}

### 写作规范
- 润色程度：{正文.polish_mode}
- 段落节奏：一段至多两句，句末标点不串联
- 人物描写：间接化——借物/借镜/借他人之口，不贴标签
- 对话：搭配神情或动作，≥3轮对话中间插入一句环境描写
- 降重率：不得直接引用人物存档原文，换感官/换语境输出
{如为 NSFW 章节则追加 NSFW 规范}

### 伏笔指令
{如有需放置的伏笔}
- 本章需埋设：{从大纲或伏笔数据库中提取的伏笔内容}
{如有需回收的伏笔}
- 本章需回收：第X章_{伏笔内容}_→ 在合适的情节节点自然回收

### 场景与氛围
{从设定文件提取的场景约束}
{氛围关键词：3-5个——如"紧张/暗流涌动/暴雨将至""温馨/隐忧/黄昏光"}

### 前情衔接
{上一章的结束状态，本章从何处接续}
```

### 2.2 极简描述扩充（≤30 字）

**扩充原则**：原始描述仅提供事件名称，LLM 需要从零构建场景与人物行动。

**扩充步骤**：

1. **反推场景**：根据事件类型从设定中提取合适的场景（如"打斗"→ 从设定中查可能的战斗地点）
2. **分配人物行动**：从人物存档查出场角色的性格，推断其在该事件中会如何行动
3. **构建情绪走向**：事件发生的情绪起点 → 过程中的情绪转折 → 事件结束时的情绪落点
4. **补充感官细节方向**：不提具体用词，只给方向（如"本章触感描写以冷/湿为主""视觉以暗色调为主"）

**示例**：

| 大纲原文 | 扩充后剧情要点 |
|---------|-------------|
| `第5章：主角遭遇伏击` | ① 主角孤身经过城西窄巷（场景从设定取"西城贫民区"），天色将暗未暗，巷口灯笼刚亮 → 氛围关键词：昏暗/逼仄/不安 |
| | ② 从两侧屋顶跳下三名蒙面人，兵器为弯刀（从设定取反派组织特征），主角拔剑格挡——首次交锋描写主角的实战反应，突出"快但不熟练"（人物存档：战斗经验不足） |
| | ③ 打斗中场，主角右臂被划伤 → 触发第3章伏笔"手心发光印记轻微发热"（不激活，仅提示读者印记与危险有关联） |
| | ④ 危急时刻一道白影介入——新角色（从人物存档查下一章需引入的角色）以飞刀逼退蒙面人，但不露面、不报名 |
| | ⑤ 主角脱险后查看手臂伤口，发现伤口边缘有微弱的金色纹路蔓延 → 本章新伏笔：伤口异常愈合伴随符文扩散 |

### 2.3 中等描述扩充（30-150 字）

**扩充原则**：原始描述已有事件框架，LLM 需要补充人物对话方向、具体场景氛围、段落节奏建议。

**扩充步骤**：

1. **细化事件分段**：将大纲中的事件拆分为 3-4 个叙事段落
2. **插入对话节点**：在事件分段之间标注对话发生的时机与对话目的
3. **标记环境换气点**：在连续动作/对话段落中标记何处插入环境描写
4. **伏笔对齐**：检查伏笔数据库，标注本章的埋设/回收点

### 2.4 详细描述扩充（≥150 字）

**扩充原则**：原始描述已较完整，LLM 主要是将其结构化并补充规范指令与伏笔标注。

**扩充步骤**：

1. **结构化转译**：将散文式描述转为 2.1 模板的结构化格式
2. **规范指令追加**：补全写作规范、伏笔指令、前情衔接
3. **交叉校验**：检查原文描述与人物存档性格是否一致、与设定文件是否冲突

## 步骤 3：多源数据注入

### 3.1 人物数据注入

从 `人物存档.md` 中提取目标章涉及的人物，注入提示词的「出场人物」段落。

**提取规则**：

| 人物类型 | 注入内容 |
|---------|---------|
| 主要出场（本章有重要戏份） | 性格简述 + 当前状态 + 本章行为边界 + 对话风格提示 |
| 次要出场（本章露面或功能性出场） | 角色定位 + 一句话行为边界 |
| 仅提及（本章不出场但被提到） | 仅列角色名 |

**人物的"当前状态"如何确定**：
- 回溯前文章节，总结该角色到上一章末为止的状态（位置、情绪、身体状态、人际关系变动）
- 如无法回溯 → 在计划中标注"人物状态未知，需用户补充"，不编造

**人物行为边界示例**：
```
张三（主角）
- 本章定位：初次独立面对危险，无师长兜底
- 行为边界：可以紧张、可以犯错，但不能冷静从容——他有战斗经验但从未独当一面
- 对话风格：对敌时嘴硬但手抖，对自己人时话少但句句到位
- 禁忌：不要在战斗中做出"微微一笑""轻描淡写"等超出当前能力的姿态
```

### 3.2 设定数据注入

从 `设定.md` 中提取与目标章场景相关的设定约束，注入「场景与氛围」段落。

**提取优先级**：
1. 本章发生的具体地点设定（如"西城贫民区——巷窄、污水横流、棚户密集"）
2. 本章涉及的世界观规则（如"符文体系——初级符文只能发光，无法主动攻击"）
3. 本章时间线约束（如"本章发生在冬季，天黑的早，角色穿着厚重"）

**不注入的内容**：
- 与本章无关的设定条目
- 尚未在该章揭示的世界观秘密（避免剧透式写作）

### 3.3 伏笔数据注入

从 `项目信息.json` 的 `foreshadowing` 数组中提取与目标章相关的伏笔。

**关联判断**：

| 关联类型 | 判断依据 | 注入方式 |
|---------|---------|---------|
| 本章需埋设 | 伏笔条目第一字段 = `第X章` + 状态为 `待回收`（即预登记在本章放置） | 写入「伏笔指令—需埋设」 |
| 本章需回收 | 伏笔条目第三字段 = `第X章`（即计划在本章回收） | 写入「伏笔指令—需回收」 |
| 本章可提及 | 已有伏笔与本集事件主题相关，但未到回收时机 | 写入「伏笔指令—可轻触」（暗示但不展开） |

**伏笔指令示例**：
```
### 伏笔指令

需埋设：
- 主角右臂受伤后伤口边缘出现金色纹路——在战斗结束后的检查场景中自然写出，
  不使用"伏笔""神秘""暗示"等提示词，仅作为身体异常状态客观描写

需回收：
- 第3章_后山发现发光符文石触碰后手心留印记_→ 本章打斗中手心印记首次发热，
  回收方式：主角感到掌心异样时低头看了一眼，不展开解释

可轻触：
- 第1章_师傅临别交付旧锦囊_→ 主角受伤后摸到怀中锦囊，闪过念头但未打开
```

### 3.4 NSFW 数据注入

根据步骤 0.3 的交叉校验结果，判断本章是否需要 NSFW 写作。

**不触发 NSFW** → 提示词不包含 NSFW 指令，维持一般向正文。

**触发 NSFW** → 在提示词中注入：

```
### NSFW 写作指令
- 输出词级别：{限制级 / 开放级}
- 角色语气：{保守 / 中性 / 放荡}
- 色色值挡位：N{N}
- 核心原则：肉体感受 > 精神思考，精神思考每次不超过一句
- 白描许可：直接描写身体感受，不借物喻人
- 段落节奏：每段至多两句，长句用逗号连接
- 档位篇幅控制：{按 N1-N5 的白描篇幅说明}
```

## 步骤 4：输出提示词

### 4.1 单章输出

按步骤 2.1 模板输出完整提示词。输出在对话中即可，不写入文件。

### 4.2 批量输出

当用户要求批量生成时：

1. 逐章按步骤 1-3 生成
2. 每章提示词以 `---` 分隔
3. 首章之前输出批量概览：

```
📋 批量提示词生成完成 — {K} 章

| 章节 | 核心事件 | 润色模式 | NSFW | 伏笔（埋/回/触） |
|------|---------|---------|------|-----------------|
| 第3章 | 后山奇遇 | 中度 | — | 埋1 / 回0 / 触0 |
| 第4章 | 初入宗门 | 中度 | — | 埋0 / 回0 / 触1 |
| 第5章 | 夜探禁地 | 重度 | N3 | 埋1 / 回1 / 触0 |
…
```

### 4.3 批量存储至 Prompt.json

**仅批量处理时执行此步骤，单章不存储。**

批量提示词输出完成后，**必须**询问用户是否存储：

```
💾 是否将以上 {K} 章提示词持久化存储至 剧情/Prompt.json？
  • 是 — 写入文件，后续可随时读取调用
  • 否 — 仅在对话中保留，不写入文件
```

**用户选择"是" → 写入：**

**定位文件**：`大纲/剧情/Prompt.json`（优先）或 `outline/plot/Prompt.json`。

**写入逻辑**（分两种状态）：

**状态 1：文件不存在 → 新建**

```json
{
  "last_updated": "2026-06-13",
  "prompts": [
    {
      "chapter": "第3章",
      "chapter_name": "初入江湖",
      "core_event": "后山奇遇",
      "polish_mode": "中度",
      "nsfw_tier": null,
      "foreshadowing_place": 1,
      "foreshadowing_resolve": 0,
      "prompt_text": "## 第3章「初入江湖」写作提示词\n\n### 章节定位\n…",
      "generated_at": "2026-06-13",
      "status": "pending"
    }
  ]
}
```

**状态 2：文件已存在 → 合并更新**

1. `Read` 读取 `Prompt.json` 全文
2. 遍历本次生成的每章提示词：
   - 如该章号在 `prompts` 数组中**不存在** → 追加新条目
   - 如该章号已存在 → **覆盖**旧条目（以最新生成为准）
3. 更新 `last_updated` 为当前日期
4. `Write` 写回

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `chapter` | string | 章号，作为主键去重（如 `"第3章"`） |
| `chapter_name` | string | 章节名称 |
| `core_event` | string | 核心事件一句话 |
| `polish_mode` | string | 润色程度（`轻度` / `中度` / `重度`） |
| `nsfw_tier` | string\|null | NSFW 档位（`"大众级"` / `"限制级"` / `"开放级"`），无则为 `null` |
| `foreshadowing_place` | int | 本章需埋设伏笔数 |
| `foreshadowing_resolve` | int | 本章需回收伏笔数 |
| `prompt_text` | string | 完整提示词文本（含 Markdown 格式） |
| `generated_at` | string | 生成日期 |
| `status` | string | `"pending"`（待执行）/ `"executed"`（已执行）/ `"skipped"`（跳过） |

**写入完成后确认**：
```
✅ 已存储至 大纲/剧情/Prompt.json（{K} 章）
```

**用户选择"否" →** 不写入，提示词仅保留在对话中。

## 步骤 5：询问是否执行

提示词输出（及存储）完成后，**必须**询问用户：

```
✏️ 以上提示词已生成完毕{如已存储则追加：并已保存至 Prompt.json}。

是否立即执行写作？
  • 是 — 使用此提示词立即开始写作（调度 Core/NSFW 技能执行）
  • 否 — 保留提示词，稍后手动使用
  • 修改 — 对提示词进行调整后再执行
```

### 5.1 用户选择"是"

调度流程：

```
提示词增强输出 → 用户确认执行 → 传递至 Core（基础写作辅助）
                                    │
                                    ├── 检测 NSFW 内容 → 自动调度 NSFW 技能
                                    │
                                    └── 按提示词中的规范指令执行写作
```

将提示词作为写作指令传入 Core 技能，由 Core 按规范矩阵执行正文写作。

**执行后更新 Prompt.json**：如该章提示词已存储于 `Prompt.json`，执行后将对应条目的 `status` 更新为 `"executed"`。

### 5.2 用户选择"修改"

询问修改方向：
```
✏️ 请说明需要修改的内容：
  • 调整润色程度（当前：{polish_mode}）
  • 调整 NSFW 档位（当前：{nsfw_tier}）
  • 补充/删减剧情要点
  • 修改人物行为边界
  • 其他
```

根据用户反馈修改提示词后，再次输出并询问是否执行。

### 5.3 用户选择"否"

提示词文本已存在于对话中（如已存储则在 `Prompt.json` 中），用户可随时使用。不做额外操作。

## 注意事项

- **计划模式为强制入口**：调用此技能后必须先 `EnterPlanMode`，不得直接进入上下文预读取
- **不清空对话上下文**：提示词增强生成的是"写作指令"，不是"写作替代"——执行时由 Core/NSFW 按规范矩阵实际写作正文
- **Prompt.json 写入时机**：仅在批量处理 + 用户明确允许时写入；单章输出不自动写入文件
- **Prompt.json 去重逻辑**：同一章号再次生成时覆盖旧条目，不产生重复记录
- **人物状态追踪**：连续多章生成时，前一章的人物状态变化应自动反映到下一章的「出场人物—当前状态」中——实现上下文接力
- **伏笔状态同步**：批量生成时，如前一章生成提示词中标注了"本章需埋设"的伏笔，下一章提示词中该伏笔应体现在 `foreshadowing` 可轻触列表中
- **不替代用户判断**：提示词中的剧情要点、人物行动是**建议**而非命令，最终由用户决定是否接受。用户说"改"即改
- **批量上限**：单次批量生成最多 10 章，超出时提示用户分批进行——防止上下文窗口溢出
- **文件缺失处理**：人物存档/设定文件不存在时，在提示词中标注"⚠ 缺少{文件}，相关约束未注入"，不编造人物或设定
- **Prompt.json 与项目信息.json 的关系**：Prompt.json 存储写作提示词，项目信息.json 存储项目元数据——两者职责分离，互不写入
