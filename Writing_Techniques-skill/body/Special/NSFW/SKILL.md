# NSFW专项写作

此技能是「基础写作辅助」的 NSFW 专项扩展，提供三档分级写作模式，覆盖从隐晦隐喻到完全开放的成人内容写作全尺度。

## 核心定位

- **被调度技能**：通常由「基础写作辅助」检测到 NSFW 内容后自动调度，用户也可直接触发
- **三档模式**：大众级 / 限制级 / 开放级，逐级放开尺度
- **叠加核心规范**：在基础写作辅助的核心规范之上叠加 NSFW 专项规则，不替代、不冲突
- **人物感知**：限制级模式下必须读取人物存档，依据角色性格选择用词尺度，绝不 OOC

## 触发条件

### 由基础写作辅助调度

基础写作辅助在步骤 2（识别内容类型）检测到 NSFW 内容时，自动调度此技能处理，处理结果返回后纳入最终输出。

### 用户直接触发

- "写 NSFW 内容"、"写成人内容"、"写色情场景"
- "这段要写床戏"、"写个吻戏/床戏"、"写个 H 场景"
- "切换到 NSFW 模式"、"用 NSFW 模式写"
- "这段改得再色情一点"、"尺度再大一点"
- "色色值"、"调整色色值"、"这章色色值设多少"
- 人物创建中用户主动提及 XP/三维/性特征/人物X能力
- 任何表达需要写作成人/色情/性相关内容的表述

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `项目信息.json` | `大纲/` | NSFW 偏好（`nsfw_output_level`/`nsfw_character_tone`/`nsfw_tier_range`）及 `content_rating` | 读写 |
| `润色配置.json` | `大纲/` | 润色模式（使用 `正文.polish_mode`） | 只读 |

| `Prompt.json` | `大纲/剧情/` | 预生成的章节写作提示词（含 NSFW 写作指令段），由 Core 传递或直接读取 | 只读 |

## 执行模式

**由基础写作辅助调度时**：跳过计划模式，直接按步骤执行。

**用户直接触发时**：进入计划模式（EnterPlanMode），列出处理步骤和将使用的 NSFW 档位后执行。

## 三档模式定义

### 大众级 —— 隐晦隐喻

**适用场景**：
- 一般向作品中的轻度 NSFW 暗示
- 需要公开发布、通过公众平台内容审查的场景
- 项目 `项目信息.json` 中 `content_rating` 为 `一般向`

**核心原则**：极其隐晦，只可意会不可言传。用日常物品/概念隐喻 NSFW 内容，表面读起来完全无害。

**词汇替换示例**：

| 原词 | 大众级隐喻 |
|------|-----------|
| 跳蛋 / 震动棒 | 跳舞的鸡蛋、电子男友、嗡嗡、小马达 |
| 假阳具 / 按摩棒 | 假男友、硅胶朋友、替代品 |
| 飞机杯 | 斐济杯、手工杯、练习杯 |
| 润滑液 | 滑滑水、护肤液、透明胶 |
| 乳房 / 胸部 | 起伏的曲线、柔软处、胸前 |
| 阴茎 | 那话儿、小兄弟、那东西 |
| 阴道 | 私处、那里、深处 |
| 做爱 / 性交 | 亲密、在一起、云雨、温存 |
| 高潮 | 那一刻、顶点、空白 |
| 自慰 | 自我安慰、独处时光、手动模式 |

**写作要求**：
- 整段读起来像正常叙事，只有"懂的人懂"
- 不直接出现任何性器官/性行为词汇
- 用动作的省略和留白代替直接描写
- 用环境/物品的异常状态暗示发生了什么
  - 示例：不写"她用跳蛋自慰"，写"她把那个会跳舞的鸡蛋塞进枕头底下，蒙上被子，过了很久才安静下来"

### 限制级 —— 优雅代称

**适用场景**：
- 明确为 NSFW 向作品，但追求文学质感
- 需要根据人物性格调整用词尺度
- 项目 `项目信息.json` 中 `content_rating` 为 `NSFW`

**核心原则**：用优雅的代称替代医学术语/粗俗词汇。**必须感知人物性格**——保守角色用更文雅的说法，放荡角色可稍直接，但总体保持文学性。

|------------|------------|---------|------------|

| 龟头 | 顶端、冠首 | 头部 | 蘑菇头 |
| 睾丸 | 双丸、囊袋 | 精囊 | 蛋蛋 |

**OOC 判断规则（关键）**：

限制级最大的约束是绝不 OOC（Out of Character）。在选词前必须：

1. **读取人物存档**：从 `大纲/人物/人物存档.md` 中读取涉及角色的性格与简介
2. **评估角色开放度**：
   - 保守/内向/矜持角色 → 使用「保守角色用词」列
   - 中性/普通角色 → 使用「中性用词」列
   - 放荡/外向/主动角色 → 可使用「放荡角色可用」列
3. **情节语境判断**：
   - 初夜/初次亲密 → 偏保守用词
   - 热恋期 → 可用中性用词
   - 激情/主动求欢 → 可用放荡用词
4. **不越级**：保守角色在初次亲密场景中突然说"操我"是严重 OOC

### 开放级 —— 完全放开

**适用场景**：
- NSFW 作品中的放荡角色写作
- 纯粹的情色/色情场景
- 用户明确表示"不用收敛"、"怎么色情怎么来"

**核心原则**：无任何词汇限制。直白、露骨、粗俗均可。怎么写最色情、最刺激就怎么写。

**写作要求**：
- 不避讳任何词汇：操、干、鸡巴、骚逼、奶子、淫水等均可直接使用
- 可详细描写性器官外观、触感、反应
- 可详细描写性行为过程、体位、节奏
- 可描写角色在被操时的心理活动与生理反应
- 但**仍需遵守基础写作辅助的核心规范**（段落节奏、间接描写、性格间接化、风景穿插、对话增强、降重率）
- 即使开放级，也不建议整段整段连续写"啊啊啊"——有节奏、有呼吸的色情比堆砌词汇更有效

## NSFW 核心写作技法（限制级 & 开放级）

以下技法适用于**限制级**和**开放级**。大众级以隐晦为首要目标，不受此节约束。

### 核心原则：肉体感受 ＞ 精神思考

NSFW 写作的第一要务是**传递肉体感受**，而非铺陈角色的精神活动、道德反思或情感内涵。

**精神思考不能放弃，但绝对不是主角。** 它只作为肉体感受的辅助调味——点缀一两句即可，绝不占据大段篇幅，更不应在同一个场景中反复出现。

### 反"注水肉"规则

一般向作品中，角色在背德感、羞耻感下产生别样/异样感觉时，作者常通过多次提及、反复强调、大篇幅描述来渲染氛围。**这在 NSFW 写作中是致命的。**

- 同一场景中，同一种精神感受（如背德感、羞耻感、罪恶感）**最多提及一次**
- 提及方式应**简短**——一句话带过即可，不展开、不反复、不回扣
- 精神感受提及后，立刻回到肉体描写上

**反例（注水肉）**：
> 她知道自己不该这样，这违背了她从小受到的教育。可是那种背德感反而让她更加兴奋了。她一边唾弃着自己，一边又沉溺在这种禁忌的快感中。这种负罪感像毒药一样，让她一边痛苦一边快乐着……

**正例**：
> 她知道自己不该这样——但这个念头只闪了一瞬。
>
> 下一秒，他的手探进来时，她已经什么都顾不上了。

### 写作重心分配

NSFW 场景中，各类内容的合理占比：

| 内容类型 | 限制级 | 开放级 |
|---------|--------|--------|
| 肉体感受（触感、温度、呼吸、生理反应） | ≥50% | ≥60% |
| 动作描写（身体动作、互动、节奏） | ≥20% | ≥25% |
| 对话（含喘息、呻吟等） | ≤15% | ≤10% |
| 精神思考（内心活动、道德反思） | ≤10% | ≤5% |
| 环境/风景穿插 | ≤5% | 酌情 |

**肉体感受优先描写角度**：
1. **触感**：温度（滚烫/微凉）、质地（坚硬/柔软/湿滑）、压力（轻抚/用力/撞击）
2. **生理反应**：呼吸变化、心跳、体温上升、肌肉紧绷/松弛、体液分泌
3. **声音**：喘息声、水声、布料摩擦声（不是对话，是身体发出的声音）
4. **视觉**：身体的视觉变化（泛红、颤抖、紧绷）、而非对形貌的审美评价

**精神思考使用的约束**：
- 每次出现不超过一句
- 必须紧贴肉体反应——是"因为这种触感让她想起……"而不是"她陷入了对人生的沉思……"
- 同一场景中禁止精神思考连续出现两次以上

### NSFW 白描许可（限制级 & 开放级）

基础写作辅助的规范 2（人物描写间接化）在 NSFW 场景中**不适用**。NSFW 内容恰恰需要直接、详细的白描来传递肉体感受，这是提升色气感的核心手法。

**原则**：NSFW 场景中的性描写，优先使用直接白描——写清楚谁碰了哪里、怎么碰的、感受到了什么。长篇白描在此不仅是允许的，是推荐的。

- 不绕弯子、不借物喻人、不借镜喻人——直面身体与动作
- 允许长段落连续白描性行为过程，写出节奏与递进
- 白描的重点是动作+感受，不是堆砌形容词

**示例（直接白描——自慰场景）**：
> 她坐在地上靠着床边，左手缓慢地抚摸到自己的小穴上，右手抚在胸前，不断挑逗着乳首。左手手指试探着——一根手指就带来不少快感，只可惜自己的手指有点短……随着浑身一阵剧烈的颤抖，她蜷起身子，去了。

**示例（直接白描——交合场景）**：
> 张三将自己雄壮的肉棒抵在李四的小穴上摩挲，而后噗呲一声插入。
>
> "啊——"李四仰起脖子，手指抓紧了床单。

**白描长度控制**：
- 色色值挡位越高，白描篇幅越长
- N1 挡位：白描 ≤ 全文 1/4，点到为止
- N2 挡位：白描可占全文一半，场景可充分展开
- N3 挡位：白描为主，叙事为辅
- N4 挡位：全篇以白描驱动，几乎无其他内容
- N5 挡位：纯白描，零叙事、零换气，从头到尾不间断情色描写

即使长篇白描，仍需遵守规范 1（段落节奏）——每段至多两句，长句用逗号连接，保持呼吸感。

限制级使用优雅代称，但不能因"优雅"而变成空洞的文学修辞堆砌。优雅的是词汇，不是内容——内容仍然是肉欲的。

- 代称是手段，传递肉体感受是目的
- 避免用代称做长篇的比喻展开（如"花径"之后接三百字的花卉通感联想）
- 代称点到为止，重点写那个部位**感受到了什么**

### 开放级专用：直白但有节奏

开放级毫无词汇限制，但不可变成纯词汇堆砌。

- 避免同一器官在同一段落中被反复指称（每次都用"鸡巴"开头显得单调）
- 变换描写角度：一轮写触感，一轮写视觉，一轮写声音——让读者自己拼出画面
- 即使是开放级，也不要让角色在性爱过程中做长篇人生感悟

## 执行步骤

### 步骤 0：确定调用来源与文本范围

NSFW 技能有两种被调用方式，文本范围不同：

**A. 由 Core 调度（预分割）：**
Core 已按步骤 2.2 完成段落分割，NSFW 收到的数据包中 `text` 字段仅包含 NSFW 段落。直接进入步骤 1。

**B. 用户直接触发（全文未分割）：**
用户提供了完整文本（可能混合一般叙事与 NSFW 内容）。此时 NSFW 需自行完成内容识别与切分：

1. **逐段扫描**：以段落为单位遍历全文
2. **按三级检测判定**（同 Core 步骤 2.1 的三级扫描规则）：
   - 命中一级（显性词汇）→ 标记 NSFW 段落
   - 命中二级（性场景）→ 标记 NSFW 段落
   - 命中三级（语境渗透）→ 标记为边界段落，视上下文决定
3. **段落归类**：将全文拆分为「NSFW 段落组」和「一般段落组」
4. **边界合并**：两个 NSFW 段落组之间如果仅隔 ≤2 个一般段落，合并为一个 NSFW 段落组（避免因一句换气话把同一场床戏拆成两段）
5. **仅处理 NSFW 段落组**：一般段落组原样保留不修改，NSFW 段落组进入步骤 1

**边界规则**：
- 大众级模式下，NSFW 段落组前后各保留一个一般段落作为"缓冲带"（防止隐喻被直接上下文戳穿）
- 限制级 & 开放级模式下，缓冲带非必须

### 步骤 1：确定 NSFW 档位

按以下优先级确定档位：

1. **用户明确指定** → 直接使用指定档位
2. **读取项目配置**：
   - 读取 `大纲/项目信息.json`（或 `project-info.json`）
   - 若 `content_rating` 为 `一般向` → 默认大众级
   - 若 `content_rating` 为 `NSFW` → 询问用户选择限制级或开放级
3. **人物档案推断**（用户未指定时）：
   - 读取涉及角色的人物性格
   - 放荡/主动型角色 → 可建议开放级
   - 保守/矜持型角色 → 可建议限制级或大众级
4. 如无法自动判定，询问用户：

```
🔞 请选择 NSFW 写作档位：
  • 大众级 — 极度隐晦，隐喻化处理，可通过内容审查
  • 限制级 — 优雅代称，感知人物性格，绝不OOC
  • 开放级 — 完全放开，不限词汇，怎么色情怎么来
```

### 步骤 2：读取必要上下文

- 读取项目润色配置：`大纲/润色配置.json`（使用 `正文.polish_mode`）
- 读取人物存档：`大纲/人物/人物存档.md`（限制级必读）
- 确认待处理文本的上下文（什么场景、涉及哪些角色）

### 步骤 2.5：确认色色值挡位（N1-N5）

色色值采用 **N1 至 N5 五档体系**，从低到高排列：

| 挡位 | 含义 | 白描篇幅 | 剧情占比 | 节奏控制 |
|------|------|---------|---------|---------|
| **N1** | 少量情色点缀 | 简短白描，一笔带过 | 剧情主导 | NSFW 作为调味，快速切入切出 |
| **N2** | 情色与剧情并重 | 白描可占一半篇幅 | 剧情与情色均衡 | 情色场景与剧情场景交替 |
| **N3** | 以情色为主 | 白描为主，长段展开 | 剧情为情色场景服务 | 少量剧情连接情色场景 |
| **N4** | 纯情色驱动 | 全篇长白描驱动 | 极少量过渡 | 几乎全程在情色场景中，只在中间换气 |
| **N5** | 从头到尾只有情色 | 纯长白描，零中断 | 无剧情 | 从头到尾只有情色，不设换气、不插叙事 |

#### 2.5.1 首次调用：询问全书 NSFW 偏好（推荐项，非必须）

当本技能在当前项目中**首次被调用**（即 `大纲/项目信息.json` 不存在或不含 NSFW 配置字段）时，向用户询问以下偏好。**以下均非必选项**——用户可跳过，无数据时 LLM 自行判断调用：

```

**询问规则**：
- 两项一起问，用户可只回答一项、两项都答，或全部跳过
- 如用户明确说"跳过"/"不用"/"以后再说"，直接进入步骤 3，不写入任何数据
- 如用户提供了数据，立即写入 `大纲/项目信息.json`

**项目信息.json 写入规则**（合并写入，绝不覆盖已有字段）：

1. **先检测**：`Read` 读取 `大纲/项目信息.json`
2. **文件不存在** → 新建最小结构（仅 NSFW 字段 + `created_date`）：

```

3. **文件已存在** → **绝对不覆盖**。读取全文 → 仅更新/新增 NSFW 字段 → 已有字段（`book_name`、`content_rating`、`foreshadowing` 等）原封不动写回。合并后结构示例：
```json

  "distribution": "传播向",

  "last_updated": "2026-06-14"

```

**合并铁律**：仅触碰 `nsfw_output_level`、`nsfw_character_tone`、`nsfw_tier_range`、`last_updated` 四个字段。其他所有字段保持原样，不增不删不改位置。

**字段说明**：
- `nsfw_output_level`（输出词级别）：`优雅级` 或 `直白级`，对应用词优雅度。存储于挡位数据上方
- `nsfw_character_tone`（角色语气）：`保守` / `中性` / `放荡`，影响 OOC 判断的默认倾向。存储于挡位数据上方
- `nsfw_tier_range.global`（全书值域）：如 `"N3-N4"`，LLM 在各章写作时以此为中轴浮动
- `nsfw_tier_range.chapters`（章节区域）：可选，精确到章节范围的值域覆盖，如 `"1-10": "N1-N2"`。章节范围优先于全局值域
- 所有字段均为可选 —— 用户可只填部分，未填字段由 LLM 自行判断

**写入位置规则**：
- `nsfw_output_level` 和 `nsfw_character_tone` 存储在 JSON 最上方（输出词相关）
- `nsfw_tier_range` 存储在输出词字段下方（挡位数据）
- `last_updated` 在最下方记录更新时间

#### 2.5.2 后续调用：读取项目数据自动匹配

当 NSFW 技能被再次调用时：

1. 读取 `大纲/项目信息.json`（如存在）
2. 若有 `nsfw_output_level` → 自动使用对应输出词级别
3. 若有 `nsfw_character_tone` → 限制级模式下以此为角色语气的默认倾向
4. 若有 `nsfw_tier_range`：
   - 先检查 `chapters` 中是否有当前章节范围的覆盖值
   - 无覆盖则使用 `global` 值
5. 若项目数据完全不存在 → LLM 自行根据上下文判断挡位与输出词级别
6. 每章写作时仍需确认当前章的具体挡位（在全书值域范围内微调）：

```
🔞 当前章色色值挡位？（全书值域：{global_range}）
   N1 / N2 / N3 / N4 / N5
   （如不指定，默认取全书值域中位值）
```

#### 2.5.3 用户不满意时的推荐机制

当用户在同一 NSFW 场景中**连续两次以上**对输出表示不满（如"太淡了"/"太过火了"/"用词不对"/"这不是我要的感觉"）时：

```

- 如用户选择配置，按 2.5.1 的流程询问并写入 `项目信息.json`
- 如已有配置但用户仍不满意 → 询问是否需要修改现有配置值

色色值挡位确认后，在后续处理中严格按对应挡位控制白描篇幅与节奏。

### 步骤 3：按档位处理文本

**大众级处理流程**：
1. 扫描文本中的所有 NSFW 直称词汇
2. 逐一替换为大众级隐喻（参照上文词汇表）
3. 将直接的动作描写改为隐晦的暗示/省略
4. 用环境、物品、对话弦外之音代替直接性描写
5. 通读：确保替换后文本表面完全无害、叙事流畅自然

**限制级处理流程**：
1. 读取涉及角色的性格、简介
2. 评估角色开放度（保守/中性/放荡）
3. 确定情节语境（初次/热恋/激情）
4. 扫描文本中的 NSFW 词汇
5. 依据角色开放度+情节语境，从对应词汇列选择代称
6. 通读：确保角色语言风格统一、不 OOC
7. 标注 —— 若某处用词可能处于 OOC 边界，向用户说明并询问

**开放级处理流程**：
1. 不限制任何词汇
2. 运用基础写作辅助核心规范优化段落节奏与可读性
3. 确保场面生动、节奏有起伏
4. 保留所有直白/露骨表达

### 步骤 4：叠加核心规范（按档位矩阵过检）

NSFW 处理完成后，按如下规范叠加矩阵逐条过检（✓=强制应用 / △=酌情 / ✕=豁免）：

| 规范 | 大众级 | 限制级 | 开放级 | 说明 |
|------|--------|--------|--------|------|
| 规范 1（段落节奏） | ✓ | ✓ | ✓ | 三档均适用；开放级尤其严格——长段白描容易暴走，每段至多两句，句末标点串联合并或拆段；NSFW 中的呻吟/尖叫（"啊——""不要！"）为感叹句，必须拆段换行 |
| 规范 2（间接描写） | ✕ | ✕ | ✕ | **NSFW 全档豁免**——直接白描是传递肉体感受的核心手法，不要求借物喻人/借镜喻人 |
| 规范 2.2（性格间接化） | ✕ | ✕ | ✕ | **NSFW 全档豁免**——NSFW 场景中角色的性格表现（顺从/主动/放荡等）通过性行为中的动作与反应自然流露，不在此限 |
| 规范 3（风景穿插） | ✓ | ✓ | △ | 大众级/限制级：NSFW 场景间仍需环境换气；开放级：仅在超长白描（≥500字连续）时强制插入一句环境 |
| 规范 4（对话增强） | ✓ | ✓ | ✓ | 三档均适用；NSFW 中的呻吟/喘息/短促对话仍须搭配神情或动作 |
| 规范 5（降重率） | ✓ | ✓ | ✓ | 三档均适用；严禁照搬/近义复述人物存档中的 NSFW 身体数据与描述原句；跨章描写同一身体特征必须换感官/换语境；同一器官/同一触感在同一段落内不得反复描写 |

**逐条过检细节：**

- **规范 1**：NSFW 段落是否超过两句？长句是否用逗号而非句末标点连接？是否出现"！""？"收尾的句子与其他句子用标点串联（NSFW 中呻吟/尖叫必须拆段换行）？开放级连续白描段落中是否出现句末标点短句堆叠？
- **规范 2**：跳过。NSFW 内容不需要间接描写手法
- **规范 2.2**：跳过。NSFW 场景中角色性格通过性行为的主动/被动、节奏、反应自然传递，不适用性格间接化规则
- **规范 3**：大众级中 NSFW 隐喻段落后是否紧跟一句环境换气？限制级长段性描写中间是否有一句风景打断？开放级超长白描（≥500字）是否至少有一处环境穿插？
- **规范 4**：角色在 NSFW 场景中的对话（含喘息、"啊"、"嗯"等）是否搭配了神情或身体动作？（纯喘气词如无伴随描写，可读性差）
- **规范 5**：是否照搬了人物存档中的原始身体数据或描述措辞？同一特征在之前的章节是否已用过同样的感官角度？（如第3章用过视觉写胸部、第8章不能再从视觉写）同一器官/同一触感在同一段落是否出现 ≥3 次？情感形容词是否堆砌（如"酥麻、战栗、痉挛、抽搐"连续排列）？

### 步骤 5：输出优化结果与返回协议

**输出文本**：返回处理后的 NSFW 文本（仅 NSFW 段落组，不含一般段落）。

**附带元数据（Core 调度时必含，用户直接触发时可省略）：**

```
{
  "nsfw_tier_used": "{大众级 / 限制级 / 开放级}",
  "sexy_value": "{N1 / N2 / N3 / N4 / N5}",
  "exempted_norms": ["规范2", "规范2.2"],
  "key_changes": "{关键替换/调整说明}",
  "ooc_warnings": "{OOC 边界标注，如有}"

**字段说明：**
- `nsfw_tier_used`：实际使用的 NSFW 三档
- `sexy_value`：实际使用的色色值挡位（N1-N5）
- `exempted_norms`：告知 Core 哪些规范已在 NSFW 端豁免，Core 整合时无需二次检查。始终包含「规范 2」和「规范 2.2」

**用户直接触发时的输出格式：**
返回处理后的文本，附带：
- 使用的 NSFW 档位和色色值挡位
- `key_changes` 关键替换/调整说明
- 如有 OOC 边界情况，标注供用户确认

- 如 NSFW 返回 `ooc_warnings`，Core 在输出前向用户展示并确认

## 注意事项

- 大众级的关键是"只可意会"——如果读者一眼能看出在写什么，说明隐喻还不够隐晦
- 限制级的关键是"人物一致性"——词汇选择必须从角色性格推导，不能为色情而 OOC
- 开放级不是"放弃写作规范"——核心规范在开放级仍然适用，防止色情场景变成词汇垃圾场
- **限制级 & 开放级铁律**：肉体感受 ＞ 精神思考。精神思考每次出现不超过一句，同场景禁止连续出现两次以上。背德感/羞耻感等同类型精神感受同一场景最多提及一次
- **NSFW 白描许可**：核心规范 2（间接描写）在 NSFW 场景中不适用——直接白描是提升色气感的核心手法；长篇白描允许且推荐，长度由色色值控制
- 三档之间不可混用：同一场景中不能一句话大众级、下一句开放级，保持档位统一
- **色色值询问**：每章涉及 NSFW 内容时**必须**先确认色色值挡位（N1-N5），不同挡位对应不同的白描篇幅与节奏控制；如已配置全书值域（`项目信息.json`），则在该范围内微调
- **项目数据推荐**：首次调用时询问全书值域与输出词级别并持久化至 `大纲/项目信息.json`，此项为非必须但强烈推荐——配置后可大幅提升 LLM 输出准确性；如用户连续两次以上对输出不满意，主动推荐配置
- 如用户对自动选择的档位不满意，允许随时切换并重新处理
- 大众级替换不改变原文叙事结构和关键信息
- 始终以 Markdown 格式输出文本内容
