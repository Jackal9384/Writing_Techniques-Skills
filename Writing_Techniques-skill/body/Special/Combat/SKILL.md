# 战斗描写专项

此技能是「Write-Router」的战斗专项扩展，处理人与人之间直接对决场景的写作优化，以及大规模/多场景战争内容（warfare 子项）。

## 核心定位

- **被调度技能**：通常由「Write-Router」检测到战斗/战争内容后自动调度，用户也可直接触发
- **对决限定**：主项仅处理人与人之间的直接对决——1v1 单挑、2v2 小团对战、一对多（≤5人）
- **战争子项**：大规模/多场景战争（军队集结/指挥部决策/攻城会战/战线态势）由 warfare 子项处理——以小见大（指挥部/参谋部/一线单位多场景切片组合营造大场面），战争多为多章长镜头，**全部软引导**（不拦截不强制）；与主项技法不直接关联，个体对决的战斗细节引用主项技法
- **叠加核心规范**：在 Core 的五项核心规范之上叠加战斗专项规则，不替代、不冲突
- **人物感知**：必须读取角色文件，依据角色战斗风格、实力层级、性格决定其在战斗中的行为模式

## 触发条件

### 由Write-Router调度

## 战斗类型识别

处理战斗内容前，首先判定战斗类型——不同类型适用不同的技法侧重：

### 类型 A：冷兵器对决

刀、剑、枪、棍棒等冷兵器近身格斗。重点：招式的空间关系、兵器触感、攻防节奏。

**技法侧重**：`cold_weapon` 组（t01 动作节奏 > t02 打击感 > t03 招式体系，索引见 `techniques/index.json`）

### 类型 B：徒手格斗

拳脚、擒拿、摔投。重点：身体触感、力量传导、疼痛递进。

**技法侧重**：`bare_hand` 组（t02 打击感 > t04 伤势递进 > t01 动作节奏 > t06 心理博弈）

### 类型 C：超能力/法术对决

元素操控、能量对轰、念动力等。重点：视觉奇观与内在消耗的平衡、能力边界的清晰性。

**技法侧重**：`ability` 组（t03 招式体系 > t06 心理博弈 > t02 打击感）

### 类型 D：枪械/现代兵器对峙

枪战、狙击对决。重点：空间位置、时间压缩感、心理博弈。

**技法侧重**：`gunfight` 组（t06 心理博弈 > t01 动作节奏 > t02 打击感）

### 类型 E：混合型

以上类型的组合（如冷兵器+超能力、徒手夺枪等）。按主要冲突手段判定侧重（`mixed` 组全技法），辅助手段酌情融入。

### 类型 F：战争子项（warfare）

大规模/多场景战争——军队集结/行军/布阵、指挥部/参谋部决策、攻城/会战/战役级冲突、战线全局态势、战斗命令传达。**不以个体对决为主**。

**处理方式**：按 `warfare` 组处理（w01-w08，以小见大——指挥部/参谋部/一线单位多场景切片组合，软引导）。战争语境中的个体对决按 w06（战中个体时刻）处理，战斗细节引用主项技法。

**与主项的关系**：warfare 子项与主项六技法不直接关联——主项是硬标准（对决场景逐条过检），warfare 是软引导（多章长镜头，参考不拦截）。

## 战斗专项技法体系

以下六项技法是此技能的核心处理标准。优化战斗文本时逐条过检，不可跳过。技法体系之上有总原则〇，统领全部技法。

### 原则〇：画面优先于过程

**让读者"看见"每一击，而不是被"解释"战斗原理。** 战斗描写的篇幅应花在读者能看见的画面上——兵器的轨迹、身体的姿态、伤口的样子、双方的走位——而不是花在解释动作的力学过程和招式机制上。

**读者要看见的画面**（战斗版）：

- **空间关系**——起点/路径/终点，双方的距离与走位
- **身体姿态**——发力的身形、受击的晃动、倒地的过程
- **打击后果**——伤口、血、断刃、碎裂的物件
- **环境交互**——卷起的尘土、晃动的灯笼、被劈开的桌案

**辅助手段（服务于画面，不可喧宾夺主）**：

- **力量传导**（"力从腰胯经脊柱传至肩臂"）——只作为姿态变化的骨架，一笔带过，不展开力学讲解
- **招式机制/能力原理**（"此招以精神力锁定对方气机"）——仅在需要交代能力边界时露一面，不可展开为设定说明文
- 力学与原理是画面的骨架，但它们不是画面本身

**判断标准**：写完后检查——几成是读者能"看见"的画面，几成是看不见的"力学过程/机制分析"？画面应占据绝大部分篇幅，传导与原理只在需要交代身体变化或能力边界时露一面就退场。

**对类型 B/C 的特别设防**：

- 类型 B（徒手格斗）的"力量传导"指打击的**触感与后果**（"这一拳打得他眼前发黑"），而非力学链条的讲解（"力自足底经膝、髋、腰、肩传至拳面"）
- 类型 C（超能力/法术）的"能力边界"通过**战斗中的行为**呈现（发招的代价、吃瘪的时刻），而非能力机制的原理说明

### 技法索引（注册表驱动）

六项技法全文外置 `techniques/` 独立文件，按战斗类型选组读取（与 Core norms / NSFW techniques 同构）。索引见 `techniques/index.json`：

| 技法 | 名称 | 核心（一句话） | 适用组 |
|------|------|--------------|--------|
| t01 | 动作节奏控制 | 出招↔受击↔反应↔喘息四拍循环；连续动作用逗号串联，每轮必有喘息拍 | 冷兵器/徒手/枪械 |
| t02 | 打击感描写 | 触感+声音+后果三维叠加；每击至少两维，关键打击三维全写 | 全部 |
| t03 | 招式体系规范 | 命名风格世界观内自洽；首现全描写/复用简描写/变招半描写；空间三要素 | 冷兵器/超能力 |
| t04 | 伤势递进 | 伤势逐级累积（L0-L4），每次受伤在后续动作体现影响 | 徒手 |
| t05 | 胜负转折 | 转折点必有铺垫（五型），铺垫与转折隔一轮四拍；胜负后收束闭环 | 混合型 |
| t06 | 心理博弈 | 预判/诱导/误判/适应四层次；心理占比按战斗类型限幅；性格行为化 | 徒手/超能力/枪械 |

**战争子项（warfare 组）**：w01 指挥部场景 / w02 参谋部场景 / w03 一线单位场景 / w04 切片组合规则（以小见大核心）/ w05 计划-现实落差 / w06 战中个体时刻（引用主项技法）/ w07 战争代价 / w08 战线推进感——与主项不直接关联，全部软引导，见 `techniques/warfare/`。

**加载策略**：`techniques/index.json` 为注册表（机器规格）——首次调度完整读取一次，之后按记忆执行。技法文件**按需读取**：步骤 1 按战斗类型选组（`groups`）后，只 Read 命中组的技法文件，未命中不读取。

**过检顺序**：按所取组内技法顺序执行（如 `cold_weapon` 组：t01 → t02 → t03；`warfare` 组：w01 → w08，软引导不拦截）。

## 与 Core 五项规范的协同矩阵

战斗场景中，Core 五项规范的适用性按以下矩阵调整（✓=强制应用 / △=酌情 / ✕=豁免 / ★=战斗专项覆盖）：

| 规范            | 冷兵器 | 徒手  | 超能力 | 枪械  | 说明                                                                |
| ------------- | --- | --- | --- | --- | ----------------------------------------------------------------- |
| 规范 1（标点正确性） | ★ | ★ | ★ | ★ | 由本技能技法 1（动作节奏控制）覆盖——战斗中标点使用规范：连续动作用逗号串联，句号仅用于换气收束 |
| 规范 1.6（破折号禁令） | ✓   | ✓   | ✓   | ✓   | 全技能不免——战斗中非声音延长的破折号一律按规则替代                                        |
| 规范 1.8（对话衔接）  | ✕   | ✕   | ✕   | ✕   | **战斗全豁免**——战斗动作序列由本技能技法 1（四拍循环）控制节奏；喘息拍已涵盖环境/呼吸/心理闪念等换气手段 |
| 规范 2（间接描写）    | ★   | ★   | △   | △   | 战斗中的人物外貌不做间接化要求——战斗动作本身即是"展示"；但战斗能力不可直接贴标签（如"他是天下第一快剑"），须通过战斗行为体现 |
| 规范 2.2（性格间接化） | ★   | ★   | ★   | ★   | 由本技能技法 6.2（战斗中的人物性格展现）覆盖——禁止在战斗中贴性格标签                             |
| 规范 3（风景穿插）    | ★   | ★   | ★   | ★   | 由本技能技法 1（四拍循环中的"喘息拍"）覆盖——环境切入是喘息拍的核心手段                            |
| 规范 4（对话增强）    | ✓   | ✓   | ✓   | ✓   | 战斗中的对话（指令、挑衅、嘶吼、呻吟）仍须搭配神情或动作                                      |
| 规范 5（降重率）     | ✓   | ✓   | ✓   | ✓   | 不同场次的战斗必须更换描写角度——攻击方式、受伤部位、环境利用、胜负转折类型均不可重复                       |

**豁免说明**：

- 规范 2（间接描写）在战斗场景中豁免"间接描写人物外形"的要求——战斗中的动作描写本身就是"展示而非叙述"。但人物的战斗水平不可通过叙述者直接贴标签（如"他是天下第一高手"），必须通过战斗过程和结果让读者自己得出结论。
- 此豁免不传达给成品输出校验——由本技能在步骤 4 中随数据包标注 `exempted_norms`。

## 执行步骤

**由 Write-Router 调度时**：接收已分类的战斗段落数据包（`text` + `polish_mode` + `content_rating` + `context`），跳过计划模式，直接执行。

**用户直接触发时**：进入计划模式（EnterPlanMode），确认战斗类型后执行。

---

### 前置：战斗类型判定

根据战斗内容判定类型（冷兵器/徒手/超能力/枪械/混合型），确定技法侧重（见上方"战斗类型识别"章节）。

如无法自动判定（如文本过短、信息不足），向用户确认类型。

---

### 步骤 1：按技法体系处理

**对决（combat_type = 冷兵器/徒手/超能力/枪械/混合型）**：按所取技法组顺序逐条过检（如 `cold_weapon` 组：t01 → t02 → t03；`bare_hand` 组：t02 → t04 → t01 → t06——组定义见 `techniques/index.json`）。

**战争（combat_type = warfare）**：按 `warfare` 组处理（w01-w08 以小见大——指挥部/参谋部/一线单位多场景切片组合营造大场面氛围）。战争场景多为多章长镜头，**软引导**：技法为参考建议，不拦截不强制；各章按内容自然选切片，不要求单章集齐。

处理完成后立即自闭环校验，按「与 Core 五项规范的协同矩阵」逐条过检——校验完成后成品输出校验不再重复以下检查：

| 规范            | 过检动作                                                         |
| ------------- | ------------------------------------------------------------ |
| 规范 1（标点正确性） | 检查战斗动作是否用逗号串联为逻辑流、是否出现句号截断连续动作、问号/感叹号是否各自独立成段 |
| 规范 1.6（破折号禁令） | 全量扫描 `——` 使用——非声音延长用途的按替代表修正                                 |
| 规范 2（间接描写）    | 豁免外貌间接化要求，但检查战斗能力是否通过叙述者直接贴标签（禁止）                            |
| 规范 2.2（性格间接化） | 检查战斗中是否出现"他是一个XX的人"式叙述者贴标签（通过技法 6.2 用行为替代）                   |
| 规范 3（风景穿插）    | 检查每个四拍循环是否有喘息拍（环境切入），喘息拍是否与战斗情绪呼应                            |
| 规范 4（对话增强）    | 检查战斗中的对话是否搭配神情/动作——如"小心！"后是否跟了动作                             |
| 规范 5（降重率）     | 检查同一场战斗的攻击方式/受伤部位/环境利用是否重复使用同一角度；跨章检查同一角色战斗描写是否换感官/换技法/换转折类型 |

### 步骤 2：输出结果与返回协议

**输出文本**：返回处理后的战斗文本（仅战斗段落组，不含一般段落）。

**附带元数据**：

```
{
  "combat_type": "{冷兵器 / 徒手 / 超能力 / 枪械 / 混合型}",
  "exempted_norms": ["规范2"],
  "key_changes": "{关键调整说明}",
  "combat_notes": "{战斗中需要注意的持续性问题，如某角色的伤势将在后续章节中持续影响}"
}
```

| 字段 | 说明 |
|------|------|
| `combat_type` | 实际判定的战斗类型 |
| `exempted_norms` | 告知 Write-Router 哪些规范已在战斗端豁免，整合时无需二次检查 |
| `key_changes` | 对用户可读的调整摘要 |
| `combat_notes` | 跨章节持续性信息，供 Core/长篇专项参考 |

## 与Write-Router的协作

```
用户输入文本
    │
    ▼
Write-Router（步骤 2-3：内容检测 + 段落预分配）
    │
    ├── 一般段落 → Core 直接处理
    │
    └── 战斗段落 → 打包数据发送 ────────────────────────┐
          ↑                                                 │
          │  {text, context:{volume, chapter,               │
          │   combat_type, involved_characters},            │
          │   polish_mode, content_rating}                  │
          │                                                 ▼
          │                                          战斗描写专项
          │                                              │
          │                                    步骤 0：确定文本范围
          │                                    步骤 1：判定战斗类型
          │                                    步骤 2：读取上下文
          │                                    步骤 3：按六项技法处理
          │                                    步骤 4：叠加 Core 规范过检
          │                                    步骤 5：输出 + 返回元数据
          │                                              │
          │  {processed_text, combat_type,                 │
          │   exempted_norms, key_changes,                 │
          │   combat_notes}                                │
          └──────────────────────────────────────────────┘
                    │
                    ▼
              Write-Router（步骤 5：整合）
              • 按原位置拼合段落
              • 依 exempted_norms 收集豁免
              • 全篇一致性过检
                    │
                    ▼
              长篇专项（如需要）
              • 战斗中放置的伏笔（如某角色隐藏实力）→ 自动登记
              • 战斗中涉及的跨章线索 → 查询
                    │
                    ▼
              成品输出校验
              • 第一轮：CPS.json 标点合规扫描
              • 第二轮：Core 规范段落/字句结构扫描
              • 通过 → 落盘 / 不通过 → 修正→重检
                    │
                    ▼
              最终输出
```

**协议要点：**

- Write-Router 负责检测、分割和整合战斗内容，战斗技能负责处理战斗段落的专项优化
- 战斗技能自行完成**战斗专项校验**（步骤 4）：动作节奏、打击感、招式规范、伤势递进、胜负转折、心理博弈——这些校验不出现在成品输出校验中
- 战斗技能返回的 `combat_notes` 中包含跨章节持续性信息（如伤势影响），Write-Router 应在后续章节写作中传递给相关技能
- Write-Router 整合完成后按流水线自动调度：长篇专项（如需要伏笔登记/剧情回忆）→ 成品输出校验（标点+结构双轨）→ 落盘输出

## 注意事项

- **主项对决限定**：主项技法仅处理人与人之间的直接对决（1v1/小团对战 ≤5人）——此范围外使用 warfare 子项或 Core
- **战争子项范围**：军队集结/行军/布阵、指挥部/参谋部决策、攻城/会战/战役级冲突、战线全局态势、战斗命令传达等大规模/多场景战争 → warfare 组（w01-w08，软引导）；warfare 组与主项不直接关联，战争语境中的个体对决按 w06 引用主项技法
- **非本技能范围的战斗内容**：
  - 魔兽/怪物狩猎（除非其中包含人与类人智慧生物的单挑对决）
  - 体育竞技（除非是格斗类竞技如拳击/MMA/击剑等直接对抗）
  - 暗杀/偷袭中一击致命的场景（无往复攻防，不算"对决"）→ 由 Core 的规范 2 间接描写处理
- **人物一致性**：战斗行为必须从角色性格推导——一个怯懦的人不会在战斗中突然变得英勇无敌（除非这是经过铺垫的性格弧光转折）
- **实力层级一致**：同一角色在不同场次中的实力表现应有合理的一致性——除非实力变化有明确的情节支撑（修炼、受伤、顿悟等）
- **技法不是公式**：六项技法是指导原则，不是填表。在确保基本质量的前提下，允许根据具体场景灵活调整
- **始终以 Markdown 格式输出**文本内容
