# 长篇专项

此技能是写作系统的**伏笔管理层**，负责伏笔的放置登记与跨章节情节回忆。长篇与短篇作品均可使用。

## 核心定位

- **伏笔登记**：用户标注时读取原文 → 提取关键意思 → 写入 `项目信息.json`
- **情节回忆**：用户提及前文章节事件时 → 读取该章原文 → 生成摘要
- **被动触发**：仅在用户提示词符合触发条件时执行，不主动扫描

## 触发条件与路由

当用户消息命中以下任一条件时，立即执行对应操作（**跳过计划模式**）：

| 触发词/条件 | 操作 |
|------------|------|
| "这是一个伏笔"、"这是伏笔"、"此处为伏笔"、"埋伏笔"、"设伏笔"、"放置伏笔"、"伏笔："、"【伏笔】" | → 伏笔登记（步骤 A） |
| 剧情大纲中写入"伏笔"/"铺垫"/"此处埋伏笔" | → 伏笔预登记（步骤 B） |
| "回收伏笔"、"填坑"、"回收XX伏笔"、"这个伏笔该回收了" | → 伏笔回收（步骤 C） |
| "查看伏笔"、"伏笔列表"、"还有哪些坑没填" | → 伏笔清单（步骤 D） |
| "之前第X章"/"在第X章中"/"回顾第X章"/"XX事件是在哪一章"/"前文中XX"/"第X章发生了什么"/"重温XX章节"/"回顾XX情节" | → 情节回忆（步骤 E） |

## 步骤 A：伏笔登记（正文标注）

当用户在正文中标注"这是一个伏笔"时执行。

### A1 — 确定当前章节

从用户上下文或当前已打开的文件路径中提取章节号与章节名。当前工作目录下按顺序查找：

```
正文/第XX章 XX.md  →  body/ChXX XX.md  →  用户手动指定
```

提取到的章号记为 `{N}`，章名记为 `{T}`。

### A2 — 读取伏笔所在原文

定位到用户标注"这是一个伏笔"的位置，读取该位置**前后各 5 个段落**的原文内容。

如果用户标注时给出了额外说明（如"这是一个伏笔——后面他会用到这把钥匙"），一并纳入上下文。

### A3 — 提取关键意思

通读 A2 读取到的原文 + 用户说明，提炼为一句话关键意思。规则：

- ≤50 字，含核心人物 + 核心事件/物品/线索
- 不评价好坏，不展开推测，不添加原文中没有的信息
- 如用户有说明预期回收方向，在末尾附加（如"→ 后续开锁用"）

输出示例：`主角在后山发现刻有符文的发光石头，触碰后手心留下印记 → 后续战斗中激活`

### A4 — 生成数据行

按模板生成一行数据：

```
{第N章_一句话关键意思_待回收}
```

- 如用户已指定或暗示回收章节 → `{第N章_关键意思_第M章}`
- 如未回收 → 第三个字段填 `待回收`
- 字段之间用下划线 `_` 分隔
- 不包含章节名 `{T}`，仅用章号保持简洁

示例产出：
```
第3章_后山发光石头手心留印记_待回收
第5章_偷听到管家提及下月初三西城码头_第12章
```

### A5 — 写入项目信息.json

**定位文件**：`大纲/项目信息.json`（或 `outline/project-info.json`）。

**情况 1：文件存在且已有 `foreshadowing` 字段**
1. 读取 `项目信息.json` 全文
2. 在 `foreshadowing` 数组的**末尾**追加 A4 生成的字符串
3. 写回文件（保持 JSON 合法，不破坏其他字段）

`foreshadowing` 字段结构：
```json
{
  "foreshadowing": [
    "第3章_后山发光石头手心留印记_待回收",
    "第5章_偷听到管家提及下月初三西城码头_第12章"
  ]
}
```

**情况 2：文件存在但无 `foreshadowing` 字段**
1. 读取 `项目信息.json` 全文
2. 在已有字段**下方**新建 `foreshadowing` 数组，写入 A4 数据
3. 写回文件（已有字段原封不动）

**情况 3：文件不存在**
1. 新建 `项目信息.json`
2. 写入最小结构：
```json
{
  "foreshadowing": [
    "第3章_后山发光石头手心留印记_待回收"
  ]
}
```

### A6 — 向用户确认

写入完成后，告知用户：

```
🔖 伏笔已登记 — 第{N}章「{T}」
{放置章节_关键意思_回收章节}
```

## 步骤 B：伏笔预登记（大纲规划）

当用户在剧情大纲中写入伏笔计划时执行。

### B1 — 读取剧情大纲

读取 `大纲/剧情/剧情大纲.md`（或 `outline/plot/plot-outline.md`）。

### B2 — 扫描伏笔标注

在剧情大纲中搜索关键词：`伏笔`、`铺垫`、`预热`、`埋伏笔`、`为……做铺垫`、`前兆`、`暗示`。

找到后，读取该关键词所在段落的完整内容。

### B3 — 逐条提取

对每条命中的伏笔标注，提取：
- 计划放置于第几章
- 伏笔的核心内容是什么
- 计划回收于第几章（大纲中往往已写明"后续XX章回收"）

按 A4 模板生成数据行，回收章节未知时填 `待回收`。

### B4 — 写入

同 A5 逻辑，逐条追加到 `foreshadowing` 数组。

### B5 — 汇总告知

```
🔖 从剧情大纲中预登记 {K} 条伏笔：
第X章_…_待回收
第Y章_…_第Z章
```

---

## 步骤 C：伏笔回收

当用户表示要回收伏笔时执行。

### C1 — 读取伏笔列表

从 `项目信息.json` 读取 `foreshadowing` 数组。

### C2 — 匹配目标伏笔

根据用户描述（如"回收那个发光石头的伏笔"）在数组各条目中匹配关键词。

如匹配到多条，列出供用户选择：
```
找到 {K} 条匹配的伏笔：
1. 第3章_后山发光石头手心留印记_待回收
2. 第7章_洞穴壁画上的相同符文_待回收
请指定要回收哪一条？
```

如仅匹配到一条，直接确认后执行下一步。

### C3 — 更新状态

将匹配条目的第三个字段（`_待回收`）替换为当前章节号：

```
修改前：第3章_后山发光石头手心留印记_待回收
修改后：第3章_后山发光石头手心留印记_第12章
```

写回 `项目信息.json`。

### C4 — 确认

```
✅ 伏笔已回收 — #{条目在数组中的序号}
第3章_后山发光石头手心留印记_第12章
```

---

## 步骤 D：伏笔清单

当用户要求查看伏笔时执行。

### D1 — 读取

从 `项目信息.json` 读取 `foreshadowing` 数组。

### D2 — 分类统计

按第三个字段（`_` 分隔后最后一段）分组：

- `待回收` → 未回收组
- 其他章号 → 已回收组

### D3 — 输出清单

```
🔖 全书伏笔清单

▎ 未回收（{N}条）
第3章_后山发光石头手心留印记_待回收
第5章_偷听到码头交易暗号_待回收
第8章_神秘人留下半块玉佩_待回收
…

▎ 已回收（{M}条）
第1章_师傅临别赠言含有深意_第8章
第2章_酒馆角落的斗笠人始终未开口_第6章
…
```

### D4 — 状态提醒

- 未回收 ≥ 5 条 → 提醒：`⚠ 尚有 {N} 条伏笔待回收`
- 某条伏笔已跨越 ≥ 10 章未回收 → 标注 `⚠ 已放置 {X} 章未回收`
- 同一章回收 ≥ 3 条伏笔 → 标注 `⚠ 第{X}章集中回收 {Y}条，注意节奏`

---

## 步骤 E：关键情节回忆

当用户提及前文章节事件时执行。

### E1 — 解析章节号

从用户消息中提取章节号。规则：

- 明确数字："第3章"、"第三章" → 直接使用
- "之前XX事件那章" → 先在剧情大纲中搜索事件名，定位章节号
- "XX和XX的关系" → 先在人物存档中查关系记录，再定位相关章节
- 章节号无法确认 → 询问用户

### E2 — 定位并读取章节文件

按以下顺序查找章节文件：

```
正文/第X章 XX.md  →  body/ChX XX.md  →  Glob 搜索 "第X章*"
```

找到后，使用 Read 工具全文读取该章。

### E3 — 提取用户关注点

根据用户查询焦点，从原文中提取相关内容：

| 用户关注点 | 提取内容 |
|-----------|---------|
| 某事件 | 事件的起因、经过、结果段落 |
| 某人物 | 该人物的出场段落、对话、行动 |
| 某段对话 | 对话的前后语境与对话内容 |
| 整体回顾 | 全章场景、关键事件、人物动态 |
| 某线索/伏笔 | 该线索首次出现段落 + 随后演进 |

### E4 — 输出情节摘要

```
📖 第X章「{章名}」情节回顾

【查询焦点】{用户问什么}

【场景】{地点 + 时间 + 出场人物}

【相关情节】
{从原文提取的 2-5 句话摘要，直接回答用户问题}

【伏笔关联】（如有）
{本章关联的伏笔条目及当前状态}
```

### E5 — 多章关联查询

当用户跨章查询时（如"第3到7章之间XX的变化"）：

1. 逐章定位并读取第 3、4、5、6、7 章
2. 每章提取与 `XX` 相关的段落（仅相关段落，非全文）
3. 按时间线呈现演进过程：

```
📖 XX 线索回溯（第3章 → 第7章）

第3章「{章名}」— {一句话}
第4章「{章名}」— {一句话}
第5章「{章名}」— {一句话}
第6章「{章名}」— {一句话}
第7章「{章名}」— {一句话}
```

## 关联文件

| 文件 | 路径 | 用途 | 读写 |
|------|------|------|------|
| `项目信息.json` | `大纲/`（优先）或 `outline/` | 伏笔数据（`foreshadowing` 数组） | 读写 |
| `剧情大纲.md` | `大纲/剧情/` 或 `outline/plot/` | 大纲伏笔计划提取 | 只读 |
| `第XX章 XX.md` | `正文/`（优先）或 `body/` | 章节原文，伏笔提取与情节回溯的数据源 | 只读 |

## 数据格式速查

### foreshadowing 数组条目格式

```
{第N章}_{一句话关键意思}_{待回收 或 第M章}
```

字段分隔符：`_`（下划线）

### 项目信息.json 中的存储位置

```json
{
  "书名": "XX",
  "content_rating": "一般向",
  "foreshadowing": [
    "第3章_后山发光石头手心留印记_待回收",
    "第5章_偷听到管家提及下月初三西城码头_第12章"
  ]
}
```

`foreshadowing` 字段位于已有数据字段之后，作为 JSON 数组独立成段。

---

## 注意事项

- 伏笔数据写入 `项目信息.json` 时**不覆盖**已有字段（`content_rating`、`nsfw_tier_range`、`nsfw_output_level` 等），仅在 JSON 最下方追加/更新 `foreshadowing` 数组
- 情节回忆时如找不到对应章文件，检查文件名格式（`第XX章 XX.md` / `ChXX XX.md`）并尝试 Glob 模糊匹配
- 大纲预登记的伏笔回收章号可能为 `待定`，正文实际放置时更新为 `待回收`
- 伏笔关键意思严格控制在 50 字以内，不展开背景、不添加评价
- 此技能不对伏笔质量做评判，不主动建议设伏笔。仅在用户触发时执行
- 短篇作品同样可用，伏笔数量少时清单更简洁
