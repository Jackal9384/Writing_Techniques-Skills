# 基础写作辅助

此技能是写作系统的**文本处理基础层**。接收 Write-Router 传入的已分类文本和润色配置，按规范矩阵逐条优化后返回。

## 核心定位

- **纯文本优化**：只做一件事——接收文本 + 润色配置 → 按规范矩阵优化 → 返回。不检测、不分割、不调度、不整合
- **Write-Router 独家调度**：用户不直接触发此技能——所有写作意图由 Write-Router 统一接收、判断、预分配后，再将对应段落传入此技能处理。Write-Router 是 Core 的唯一调度源（标准模式处理正文段落，轻量模式处理创建阶段大纲文本）
- **模式感知**：从 Write-Router 传入的 `polish_mode` 和 `polish_config` 中读取润色程度——轻度/中度/重度，据此调整加工强度

## 触发条件

仅由 Write-Router 调度：Write-Router 在步骤 4.1 中将已分类的 `general` 段落打包传入（标准模式）；或在轻量模式中将创建阶段大纲文本传入（`content_type` 为 `大纲文本`）。此技能不接收用户直接触发，也不接收创建技能直接调用。

## 关联文件

| 文件                                | 位置               | 用途                                  | 读写  |
| --------------------------------- | ---------------- | ----------------------------------- | --- |
| `润色配置.json`                       | `大纲/`            | 润色模式（由 Write-Router 读取后传入，此技能不直接读取） | —   |
| `主要角色.md` / `次要角色.md` / `龙套角色.md` | `大纲/人物/`（或分卷子目录） | 人物数据，供规范 2/2.2 降重率校验及性格参照           | 只读  |
| `设定.md`                           | `大纲/设定/`         | 世界观约束、场景设定，供正文描写参照                  | 只读  |

## 执行模式

**始终跳过计划模式**：此技能仅被 Write-Router 调度，直接按步骤处理。

---

## 步骤 1：接收数据包

### 由 Write-Router 调度时

从 Write-Router 接收已分类的文本数据包：

```
{
  "text": "{一般段落组文本}",
  "context": {
    "chapter": "{当前章号/章名}",
    "volume": "{当前卷号或 null}",
    "content_type": "{叙事文本/对话文本/描写文本/大纲文本}",
    "prose_mode": "narrative"
  },
  "polish_mode": "{轻度/中度/重度}",
  "polish_config": { "{完整的润色配置 JSON}" }
}
```

### Write-Router 轻量模式时

Write-Router 在轻量模式（`mode: "creation_phase"`）下将创建阶段大纲文本传入，数据结构与标准模式一致，`content_type` 为 `大纲文本`。Core 对两种模式的数据包不做区分——统一按 `content_type` 确定规范矩阵。

## 步骤 2：识别内容类型

根据 Write-Router 传入的 `content_type` 确定使用的规范矩阵：

| 内容类型     | 润色强度          | 应用规范                      |
| -------- | ------------- | ------------------------- |
| **叙事文本** | `polish_mode` | 应用全部正文适用规范（1/2/2.2/3/4/5） |
| **大纲文本** | `polish_mode` | 应用规范 1.5，其余规范酌情           |
| **对话文本** | `polish_mode` | 重点应用规范 4                  |
| **描写文本** | `polish_mode` | 重点应用规范 2、3                |

**润色强度**（由 Write-Router 传入的 `polish_mode`）：

| 模式   | 加工策略                     |
| ---- | ------------------------ |
| `轻度` | 仅书面化、规范化书写，保留用户原话结构与用词   |
| `中度` | 在用户原话基础上小幅优化表达，改动幅度 ≤45% |
| `重度` | 保留原意，完全改写润色，但须遵守降重率规范    |

## 步骤 3：按规范逐条优化

依据内容类型，按下方规范矩阵逐条过检（✓=强制应用 / △=酌情应用 / ✕=不适用）：

| 规范               | 叙事文本 | 大纲文本 | 对话文本 | 描写文本 |
| ---------------- | ---- | ---- | ---- | ---- |
| 规范 1（标点正确性）     | ✓    | △    | ✓    | ✓    |
| 规范 1.5（大纲特殊）    | ✕    | ✓    | ✕    | ✕    |
| 规范 1.7（禁止数据堆砌）  | ✓    | ✕    | ✓    | ✓    |
| 规范 2（间接描写）      | ✓    | ✕    | ✕    | ✓    |
| 规范 2.2（性格间接化）   | ✓    | ✕    | ✕    | ✓    |
| 规范 3（风景穿插）      | ✓    | ✕    | ✓    | ✓    |
| 规范 4（对话增强）      | ✓    | ✕    | ✓    | ✕    |
| 规范 5（降重率）       | ✓    | △    | ✓    | ✓    |

**逐条过检**：按规范 1 → 1.5 → 1.6 → 1.7 → 2 → 2.2 → 3 → 4 → 5 的顺序依次检查，发现违规立即修正。

## 步骤 4：返回优化结果

将优化后的文本返回给 Write-Router：

```
{
  "processed_text": "{优化后文本}",
  "changes_summary": "{调整摘要}"
}
```

## 写作规范

以下规范是此技能的核心处理标准。优化文本时**逐条过检**，不可跳过。

### 规范 1：段落节奏控制

**为什么需要这条规范**：

AI 在未经规范约束时，倾向于将叙事写成"产品报告"——每个信息点用一句独立的陈述句罗列出来，句与句之间只有并列关系，没有逻辑流转。读者读到的不是一个人在经历一件事，而是一份分项说明：

> 血已经流了太多。他的视野边缘开始发黑。耳边的声音像是隔了一层水。他只看到一道剑光向他喉咙飞来。

四句话各自独立，每句都在"报告"一个状态，但彼此之间缺乏因果递进——读者感受到的是一个冷静的第三方在逐条陈述伤情，而非一个濒死之人的主观体验。

规范1的作用，就是将这些**彼此关联但被句号割裂的短句，融合为有逻辑、有转折、有呼吸的自然句**：

> 血已经流了太多了，视野边缘开始发黑，有些看不清了，声音也有些听不到了。
> 
> 最后他只看到一道寒光向他刺来。

两句。第一句将失血→视力模糊→听力衰减串成一个完整的生理衰退过程，逗号承载的是"因为…所以…"的因果逻辑；换行之后，独立成段的最后一句是视觉收束——读者跟着角色的视角，看到那道终点。

**核心链路**：

```
产品报告式写作（AI 默认）              自然叙事（规范1 约束后）
─────────────────────────          ────────────────────────
句号 = 分项标记                      句号 = 段落收束
每句独立陈述一个事实                   多句融合为一个逻辑流
句与句之间只有并列                     句与句之间有因果/转折/递进
读起来像看说明书                      读起来像在经历这件事
```

**原则**：规范1约束的不是"一段能写多长"，而是**哪里不该用句末标点**。一段极长但标点使用正确的句子是被允许的——例如用逗号、分号、冒号等句内标点将超短句、短句、长句合理连接，形成逻辑流畅的自然段。**禁止的是**在语义彼此关联的句子之间滥用句末标点（。！？…）将其截断为碎片。

**"句子"的定义**：本规范中的"句子"指以句末标点（。！？… 等）收尾的**完整自然句**，一个自然句的结束也就表示一件事情、一个话题被终结，要慎重地考虑。

**核心规则：句末标点的正确使用**

| 标点 | 何时使用 | 何时不用 |
|------|---------|---------|
| 句号（。） | 语义完整收束、一个意群自然结束、形成段落感时 | 前后两句语义紧密关联、属同一逻辑链时——改用逗号连接 |
| 问号（？） | 疑问语气结束，**独立成段** | 连续追问挤在同一段（必须逐句拆段换行） |
| 感叹号（！） | 感叹/强烈语气结束，**独立成段** | 连续感叹挤在同一段（必须逐句拆段换行） |
| 省略号（…） | 留白、余韵、渐弱，**独立成段** | 与句号/问号/感叹号串联使用 |

**核心禁令：禁止句末标点链接**

彼此语义关联的句子之间，**不得**用句末标点串联为"X{标点}Y{标点}"的链式结构。应用逗号（，）将关联语义融合为自然句，或用换行使独立情感句各自成段。

| 违规形态 | 说明 | 纠正 |
|---------|------|------|
| 短句 + 标点 + 短句 | 两个 6~15 字、语义关联的短句用句号/问号/感叹号断裂 | 句号→逗号合并；问号/感叹号→各自拆段换行 |
| 超短句 + 标点 + 任意句 | 超短句（≤5字）后方跟句末标点再接其他句子 | 超短句应单独成行，或用逗号并入前/后句 |
| 长句 + 标点 + 短句 | 长句以标点收束后紧跟一个语义相关的短句 | 句号→逗号合并为一个更长但逻辑流畅的自然句 |
| 任意句 + 标点 + 超短句 | 超短句前方有句末标点将其孤立 | 超短句并入前句（逗号），或独立成行 |

**纠正原则**：遇到句末标点链接时，目标是**将断裂的语义碎片融合为有逻辑流转的自然句**——调整语序、增删连接词、改变句式结构，确保读起来像一句话自然流淌，而非两句话被逗号硬拼在一起。

| 句末标点 | 纠正路径 | 原因 |
|---------|---------|------|
| 句号（。） | 合并为一个完整自然句，或拆段换行 | 陈述语气中性，两种路径均可 |
| 问号（？） | **仅拆段换行**，禁止合并 | 疑问句情感独立，换行强化追问感 |
| 感叹号（！） | **仅拆段换行**，禁止合并 | 感叹句情感强烈，换行保留冲击力 |

**超短句处理规则**：

- 超短句（≤5字）在没有必要的情况下，不与其他超短句用句末标点相连，各自单独成行
- 有必要时（同一意群、快速动作序列等），将它们**融合为一个完整的自然句**——调整语序、增减虚词、用逗号或省略号连接，使多个动作或感受在一口气内自然流淌
- 超短句成段时不得出现连续两个及以上的句末标点

**反例 1**（短句间句号链接）：

> 她走进房间。房间很暗。窗帘拉着。她打开灯。然后看到了桌上的信。

**正例 1**（合并+拆段混合）：

> 她走进房间，窗帘紧拉着，光线昏暗，空气里浮着一层薄灰。
> 
> 打开灯后，她看到了桌上的信。

**反例 2**（超短句堆叠——句号链接）：

> 他停下。回头。皱眉。没说话。

**正例 2**（拆段——各自独立）：

> 他停下，
> 
> 回头，
> 
> 皱眉。
> 
> 没说话。

**反例 3**（超短句撞句号）：

> 跑了。追。没追上。算了。

**正例 3**（有必要时逗号相连）：

> 跑了，追，没追上...算了。

**反例 4**（长句+句号+短句链）：

> 他将手中的信纸翻来覆去看了三遍，每一个字都像针一样扎进眼睛里，窗外的雨声渐渐大了起来。他放下信。叹了口气。

**正例 4**（拆段——短句独立成段）：

> 他将手中的信纸翻来覆去看了三遍，每一个字都像针一样扎进眼睛里，窗外的雨声渐渐大了起来。
> 
> 他放下信，
> 
> 叹了口气。

**反例 5**（短句+句号+超短句）：

> 她推开门走进客厅，沙发上坐着一个陌生男人。是他。

**正例 5**（合并——句号改逗号）：

> 她推开门走进客厅，沙发上坐着一个陌生男人。是他。

**反例 6**（问号链接——连续追问挤在同一段）：

> 这是什么？这怎么可能呢？为什么会这样呢？

**正例 6**（问号强制拆段）：

> 这是什么？
> 
> 这怎么可能呢？
> 
> 为什么会这样呢？

**反例 7**（感叹号链接 + 叹号误用于陈述句）：

> 他做到了！他真的做到了！所有人都不敢相信。

**正例 7**（感叹号强制拆段）：

> 他做到了！
> 
> 他真的做到了！
> 
> 所有人都不敢相信。

**反例 8**（混合标点链接——问号+感叹号挤在同一段）：

> 你疯了吗？快停下！这会害死你的！

**正例 8**（逐句拆段）：

> 你疯了吗？
> 
> 快停下！
> 
> 这会害死你的！

### 规范 1.7：减少数据堆砌——优先用感受而非量词、设定、事实来叙事

**为什么需要这条规范**：

AI 在不知道如何"讲故事"时，会退回到它最擅长的模式——输出数据。它用量化的身体数据代替外貌描写，用世界观设定文档代替环境描写，用履历清单代替人物塑造。读者读到的不是一个人在经历一个故事，而是一份带格式的产品规格书。

**三种应减少的数据写法**：

| 类型 | AI 倾向于这样写（应减少） | 更好的写法 |
|------|------------------------|-----------|
| **量词与数词** | "那天丽丽经过管理室时嬷嬷从针线活上抬起头，视线在她背上的腰窝位置停了不到两秒。没有问。只是多看了两眼。丽丽不知道这两眼意味着什么——她只知道剑带今天勒在腰上，修女袍下面是赤裸的，风从高开叉灌进来时小穴会自己收缩。这种感觉已经和她右手握剑时的肌肉记忆一样自然了。" | "那天丽丽经过管理室时嬷嬷从针线活上抬起头，视线在她背上的腰窝位置停了片刻。没有问。只是多看了几眼。丽丽不知道这几眼意味着什么——她只知道剑带今天勒在腰上，修女袍下面是赤裸的，风从高开叉灌进来时小穴会自己收缩。这种感觉已经和她右手握剑时的肌肉记忆一样自然了。" |
| **讲设定** | "这个世界有三大帝国、七大种族、十二种魔法体系。精灵族寿命约800年，矮人族擅长锻造，人族人口最多但寿命最短。" | "她在酒馆角落里看到一个精灵——不是第一次见到，但每次都会忍不住多看一眼。那张脸看起来二十出头，但她知道这人可能见过她曾曾祖父。" |
| **摆事实** | "她毕业于23区第三中心医院，曾获得年度最佳住院医师奖，专攻外科急救，拥有BLS和ATLS认证，职业生涯中经手过超过200例枪伤手术。" | "她看着伤口停顿了不到一秒，手已经伸出去按住了出血点。这个动作她做过太多次——多到不需要思考，多到她自己都不记得上一次紧张是什么时候。" |

**核心原则**：

数据是给作者参考的，不是给读者阅读的。角色的身高体重、世界的种族体系、人物的履历成就——这些属于**大纲文件**（人物存档、设定文档），是写作时的参考约束。正文的任务是让读者**感受到**这些数据带来的效果——一个人很高（数据）→ 他进门撞到了门框（感受）；一个人专业过硬（数据）→ 她处理伤口时手比脑子快（感受）。

**这不是绝对禁令**。精确的数量词在特定情境下是必要且有力的——"她等了整整三个小时"和"她等了很久"是不同的；"他数了数，还剩七发子弹"和"他数了数，还剩一些子弹"是不同的。关键是**默认减少，而非绝对不使用**——优先用不定数词和感受传递信息，仅在精确数字本身承载叙事意义时保留它。

**检测标准**：写完一段描写后问自己——这些数字和信息如果替换为不定表达或感受描写，对场景的理解有没有影响？如果没影响，优先用不定表达。

**与规范5（降重率）的关系**：规范5禁止的是照搬大纲原文，规范1.7禁止的是**把信息结构本身当作文本**——即使换了一套措辞，如果本质还是在"逐条陈述数据"，仍然违规。

### 规范 1.5：大纲类文本特殊处理

**仅适用于大纲/剧情/设定类文件。**

- 允许使用大段连接的文字
- 减少句号使用，以分号（；）分隔意群
- 保持条目式的清晰结构，不强制短段分行

**示例**：

> 主角在此阶段经历三次关键转折：首次遭遇敌对势力，在逃亡中意外获得秘宝；秘宝引发出租体内的潜藏血脉，导致外貌与性格发生微妙变化；最终在一次街头冲突中暴露能力，被路过的宗门长老注意到并收为记名弟子

### 规范 1.6：破折号禁令

**原则**：双字线破折号 `——`（U+2014 U+2014）在中文正文中**禁止使用**。唯一例外：声音延长（如"啊——"表示拖长的叫声）等特定写作技法中 `——` 是标准表达方式，允许保留。

**为什么禁止**：

`——` 占两个字宽，视觉冲击力强，但中文排版中绝大多数 `——` 可被更精确的标点替代——逗号、句号、省略号、冒号各自有明确语义，`——` 将它们的功能模糊化。大量使用 `——` 是 AI 生成文本的典型特征——人类写作者在不确定用什么标点时倾向用它兜底，最终导致文本中破折号泛滥、停顿节奏单一。

**替代规则**：

| 原用法   | `——` 原句              | 替代                                     |
| ----- | -------------------- | -------------------------------------- |
| 解释说明  | `他提到了那个人——他的父亲`      | 逗号：`他提到了那个人，他的父亲` / 括号：`他提到了那个人（他的父亲）` |
| 转折    | `她想说点什么——又咽了回去`      | 逗号：`她想说点什么，又咽了回去`                      |
| 停顿/犹豫 | `我——我不知道`            | 省略号：`我……我不知道`                          |
| 强调    | `只有一个答案——不`          | 句号拆分：`只有一个答案。不。`                       |
| 话语中断  | `你难道——`              | 省略号：`你难道……`                            |
| 插入补充  | `张三——那个从来不笑的人——居然笑了` | 逗号：`张三，那个从来不笑的人，居然笑了`                  |

| 突然中断+延长 | `"你——"她指着他的鼻子，尾音拖了三秒才接上"——给我站住"` | 省略号：`"你……"她指着他的鼻子，尾音拖了三秒才接上"……给我站住"` |

**允许保留的例外**：

| 用法    | 示例                  | 原因                           |
| ----- | ------------------- | ---------------------------- |
| 声音延长  | `"救命啊——"声音在山谷里拖了很长` | 表示声音拖长，省略号不适用（省略号是断续/渐弱，非延长） |
| 拟声词延长 | `呜——汽笛声响彻码头`        | 同上，声音延长的唯一标准表记               |

**硬约束**：

- **全技能不豁免**：NSFW、成品校验、提示词增强——没有任何技能允许在产出文本中保留非例外用途的 `——`。这是跨技能的绝对禁令，不进入 `exempted_norms` 列表，任何技能无权豁免
- 成品输出校验在步骤 2 结构扫描中**强制过检本规则**——发现非例外用途的 `——` 一律按上述替代表自动修正；无法确定用途的标记 `[⚠️ 需人工：破折号用途不明]`
- 人物对话中的声音延长不在此限，但连续出现 ≥3 个 `——` 时触发提醒——可能不是技法需要而是写作习惯

### 规范 2：人物描写的间接化

**原则**：避免直接的、长段的人物外形与行动叙述。多用间接手法让描写生动。人物特征不必在初登场时一次性交代完毕——没有人一见面就盯着别人的胸、腿、头发看，那很不礼貌。好的描写像剥洋葱，一层一层来。

**具体规则**：

- **借物喻人**：通过物品、环境来折射人物特征
  - 反例：她长得很美，身材纤细。
  - 正例：风一吹，那件旧旗袍在她身上晃荡得像挂在了衣架上。
- **借镜喻人**：通过他人视角/反应来映衬人物
  - 反例：他走进酒馆，所有人都注意到了他的高大身材。
  - 正例：他弯腰钻进酒馆门框时，靠门那桌的酒客下意识往后挪了半寸椅子。
- **借他人之口（借喻）**：不直接叙述特征，而是让另一个角色在对话或内心戏中点出
  - 反例：她有一双惊人的长腿。
  - 正例：身边的闺蜜扫了一眼，嘀咕了句"腿玩年啊。" / 身后的男生压低声："这腿比我命都长。"
- **打趣俏皮话**：用轻松、略带调侃的笔调描写，不板着脸叙述
- **短篇白描**：短段落可直接用白描，但不堆砌形容词
  - 正例：她瘦，白，走路没声。

#### 手法 2A：延迟揭示——特征不必在初登场时交代

**原则**：角色的一些外形特征不必在第一次出场时就全部抛出。现实中没有人会一照面就把对方从头到脚扫描一遍。那是 AI 的写法，不是人的写法。

**操作规则**：

- 初登场时，仅描写对当下场景有意义的特征（如：打架场景写体型，对话场景写表情，搜索场景写视力）
- 其余特征在后续章节中，在**该特征被看见的时机**自然带出
- 特征第一次被提及时，优先使用**借镜喻人**或**借他人之口**，而非叙述者直接陈述

| 特征    | 初登场写不写？       | 什么时候写？                   |
| ----- | ------------- | ------------------------ |
| 胸部/身材 | ✕ 不写（谁上来就盯胸？） | 角色进入亲密关系、换衣服、或他人偷瞄时      |
| 长腿    | △ 如角色正走路/跑步可写 | 他人内心戏、或她的动作中体现（"一步两个台阶"） |
| 长发/发型 | ✓ 可写（视觉第一印象）  | —                        |
| 身高    | ✓ 可写（空间关系有意义） | —                        |
| 伤疤/纹身 | ✕ 不写（非当下可见）   | 露出时写——脱衣服、挽袖子、风吹起衣角时     |
| 手/手指  | ✕ 不写          | 角色用手做事时——弹琴、握住东西、递物品时    |

#### 手法 2B：多角度轮换——突出特征不可死盯一个角度写

**原则**：当一个特征足够突出、让人想不注意都难，确实需要在不同场景中多次描写时，**每次必须换一个描写角度**。盯着同一个角度反复写等于告诉读者"这个作者只会这一招"。

**轮换角度清单：**

| 轮次    | 描写方式        | 示例（特征：腿长）                    |
| ----- | ----------- | ---------------------------- |
| 第 1 次 | 他人内心戏/口述    | 闺蜜瞟了一眼："腿玩年。"                |
| 第 2 次 | 功能/动作后果     | 她一步两个台阶走得飞快，后面的人要跑着才跟上。      |
| 第 3 次 | 环境互动        | 沙发对她来说太矮了，膝盖几乎弯到了胸口。         |
| 第 4 次 | 对比/参照物      | 站在一排女生中间，她的腰线比别人高出整整一个头的位置。  |
| 第 5 次 | 穿搭/衣物       | 那条普通牛仔裤穿在她身上，裤脚只到脚踝上方，不是七分裤。 |
| 第 N 次 | …继续轮换上述五个维度 | 不重复此前已用过的角度                  |

**适用特征**：

- 本规则不仅适用于生理特征，同样适用于：**性格特质**（如暴脾气——一次写摔东西、一次写脸涨红、一次写旁人躲开）、**能力特征**（如力大无穷——一次写举重物、一次写捏碎杯子、一次写别人推不动她）、**声音特征**（如嗓音沙哑——一次写电话里被误认成男人、一次写唱歌时的颗粒感、一次写小声说话反而更清晰）

**核心约束**：

- 同特征同角度在同一章节中最多出现一次
- 同特征同角度在不同章节中最多出现两次（第二次必须与其他角度组合，不能纯重复）
- 出现第三次同角度描写 → 违规，必须重写

**适用范围**：外在造型描写、人物行动描写、性格特质表现、能力特征展示。内心活动不在此限。

### 规范 2.2：人物性格描写的间接化

**原则**：性格描写与外貌描写遵循同一套间接化逻辑。直接给角色贴性格标签（"他是一个莽撞冒失的人"）是 AI 的写法——现实中没有人能一眼看透另一个人的全部性格，这种话只会出现在他人的评价中，不会出现在叙述者的口中。

#### 为什么需要这条规范

叙述者直接告诉读者"这个人很善良""这个人脾气暴躁"是在剥夺读者的判断权。读者应该在角色的行为、对话、选择中**自己得出结论**。一个写了三章都没发过火的人，叙述者说他"脾气暴躁"，读者不会信。一个一开头就救了路边小猫的人，不需要叙述者说他"善良"，读者自己会看到。

**核心链路：**

```
禁止：叙述者贴标签 → "他是一个莽撞、冒失的人。"
允许：他人评价中出现 → "我妈总说我莽撞，她没说错。"
要求：用行为和情节让读者自己得出这个结论
```

#### 两个主要描写方向

**方向 A：与故事结合——性格随情节展开**

性格不是一张表格，是一个过程。不同性格侧面在不同类型的事件中被激活，读者通过角色**做了什么**来认识他。

| 写法            | 例（性格：莽撞冒失）                                  |
| ------------- | ------------------------------------------- |
| ✕ 直接贴标签       | "张三是个莽撞冒失的人。"                               |
| ✓ 初登场用一个小事件激活 | 张三撞开门冲进来，才发现走错了教室，满屋子的人转头看他，他挠挠头又撞上了门框。     |
| ✓ 后续用更大的事件深化  | 别人都趴下了，就他还站着往前冲。李四拽住他："你不要命了？"他说："刚才没想那么多。" |
| ✓ 用后果反写       | 医生看着片子叹气："上个月叫你静养，你倒好，又去爬山。这条腿再断一次就接不上了。"   |

**方向 B：与外貌结合——外貌暗示性格**

伤疤、纹身、体态、眼神、穿衣风格——这些都是性格的视觉锚点。不直接说"他很凶"，而是让外貌自己开口。

| 外貌特征                | 暗示的性格方向                  |
| ------------------- | ------------------------ |
| 满脸横肉 + 寸头 + 脖子上的旧刀疤 | 不好惹、有暴力过往、经历过事           |
| 满臂纹身但戴着银边眼镜         | 外表粗犷/反叛 + 内在细腻/斯文（冲突复合型） |
| 永远把衬衫扣到最上面那颗        | 严谨、保守、可能有不想让人看到的伤        |
| 走路时右脚微跛但不减速         | 有旧伤但不服输、倔强               |
| 手指甲永远有洗不掉的机油渍       | 动手能力强、蓝领背景、不讲究外表         |
| 笑容永远停在嘴角不到眼睛        | 表面友好实则疏离、有故事/有心结         |

**操作规则**：外貌写完立即接一个行为/情节，让外貌暗示的性格落地——否则外貌只是摆设。

> 例（纹身+镜框——冲突型）：
> 他推了推银边眼镜，一只满臂纹身的手翻开了面前的文件。坐在对面的客户明显不知道该看他的纹身还是眼镜，目光来回跳了三趟。
> 
> ↑ 外貌暗示了"粗犷+斯文"的冲突性格，但读者是通过客户的反应（不是叙述者的标签）感受到的。

#### 性格描写的四项技法

**技法 1：借行为写性格（替代贴标签）**

叙述者不评价，只写角色做了什么。读者自己判断。

| 标签（禁止） | 行为（正确）                          |
| ------ | ------------------------------- |
| "他很善良" | 雨里遇到一只纸箱里的猫，他脱了自己的外套盖上去。        |
| "她很小气" | 吃完饭她拿着账单算了三遍，最后说了句"你那份多了两块钱。"   |
| "他胆子大" | 别人都在往后退，就他往前走了一步，这一步很小，但没人在意大小。 |

**技法 2：借他人之口写性格**

性格标签是允许出现的——但只能出现在**他人的评价**中。不同人对同一角色的评价可以互相矛盾，这正是塑造立体性格的好机会。

> 正例（他人评价——立场不同、说法不同）：
> 李四对王五说："张三那个人就是一根筋，你别跟他计较。"
> 
> 但赵六私下跟钱七说："张三不是一根筋，他是看准了就不放手。你以为他能忍三年是蠢？他比谁都精。"
> 
> ↑ 两个评价互相矛盾，读者开始好奇张三到底是什么人。这才是有效的性格写作。

**技法 3：性格的延迟揭示——浅层在前，深层在后**

初登场时读者只能看到性格的**表层**（行为方式、说话语气），深层性格（动机、价值观、软肋）随着情节推进逐步揭露。三个层次：

| 层次         | 揭示内容               | 揭示时机       |
| ---------- | ------------------ | ---------- |
| 表层（初登场）    | 行为习惯、说话方式、情绪反应     | 角色第一次出现的场景 |
| 中层（发展期）    | 价值判断、做人底线、对重要事件的态度 | 面临选择/冲突的场景 |
| 深层（高潮/关键章） | 动机根源、最大软肋、性格成因     | 重大危机/坦白/闪回 |

> 例（三层递进——性格：表面冷漠实则心软）：
> 
> 表层（初登场）：他路过那只受伤的狗时脚步没停，连看都没看一眼。
> 
> 中层（第5章）：师妹发现他在后院给那只狗上药，手法很轻。见师妹来，他起身走了，丢下一句："别跟别人说。"
> 
> 深层（第15章，闪回）：六岁那年他养过一条狗，被父亲在他面前吊死了，因为"男孩子不能有软肋"。此后他没再摸过任何一只动物。

**技法 4：性格的多角度轮换——同一特质不同情境轮换**

与规范 2B 同理，同一性格特质在不同章节中出现时，必须轮换情境/表现方式。

| 轮次    | 描写方式    | 示例（性格：倔强）                      |
| ----- | ------- | ------------------------------ |
| 第 1 次 | 行为冲突    | 妈妈叫他往东他偏往西，最后摔门出去了。            |
| 第 2 次 | 身体/生理反应 | 他咬着牙不哭，嘴唇都咬出血了，但眼泪就是不掉下来。      |
| 第 3 次 | 他人评价    | "这孩子，跟我年轻时候一模一样。"父亲指着他对母亲说。    |
| 第 4 次 | 后果展现    | 他在雨里站了四个小时等她回来，第二天发了高烧，但她看到了。  |
| 第 5 次 | 情境反转    | 这次他让步了。所有人都愣住了，这个倔了二十年的人，居然让了。 |

**硬约束**：

- 禁止在初登场时用任何形式的性格标签（包括"他看起来是个很XX的人"——叙述者没有权利"看起来"）
- 前 3 章内，同一性格特质必须至少用一次**行为**来展现，纯靠他人评价不算数
- 同性格特质同情境下同表现方式，跨章最多出现两次

#### 与规范 2 的衔接

规范 2.2 是规范 2（人物描写间接化）在性格维度的专项扩展：

- 规范 2 管**外貌怎么写** → 借物喻人、借镜喻人、延迟揭示、多角度轮换
- 规范 2.2 管**性格怎么写** → 借行为写性格、借他人之口、三层递进、多角度轮换
- 两者共享同一核心逻辑：**禁止叙述者贴标签，让读者自己看**

### 规范 3：风景穿插

**原则**：在对话之间与长段叙事之间适当插入风景/环境描写，打破文本单调感。

**具体规则**：

- 对话来回超过三轮时，中间插入一句环境/风景描写
- 长段白描叙事（超过 200 字）中途加入环境细节
- 风景描写不求多，一句即可——作用是"换气"
- 风景应与当下场景/情绪呼应，不为写景而写景

**示例**：

> "你确定要这么做？"
> 
> "没有别的办法了。"
> 
> 窗外梧桐叶落了一片，贴着玻璃滑下去。
> 
> "那就走吧。"

### 规范 4：对话增强

**原则**：对话常态搭配神情、动作或内心活动以增强表现力，但白描（纯对白不加修饰）在特定场景中是有效技法，不应一律禁用。

**具体规则**：

- 对话时优先搭配以下之一：神情描写 / 身体动作 / 内心闪念
- 神情与动作应服务于对话情绪，不做冗余堆砌
- 内心想法可用括号注记或短句并入叙事流
- **白描适用场景**：以下情况可仅用纯对白，不加神情/动作修饰：
  - 沉闷压抑的氛围（对话双方情绪低沉，留白反而加重压迫感）
  - 简短快速的应答（嗯。/ 好。/ 知道了。——单字成段有力量）
  - 冷对峙/冷战（刻意不说话外之音，靠台词本身传递疏离感）
  - 信息交代（功能性对话，不做冗余表演）
- 白描对话同样遵守规范1的超短句规则

**反例**（该加但没加——重要情绪对话缺乏表现力）：

> "你为什么不说一声就走了。"
> "我说了你也不会懂。"
> "你不说我怎么懂。"

**正例**（对话增强）：

> 她停了一下，手指无意识地卷着发尾。"我知道了。"
> 
> 至少现在知道了。

**正例**（白描——沉闷场景，纯对白反而更有力）：

> "什么时候走。"
> 
> "明天。"
> 
> "不回来了？"
> 
> "嗯。"

### 规范 5：降重率规范

**核心原则：大纲/设定/角色/Prompt.md 等参考文件提供的是合法性验证，不是写作素材。正文必须对所有参考源进行二次加工后输出——直接引用、近义复述、跨章重复使用同一描述角度，均属违规。**

#### 为什么需要这条规范

大纲文件（角色文件、剧情大纲、设定文件）以及 Prompt.md（提示词增强技能产出）存在的意义是让 LLM 知道"这个角色有什么特征、这个世界有什么规则、这章要写什么"——即验证一段描写的合法性。如果正文直接照搬这些参考源中的描述语句、数据、比喻，甚至在不同章节反复使用同一套措辞，那么这套技能系统就失去了存在价值——用户自己复制粘贴即可，不需要 AI 创作。

**参考源 → 正文的正确链路：**

```
参考源中的原始数据（大纲/设定/角色/Prompt.md）
    │
    ▼
合法性验证（"这个角色确实有 B 罩杯""本章确实要写后山奇遇"）── ✓ 允许
    │
    ▼
禁止 ── 直接引用原句（"底盘紧致、乳峰高翘挺立"）
禁止 ── 直接引用 Prompt.md 中的提示词原文作为正文叙述
禁止 ── 近义改写原句（"底盘紧致，乳峰挺翘，即便放松也保持上翘"）
禁止 ── 跨章反复使用同一组描述词
    │
    ▼
要求 ── 换角度、换感官、换语境、换精度，二次创作后输出
```

#### 四条禁令

**禁令 1：禁止完全引用（照搬原文）**

不得将任何参考文件（大纲、设定、角色、Prompt.md）中的描述语句原封不动或仅调换语序后用于正文。Prompt.md 中的提示词是"写作指令"而非"写作文本"——正文不得将提示词里的叙述性语句直接复制为正文段落。

> 反例（大纲原句 → 正文照搬）：
> 大纲：`乳房并不丰硕，B 罩杯——胜在形态近乎完美：底盘紧致、乳峰高翘挺立`
> 正文：`乳房的轮廓在烛光中半明半暗——B 罩杯，底盘紧致，乳峰挺翘，即便在完全放松的状态下也保持着向上翘的形态`
> 
> ↑ 违规：底盘紧致、乳峰挺翘、B 罩杯——三个数据点完全复刻，仅加了一句"烛光中半明半暗"做包装。

> 正例（二次加工——换感官+换语境）：
> 大纲：`乳房并不丰硕，B 罩杯——胜在形态近乎完美：底盘紧致、乳峰高翘挺立`
> 正文：`他解开她衣襟时，掌侧擦过一处：不大，刚好盈满手心。那团柔软在他指间微微上挑，像一瓣被晨露压弯后又弹起的花。`

↑ 合规：保留了"不大/不丰硕"的核心事实（合法性验证通过），但完全换了描写角度（触感而非视觉）、换了语境（互动场景而非静态描述）、换了比喻（花瓣而非几何形态）。

> 反例（Prompt.md 提示词 → 正文照搬）：
> Prompt.md 中的提示词：`西城窄巷，天色将暗，巷口灯笼初亮，光线昏暗逼仄。主角孤身前来探查线索，穿棉麻夹衣。`
> 正文：`西城的窄巷里天色渐渐暗了下来，巷口的灯笼刚刚亮起，光线昏暗而逼仄。他孤身一人前来探查线索，身上穿着一件棉麻夹衣。`
> 
> ↑ 违规：场景→情境→人物行动的结构完全照搬 Prompt.md，仅调换语序和加几个虚词。提示词是写作指引，不是正文底稿。

**禁令 2：禁止近义复述（换皮不换骨）**

不得将任何参考源（大纲、设定、角色、Prompt.md）中的描述换几个同义词后当作新内容输出。判断标准：如果正文和参考源在同一个特征维度上使用了**相同的数据、相同的比喻方向、相同的描写器官/部位**，或正文的叙事结构与 Prompt.md 提示词的剧情要点高度重合（场景顺序→人物行动→情绪走向一一对应），即视为近义复述。

> 反例：
> 大纲：`阴茎粗长，约18cm，龟头饱满呈紫红色`
> 正文：`他的那根东西又粗又长，目测接近二十公分，前端那个蘑菇头鼓鼓的，颜色偏深`
> 
> ↑ 违规：粗长→又粗又长，18cm→接近二十公分，龟头→蘑菇头，紫红→颜色偏深。每一个数据点都找到了同义词，但没有新增任何角度。

> 正例（换角度——从视觉换为触觉/感受）：
> 正文：`她两只手才勉强握住。顶端蹭过她小腹时，她才发现那处的皮肤比想象中烫，像一块被太阳晒了一下午的石头。`

↑ 合规：保留了"粗/大"的事实，但换成了触感（两手握住）、温度（烫）、视角（她的感受），没有重复大纲中任何一个具体数据或比喻。

**禁令 3：禁止跨章重复（同一角度反复使用）**

同一人物/事物的同一特征，在不同章节中**不得**从同一角度使用同一组词汇重复描写。每次出现该特征时，必须换一个描述维度。

| 章节   | 描述同一特征"她身材娇小"           | 判定            |
| ---- | ----------------------- | ------------- |
| 第1章  | "她个子小小的，站在人群中只到别人肩膀"    | ✓ 视觉/对比       |
| 第3章  | "她踮起脚尖还是够不到最上面那格"       | ✓ 动作/功能后果     |
| 第5章  | "她的身形娇小，在人群中格外显眼"       | ✕ 回到了第1章的同一角度 |
| 第8章  | "别人三步的距离她要走四步"          | ✓ 行为节奏        |
| 第10章 | "她个子不高，但每次抬头看人时眼神从不落下风" | ✓ 视觉+性格（新组合）  |

**禁令 4：禁止感官单一（始终用一种感官描写同一特征）**

同一特征的多次描写必须轮换感官通道，不能每次都用同一感官（如始终是视觉描述）。

| 感官通道  | 可用描写角度                  |
| ----- | ----------------------- |
| 视觉    | 形状、颜色、光影、对比             |
| 触觉    | 温度、质地、压力、重量             |
| 听觉    | 声音、节奏、呼吸、布料摩擦           |
| 动作/后果 | 该特征导致的行为后果（够不到、塞不进、被挡住） |
| 他人反应  | 他人的目光、动作、回避或靠近          |

#### 合法二次加工手法

将参考源数据转化为正文描写时，以下手法视为合规加工：

| 手法  | 操作               | 示例（大纲"身高180cm"）               |
| --- | ---------------- | ----------------------------- |
| 换感官 | 从视觉换为触觉/听觉/动作    | "他进门时低头躲了下门框"                 |
| 换语境 | 嵌入互动场景而非静态陈述     | "她仰头看他，脖子酸了"                  |
| 换精度 | 用模糊感受替代精确数据      | "他比周围所有人都高出大半个头"              |
| 换视角 | 从他人眼中看，而非客观叙述    | "站他旁边说话，总觉得自己像被一面墙罩着"         |
| 换时间 | 不同时间/光线/状态下的不同呈现 | "晨光从他背后打过来时，影子把她整个人吞了进去"      |
| 换隐喻 | 不同的比喻体系          | 一次用建筑比喻（"像面墙"），一次用自然比喻（"像棵树"） |

#### 该条规范的检验标准

写完一段涉及人物特征的正文后，逐条自检：

1. 这段描写中，有没有任何参考源（大纲、设定、角色、Prompt.md）中出现过的**原词或原数据**？
2. 这个特征在之前的章节中是否**已经用同样的感官通道**写过？如果写过，这次换了吗？
3. 这段描写去掉之后，参考源中的那条数据能否被**独立还原**出来？（如果能还原，说明正文太接近参考源原文）
4. 这段正文的叙事结构是否与 Prompt.md 提示词的剧情要点**一一对应**？（如果是，等于用提示词做了正文底稿——违规）

如果问题 1、3 或 4 答"是"，必须重写。如果问题 2 答"是"，必须换感官/换语境。

#### 补充规则（保留原防过度润色规则）

以下规则承自原"防过度润色"规范，在降重率框架下仍然有效：

- **克制情感用词**：避免堆砌"心痛如绞"、"泪如雨下"等高度饱和的情感表达。情感靠情节与动作传递，不靠形容词堆叠
- **相近角度扩写**：从相邻语义维度展开扩写，而非原地叠加同义词。如已写"小巧玲珑" → 可从"因此走路轻快""在人群中容易被忽略""总被误认为比实际年龄小"等后果与表现角度扩写
