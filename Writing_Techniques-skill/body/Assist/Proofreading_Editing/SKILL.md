# 成品输出校验

此技能是写作系统的**唯一落盘入口**。任何技能（基础写作辅助、NSFW 专项写作、提示词增强、人物/设定/大纲编辑等）不得自行将内容写入本地文件系统——必须将待写入内容传入此技能，经校验通过后由此技能统一执行落盘。**不经校验直接写入视为流程违规。**

## 核心定位

- **唯一落盘入口**：系统内没有任何技能可以 bypass 此技能直接写文件——这是硬约束，不是建议
- **全类型覆盖**：所有输出到本地持久存储的文件均需校验——正文(.md)、JSON(.json)、结构化 Markdown（角色/设定/大纲）
- **格式感知**：根据文件类型自动选择校验策略（正文文本 / JSON / 结构化 Markdown）
- **校验不过自动改到过**：发现违规 → 自动修正 → 复检确认 → 落盘。不回头找上游，不自称"无法处理"退回
- **正文双轨校验**：标点合规（CPS.json）+ 段落/字句合规（Core 规范）
- **JSON 校验**：语法有效性 + 必填字段完整性 + 引用一致性
- **结构化 MD 校验**：必填字段完整性 + 跨文件引用有效性
- **NSFW 感知**：NSFW 内容的专项校验由 NSFW 技能步骤 4 自行完成，此技能仅做通用结构校验
- **被动调度**：由上游技能在准备写入时主动调用——上游技能不持有文件写入权限

## 触发条件

- **强制触发**：任何技能在将内容写入本地文件前**必须**调用此技能。不调用直接写入 = 流程违规，写入的内容视为不合规
- **手动触发**：用户直接要求"检验一下"、"检查一下"、"合规检查"等

## 关联文件

| 文件 | 位置 | 用途 |
|------|------|------|
| `CPS.json` | 本技能同目录 | 中文标点符号用法国家标准（GB/T 15834），正文标点合规性校验的唯一权威依据 |
| 基础写作辅助 SKILL.md | `body/Core/SKILL.md` | 段落节奏、间接描写等规范的校验基线 |
| `项目信息.json` | `大纲/` | 跨文件引用一致性校验的参照源（卷结构、章节数等） |
| `主要角色.md` / `次要角色.md` / `龙套角色.md` | `大纲/人物/` | 角色文件字段完整性校验的参照模板 |
| `Prompt.md` | `大纲/剧情/` | JSON 模式校验对象之一 |

## 文件类型识别与校验策略路由

接收待校验内容时，首先根据文件路径和内容特征判定类型，然后路由到对应的校验策略：

| 文件类型 | 判定依据 | 校验策略 |
|---------|---------|---------|
| **正文文本** | 路径含 `正文/` 或 `番外/`，文件为 `.md`，内容为叙事/对话/描写 | 第一轮（CPS.json 标点）+ 第二轮（Core 结构规范） |
| **JSON 数据** | 文件为 `.json` | 语法有效性 + 必填字段模式校验 + 引用一致性 |
| **角色 Markdown** | 路径含 `人物/`，文件名含角色类型 | 必填字段完整性 + 与其他角色文件的关系一致性 |
| **设定 Markdown** | 路径含 `设定/` 或文件名含 `设定` | 结构完整性 + 世界观规则自洽性 |
| **大纲 Markdown** | 路径含 `剧情/` 或 `大纲/`，非 JSON | 章节编号连续性 + 卷章对应关系 |
| **润色配置 JSON** | 文件名含 `润色配置` | 模式值域合法性 + 分卷覆盖完整性 |

## 执行模式

由上游技能调度时：跳过计划模式，直接按步骤执行。
用户直接触发时：进入计划模式（EnterPlanMode）。

## 执行步骤

### 步骤 0：接收待校验内容

接收上游技能传来的待写入内容及相关元数据。**根据内容类型，数据包结构不同**：

**正文文本类**：
```
{
  "type": "prose",
  "content": "{待校验的完整成品文本}",
  "file_path": "{目标写入路径，如 正文/第三章 初入江湖.md}",
  "source_skill": "{Core / NSFW / other}",
  "word_count": {字数},
  "chapter": "{当前章号/章名（如有）}",
  "volume": "{当前卷号（分卷多文件时必填，不分卷时为 null）}",
  "content_type": "{叙事文本 / 对话文本 / 描写文本 / NSFW}",
  "prose_mode": "{narrative / outline}",
  "exempted_norms": ["规范2", "规范2.2"]
}
```

| 字段 | 说明 |
|------|------|
| `prose_mode` | `"narrative"`（默认）→ 适用规范 1 段落节奏控制；`"outline"` → 适用规范 1.5 大纲类文本处理（免短段强制拆分，允许长段叙述和分号分隔） |

**JSON 数据类**：
```
{
  "type": "json",
  "content": "{JSON 字符串}",
  "file_path": "{目标写入路径，如 大纲/剧情/Prompt.md}",
  "source_skill": "{提示词增强 / other}",
  "expected_schema": "{Prompt / 项目信息 / 润色配置}"
}
```

**结构化 Markdown 类**：
```
{
  "type": "structured_md",
  "content": "{Markdown 文本}",
  "file_path": "{目标写入路径，如 大纲/人物/主要角色.md}",
  "source_skill": "{创建人物 / 设定编辑 / 剧情编辑 / other}",
  "md_category": "{角色 / 设定 / 大纲}"
}
```

### 步骤 1：正文文本校验 — 标点符号合规性（CPS.json）

**仅 `type = "prose"` 时执行。其他类型跳过此步骤。**

读取本技能同目录下的 `CPS.json`，以其中的标点符号定义、用法规则为校验依据，对成品文本进行全量标点扫描。**所有 E 级违规自动修正，所有 W 级违规在上下文可判定时自动修正**。

#### 1.1 扫描项目与自动修正规则

| 扫描项 | 依据 | 违规判定 | 自动修正动作 |
|--------|------|---------|------------|
| 句号 | §4 + §A.1 | 陈述句末尾漏句号；非陈述语气误用句号 | 补句号 / 改为对应语气标点 |
| 问号 | §4 + §A.2 | 非疑问句用问号；选择问句所有选项误加问号 | 改为句号 / 中间选项问号改逗号 |
| 叹号 | §4 | 无感叹语气滥用叹号；叠用超三个 | 改为句号 / 缩减至三个 |
| 逗号 | §4 + §A.3 | 长主语/句首状语后漏逗号；非提示性话语后误用冒号 | 补逗号 / 冒号改逗号 |
| 顿号 | §4 + §A.4 | 并列词语间漏顿号；概数间误用顿号；引号/书名号并列间多余顿号 | 补顿号 / 删顿号 / 删多余顿号 |
| 分号 | §4 + §A.5 | 非并列/非第一层分句间误用分号；含句号的分项仍用分号 | 改逗号 / 改句号 |
| 冒号 | §4 + §A.6 | 无停顿处用冒号；非提示性话语后误用 | 删冒号或改逗号 |
| 引号 | §4 + §A.7 + §B.2.1 | 内外标点位置错误；嵌套反序；段尾漏后引号 | 移标点至正确位置 / 换嵌套顺序 / 补后引号 |
| 破折号 | §4 + §B.1.7 + §B.2.3 | 断开分行；普通注释误用（应为括号） | 合并至同行 / 改为括号 |
| 省略号 | §4 + §A.9 + §B.2.4 | 与"等""等等"同时使用；超量叠用；断开分行 | 删省略号保留"等" / 缩减至标准 / 合并至同行 |
| 书名号 | §4 + §A.13 | 非作品名称套用；嵌套反序 | 改引号 / 换嵌套顺序 |
| 括号 | §4 + §A.8 + §B.2.2 | 句内括号未紧跟被注释词；行末多余标点 | 移至正确位置 / 删多余标点 |
| 连接号 | §4 + §A.11 | 数值范围误用短横；行首出现 | 改浪纹线 / 移至上行末 |
| 间隔号 | §4 + §A.12 | "和"连接标题中仍用间隔号 | 删间隔号 |
| 分隔号 | §4 + §A.14 | 前后多余点号 | 删多余点号 |
| **横排位置** | §5 | 行首出现句内点号；行末出现前引号/前括号；破折号/省略号分行断开 | 点号移上行末 / 符号移下行首 / 合并同行 |

#### 1.2 自动修正执行方式

对文本逐句扫描，发现违规后立即执行修正并记录修正日志：

```
🔧 标点自动修正日志：
  L3: "他推开门——" [破折号断开] → 已合并同行
  L7: "……等等" [省略号与"等"同用] → 已删省略号
  L12: "这是巧合还是有意安排？" [选择问句中位→逗号] → "？"改为"，"
  L15: "你知道吗？？？" [问号叠用超三个] → 缩减为"你知道吗？"
  L20: ""你好。"他说道。"好久不见。"" [引号嵌套反序] → 修正为'你好。'他说道。"好久不见。"
```

修正后立即对该句做复查确认修正成功。

#### 1.3 仅警告不修改的项（上下文无法判定时）

以下情况不做自动修正，仅在报告中标注供上游参考：

| 情形 | 原因 |
|------|------|
| 破折号与括号用途边界模糊 | 取决于作者意图（重要补充→破折号连读 / 普通注释→括号） |
| 分号/逗号在复杂多重复句中的选择 | 取决于作者对分句层次的判断 |
| 书名号与引号对"题"类短语的适用 | 取决于是否视为作品名 |

### 步骤 2：正文文本校验 — 段落/字句结构合规性（Core 规范）

**仅 `type = "prose"` 时执行。其他类型跳过此步骤。**

读取 `body/Core/SKILL.md` 中的写作规范，对成品文本进行结构性校验。**所有违规自动修正至合规状态**。

**校验前先读取步骤 0 输入数据包中的 `exempted_norms`**：如包含 `"规范2.2"` 则跳过 2.1.7（贴标签式性格描写）。`"规范2"`（人物外观间接描写）在 Proofreading 检查项中无直接对应子项，不产生跳过效果。2.1.8（参考源原文复刻）属规范 5，永不免除。2.1.6（破折号禁令）属规范 1.6，永不免除。其余规范照常过检。

#### 2.1 校验项与自动修正规则

**`prose_mode` 感知**：校验前读取数据包中的 `prose_mode`。若为 `"outline"`，规范 1 项下的 2.1.1~2.1.5 全部跳过（类比规范 1.5 大纲类特殊处理），仅执行 2.1.6 和 2.1.7。

##### 2.1.1 段落长度超标（规范 1 — `prose_mode = "narrative"` 时执行）

**检验**：段落中完整自然句（以。！？… 收尾）超过 3 个 → 违规。

**自动修正**：在最佳拆分点将长段一分为二。
- 拆分点优先选择：句号之后 > 问号之后 > 叹号之后
- 如段落超过 5 个完整自然句 → 拆分为 2~3 段，每段 ≤3 句
- 拆分后检查：新段落的第一句是否仍能独立成意 → 如太短（≤5字）则并入下一段

```
修正前：
  她走进房间。窗帘紧拉着。光线昏暗。空气里浮着一层薄灰。她打开灯。然后看到了桌上的信。

修正后：
  她走进房间。窗帘紧拉着，光线昏暗，空气里浮着一层薄灰。
  
  她打开灯，然后看到了桌上的信。
```

##### 2.1.2 句末标点链接（规范 1）

**检验**：短句/超短句/长句之间出现"X{标点}Y{标点}"的链式结构 → 违规。

**自动修正路径**：
- 句号链接 → 合并为逗号，或拆段（优先合并）
- 问号链接 → **强制拆段**，每句独立成段（保留追问感）
- 叹号链接 → **强制拆段**，每句独立成段（保留冲击力）
- 省略号链接 → 强制拆段
- 混合标点链接（？！）→ 强制拆段

```
修正前："这是什么？这怎么可能呢？为什么会这样呢？"
修正后：
  "这是什么？
  
  这怎么可能呢？
  
  为什么会这样呢？"

修正前："他做到了！他真的做到了！"
修正后：
  "他做到了！
  
  他真的做到了！"
```

##### 2.1.3 超短句堆叠（规范 1）

**检验**：超短句（≤5字）成段时出现连续 ≥2 个句末标点 → 违规。

**自动修正**：将连续超短句改为逗号相连（同一意群）或各自换行（非同一意群）。

```
修正前："跑了。追。没追上。算了。"
修正后："跑了，追，没追上——算了。"

修正前："他停下。回头。皱眉。没说话。"
修正后：
  "他停下，
  
  回头，
  
  皱眉。
  
  没说话。"
```

##### 2.1.4 无必要短句断裂（规范 1）

**检验**：同一意群被句号无理切断（三问判定法：同一件事？无转折？每句不独立？全中 → 违规）。

**自动修正**：将句号改为逗号合并为一个完整句。

```
修正前："你累了。回去休息吧。"
修正后："你累了，回去休息吧。"

修正前："我知道。你不会来的。所以我没有等。"
修正后："我知道你不会来的——所以我没有等。"
```

##### 2.1.5 对话叙述被句号截断（规范 1 衍生）

**检验**：对话+叙述+对话的"三明治"结构中，中间叙述以句号结尾 → 违规。

**自动修正**：将句号改为逗号。

```
修正前："教宗大人。"丽丽没有收剑。"我只是想问一个问题。"
修正后："教宗大人。"丽丽没有收剑，"我只是想问一个问题。"
```

##### 2.1.6 破折号禁令（规范 1.6 — 全技能不免）

**检验**：文本中出现 `——`（U+2014 U+2014）且不属于声音延长等允许例外 → 违规。

**全技能不豁免**：此规则不进入 `exempted_norms` 列表，NSFW 返回的任何豁免声明对此规则无效。无论 `prose_mode` 为何值均强制执行。

**自动修正**：检测到 `——` 后判定上下文：
- 解释/转折/插入 → 替换为逗号
- 停顿/犹豫/中断 → 替换为省略号
- 强调 → 拆分为独立短句
- 声音延长（前后为感叹词如"啊""呜""嗯"、拟声词、或对话中拖长音）→ 保留
- 无法判定用途 → 默认替换为逗号，标记 `[⚠️ 需人工：破折号用途不明，已默认替换为逗号]`

```
修正前："他提到了那个人——他的父亲"
修正后："他提到了那个人，他的父亲"

修正前："我——我不知道"
修正后："我……我不知道"

修正前："救命啊——"声音在山谷里拖了很长
修正后：保留（声音延长，合法例外）
```

##### 2.1.7 贴标签式性格描写（规范 2.2）

**检验**：初登场文本中出现叙述者直接贴性格标签（"他是XX的人""她看起来XX"）→ 违规。

**自动修正**：将标签句改写为行为展现。如标签句无法确定对应的行为替代，标记 `[⚠️ 需人工: 性格标签→行为展现]` 向用户说明。

```
修正前："他是个莽撞冒失的人。"
修正后："他一头撞开门冲进来，才发现走错了教室——满屋子的人转头看他，他挠挠头，又撞上了门框。"
```

> 如上下文不足以推断合适的替代行为，标注 `[⚠️ 需人工]` 保留原文并提示用户。

##### 2.1.8 参考源原文复刻（规范 5）

**检验**：段落中出现与任何参考源（大纲/角色文件/设定文件/Prompt.md）中原文高度重合的描述 → 违规。

**自动修正**：无法自动修正（需要创作级替换）。标记 `[⚠️ 降重提醒: 以下段落与参考源原文高度重合，建议换感官/换语境重写]` 并列出重合段落和对应参考源出处，由上游技能最终处理。

```
⚠️ 降重提醒：
  段落 2："B罩杯，底盘紧致，乳峰挺翘"
  → 与角色文件（`主要角色.md` / `次要角色.md` / `龙套角色.md`）中「林婉儿」条目原文高度重合
  → 建议：换触觉/互动角度重写（如"他解开时指尖擦过一处——刚好盈满"）

⚠️ 降重提醒：
  段落 1："西城窄巷，天色将暗，巷口灯笼初亮，光线昏暗逼仄。"
  → 与 Prompt.md（第5章）提示词原文高度重合
  → 建议：换时间/天气/感官角度重写，提示词是写作指引不是正文底稿
```

#### 2.2 自动修正执行流程

```
待校验文本
    │
    ▼
逐段扫描 ──→ 发现违规段 → 执行对应修正规则 → 写出修正后文本
    │
    ▼
全篇修正完成 → 生成修正日志
```

#### 2.3 输出结构修正报告

```
📋 段落/字句结构修正报告

🔍 扫描范围：{N} 段落，{N} 自然句

🔧 自动修正：
  • L5：段落长度超标（5个完整句）→ 拆分为2段
  • L8："这是什么？这怎么可能呢？"问号链接 → 逐句拆段
  • L12："跑了。追。没追上。"超短句堆叠 → 逗号合并
  • L18：对话叙述句号截断 → 改逗号
```

### 步骤 3：JSON 文件校验

**仅 `type = "json"` 时执行。其他类型跳过此步骤。**

#### 3.1 JSON 语法有效性

- 解析 JSON 字符串 → 解析失败则标记具体错误行/位置并自动修复（补逗号、补引号、删尾逗号等常见错误）
- 修复后重新解析确认

#### 3.2 模式校验（按 expected_schema）

**Prompt.md 模式**：

> Prompt.md 为 Markdown 文件，不进入 JSON 校验流程。提示词增强技能以 `type: "prose"` + `prose_mode: "outline"` 将其传入此技能，走步骤 1（CPS 标点）+ 步骤 2（Core 结构）校验后落盘。Prompt.md 中的提示词文本与大纲类文本共享规范 1.5 段落豁免，破折号禁令（规范 1.6）正常执行。

**项目信息.json 模式**：

| 校验项 | 规则 | 违规处理 |
|--------|------|---------|
| 必填字段 | `content_rating`、`volumes` 必须存在 | 标记缺失字段 |
| `content_rating` | 必须为 `一般向` 或 `NSFW` | 自动修正 |
| `volumes.enabled` | 必须为 boolean | 自动修正 |
| 卷号连续性 | `volumes.list[].id` 必须连续递增 | 标记不连续处 |

**润色配置.json 模式**：

| 校验项 | 规则 | 违规处理 |
|--------|------|---------|
| `正文.polish_mode` | 必须为 `轻度`/`中度`/`重度` | 自动修正为 `中度` |
| `大纲.polish_mode` | 必须为 `轻度`/`中度`/`重度` | 自动修正为 `轻度` |
| `分卷` 覆盖 | key 必须对应 `项目信息.json` 中存在的卷号 | 标记孤立卷覆盖 |

#### 3.3 引用一致性校验

对 JSON 中的跨文件引用做一致性检查：

| 检查项 | 校验方式 | 违规处理 |
|--------|---------|---------|
| Prompt.md 中的章名 | 对比 `剧情大纲.md` 中是否存在对应章节 | 标记不存在于大纲中的章 |
| 润色配置中的分卷覆盖 | 对比 `项目信息.json` → `volumes.list` | 标记不存在卷号的覆盖项 |
| 项目信息中的伏笔引用章号 | 对比大纲中章号范围 | 标记超出范围的章号引用 |

```
  • 章名"初入江湖"在第3条和第7条重复 → 已保留最新，移除旧条目

  • Prompt.md 第5章引用的章名"夜探禁地"在大纲中不存在 → ⚠️ 需人工确认

✅ JSON 校验完成（{N}处修正，{M}处需确认）
```

### 步骤 4：结构化 Markdown 校验

**仅 `type = "structured_md"` 时执行。其他类型跳过此步骤。**

#### 4.0 纯文本内容合规校验（所有 md_category 共用）

> 结构化 MD 文件（角色/设定/大纲）中同样包含大量叙述性文本——角色简介、设定描述、剧情梗概等。这些文本的标点和结构合规性直接影响后续技能的读取准确性，必须经与正文相同的双轨校验。

在分类字段校验之前，先将结构化 MD 的**全部文本内容**视为 `type: "prose"` + `prose_mode: "outline"` 执行步骤 1（CPS.json 标点扫描）和步骤 2（Core 结构规范扫描）：

| 校验层 | 执行内容 | 说明 |
|--------|---------|------|
| 标点合规 | 全量 CPS.json 逐句扫描 | 与正文步骤 1 完全一致——标点错误同样影响参考源可读性 |
| 段落节奏 | 免检 | `prose_mode: "outline"` → 适用规范 1.5，允许长段叙述、分号分隔 |
| 间接描写 | 规范 2 / 2.2（贴标签式描写、性格间接化） | **角色文件豁免**——角色文件本身就是参考数据源，允许直接陈述特征；设定和大纲文件中若包含示例描写语句仍需遵守 |
| 降重率 | 规范 5（禁止原文复刻） | 全类别执行——结构化 MD 中的描述语句不得大段照搬其他参考源原文 |

**修正方式**：标点违规自动修正后写回文本；结构违规自动修正；需人工项标记后阻断落盘。

#### 4.1 角色 Markdown 分类校验（`md_category = "角色"`）

| 校验项 | 规则 | 违规处理 |
|--------|------|---------|
| 角色名 | 必须为非空标题 | 标记 |
| 性别/年龄 | 应有明确字段 | 标记缺失 |
| 性格描述 | 允许"行为展现"或"标签式"（角色文件为参考数据，非正文，不强制间接化） | 不干预 |
| 与其他角色的关系 | 如提及另一角色名，对方文件中应有对应关系条目 | 标记单向关系 |
| 分卷目录存在性 | 如引用 `大纲/人物/卷{N}/`，确认对应卷目录存在 | 标记不存在目录 |

#### 4.2 设定 Markdown 校验（`md_category = "设定"`）

| 校验项 | 规则 | 违规处理 |
|--------|------|---------|
| 章节结构 | 应有明确的小标题分段 | 标记无结构文件 |
| 世界观规则 | 同一概念在不同段落中定义一致 | 标记矛盾定义 |
| 引用章节号 | 如设定引用"第X章揭示"，该章号应在大纲中存在 | 标记无效引用 |

#### 4.3 大纲 Markdown 校验（`md_category = "大纲"`）

| 校验项 | 规则 | 违规处理 |
|--------|------|---------|
| 章节编号连续性 | 章号从 1 开始连续递增，无跳号 | 标记跳号位置 |
| 卷章对应 | 分卷模式下各卷 `chapter_range` 与实际章号范围一致 | 标记不一致 |
| 每章必有描述 | 每章不可为空描述 | 标记空章 |
| 跨卷引用 | 章内提及"参见前文第X章"，确认 X 存在 | 标记无效引用 |

#### 4.4 结构化 MD 校验报告

```
🔍 文件类别：角色 / 主要角色

🔧 字段完整性：
  • "林婉儿"缺失年龄字段 → ⚠️ 已标记
  • "张三"与"李四"的关系标注为"好友"，但李四文件中未提及张三 → ⚠️ 已标记单向关系

✅ 结构化 MD 校验完成（{N}处标记）
```

### 步骤 5：复检确认

所有校验轮次完成后，对修正后的内容再做一次快速扫描，确认所有违规已消除：

1. **正文文本**：标点逐句检查 + 结构逐段检查，确认无新引入错误
2. **JSON**：重新解析确认语法有效 + 模式字段完整
3. **结构化 MD**：重新确认标记项已正确标注；确认 4.0 纯文本校验的修正未引入新的标点/结构违规

如发现修正引入的新问题 → 对该处再次修正后重检。
复检通过则进入步骤 6。

### 步骤 6：落盘写入

所有校验通过后，**由此技能将修正后的内容写入 `file_path` 指定的目标路径**。上游技能不持有文件写入权限——它们只是内容生产者，此技能是唯一的落盘执行者。

**写入流程**：

1. 确认目标目录存在（如 `正文/`、`正文/卷{N}/`、`大纲/剧情/` 等）→ 不存在则自动创建
2. 将修正后的最终内容写入 `file_path`
3. 输出校验摘要确认落盘成功：

```
✅ 成品输出校验完成 → 已落盘

📁 {file_path}
📊 校验摘要：
  • 文件类型：{正文文本 / JSON / 结构化MD}
  • 标点修正：{N} 处（仅正文文本）
  • 结构修正：{N} 处（仅正文文本）
  • JSON 修正：{N} 处（仅 JSON）
  • 字段/引用标记：{N} 处（JSON + 结构化MD）
  ⚠️ 需人工确认：{N} 项

━━━━━━━━━━━━━━━━━━━━
{落盘内容全文}
━━━━━━━━━━━━━━━━━━━━
```

**⚠️ 落盘前阻断条件**：如存在 `⚠️ 需人工确认` 项（降重提醒、引用不一致等），在落盘前向用户展示标记项并询问是否继续写入。用户确认后执行落盘；用户拒绝则退回上游技能修改。

## 与上游技能的协作

```
上游技能处理完毕，准备写入文件
  │  携带：{type, content, file_path, ...}
  │  ⚠️ 上游技能不自行写入——仅传递数据包
  ▼
成品输出校验（此技能）—— 唯一落盘入口
    │  步骤 0：接收 → 识别文件类型 → 路由校验策略
    │
    ├── type = "prose" ──→ 第一轮：CPS.json 标点扫描 → 自动修正 → 复检
    │                └── 第二轮：Core 规范结构扫描 → 跳过 exempted_norms → 自动修正 → 复检
    │
    ├── type = "json" ──→ 第三步：语法有效性 + 模式校验 + 引用一致性
    │
    ├── type = "structured_md" ──→ 第四步：字段完整性 + 跨文件引用有效性
    │
    ├── 步骤 5：复检确认
    │
    └── 步骤 6：落盘写入 → 输出校验摘要
            │
            ├── 无阻断项 → 直接写入 file_path
            └── 有 ⚠️ 需人工确认 → 询问用户 → 确认后写入 / 拒绝则退回上游
```

**关键原则**：
- 此技能是系统的**唯一落盘入口**——没有任何技能可以 bypass 它直接写文件
- 此技能自闭环——所有可自动修正的违规在此技能内部修正完毕，不退回上游
- 不可自动修正的项（降重提醒、引用不一致等）标记为 `⚠️ 需人工确认`，阻断落盘直到用户确认
- 上游技能是**内容生产者**，此技能是**校验者 + 落盘执行者**——职责严格分离

**NSFW 校验边界**：
- NSFW 技能负责：档位色色值合规、白描篇幅控制、精神思考比例、NSFW 降重率
- 此技能负责：标点合规（CPS.json）+ Core 通用结构（段落节奏/对话增强/风景穿插/通用降重率）+ JSON/结构化MD 完整性
- 规范 2/2.2 已由 NSFW 豁免并通过 `exempted_norms` 传递——此技能跳过

## 注意事项

- **硬约束：不经此技能，不得落盘**。任何技能绕过此技能直接将内容写入文件系统 = 流程违规。唯一的例外是此技能自身执行校验后的落盘操作
- 文件类型判定优先看 `type` 字段，其次看 `file_path` 扩展名
- 正文文本的两轮校验独立运行，不可跳过任何一轮
- JSON 校验中语法错误自动修复，模式违规自动修正，引用不一致标记需人工
- 结构化 MD 校验中字段缺失仅标记不自动填充（数据源在上游技能）
- 标点修正仅改标点，不改词汇；结构修正可改段落/句子边界，不改叙事内容
- 修正后必须复检一次确认无新问题
- CPS.json 是本技能同目录下的标点权威数据源
- 如输入数据包中 `exempted_norms` 非空，正文结构校验跳过其中列出的规范项；标点校验和 JSON/MD校验不受豁免影响
- **NSFW 校验边界**：此技能不负责 NSFW 专项校验——NSFW 技能步骤 4 已自行完成
- 分卷多文件项目：`volume` 字段用于跨文件引用校验中的卷号定位
- 始终以 Markdown 格式输出校验报告和最终成品
- 所有修正动作均记录日志，确保可追溯
- **不再仅校验正文**：任何写入 `正文/`、`番外/`、`大纲/`、`outline/` 目录及其子目录的文件，均纳入校验范围
