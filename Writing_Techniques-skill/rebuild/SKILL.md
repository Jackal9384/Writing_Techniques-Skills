# 快速重建

此技能将用户已有的小说、文学创作文件（集）按 **Writing Techniques (WT)** 规范标准化，自动识别数据、归类并写入对应的 WT 项目文件中。

## 执行模式：计划模式

**调用此技能后，必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出：
   - 已识别的素材来源（文件路径/粘贴内容）
   - 识别到的数据类型和数量（人物 X 个、设定项 X 条、剧情线索 X 条）
   - 将调度的 WT 技能列表和执行顺序
   - 标记出的缺失项和模糊项（需用户确认）
3. 等待用户批准计划后执行
4. **严禁**在计划未被批准前开始任何数据写入

## 触发条件

当用户表达以下意图时，立即调用此技能：
- "我有现成的设定，帮我整理一下"、"把XX规范化"
- "导入旧小说"、"把我之前的设定迁移过来"
- "这个文档里有角色信息，帮我提取"
- "把这段文字按WT规范整理"
- 任何表达"用现有资料/已有设定进行重建"的类似表述

## 核心原则

### 原则一：严审模糊项，绝不擅自做主

- **可明确识别的数据** → 直接归类并标注来源
- **模糊/不确定的数据** → 列出所有可能的解读，**询问用户**，等用户确认后再归类
- **缺少的必填项** → 标记为「缺失」，逐一询问用户补充
- **候选匹配**（如识别到一个可能是"角色名"的词，但不确定）→ 列出候选并让用户确认

### 原则二：数据来源可追溯

每个写入的数据项都标注来源，格式：`[来源：{文件名/用户输入}]`

### 原则三：调用而非重复

此技能**不亲自写入文件**，而是调度其他 WT 技能完成：
- `创建新书` — 建立项目结构（如尚未创建）
- `创建人物` — 写入识别到的人物数据
- `设定编辑` — 写入识别到的设定数据
- `剧情编辑` — 写入识别到的剧情数据
- `基础写作辅助` — 对识别到的正文内容进行润色

## 数据识别规则

### 人物数据识别

扫描输入内容，匹配以下模式：

| 模式 | 识别方式 | 映射字段 |
|------|---------|---------|
| 名称 + 性别 | "张三，男" / "Female: Alice" | 人物名称、性别 |
| 年龄/出生 | "25岁" / "生于XX年" / "年龄：XX" | 年龄/出生日期 |
| 身高体重 | "180cm" / "XXkg" / "身材高大" | 身高/体重/身形特点 |
| 性格描述 | "性格开朗" / "他沉默寡言" / "性格：XX" | 人物性格 |
| 背景故事 | 段落级描述，通常以角色名为中心 | 人物简介 |
| 关系表达 | "A是B的XX" / "A与B：XX关系" | 人物基本关系 |
| 能力描述 | "擅长XX" / "战斗力X" / "精通XX" | 人物能力 |

**识别后处理：**
1. 对每个识别到的角色，列出所有已提取的字段
2. 标记「已提取」「模糊」「缺失」三种状态
3. 模糊项 → 询问用户；缺失必填项 → 询问用户
4. 用户确认后，调用 `创建人物` 技能逐个写入

### 设定数据识别

扫描输入内容，匹配以下模式：

| 模式 | 识别方式 | 映射区块 |
|------|---------|---------|
| 世界观描述 | "这个世界……" / 背景设定段落 | 世界观设定 |
| 核心规则 | "XX的规则是……" / "在这个世界中XX" | 核心设定 |
| 其他设定 | 不属于以上两类的设定项 | 其他设定 |
| 基本信息 | 书名、作者、类型等元数据 | 项目信息 |

**识别后处理：**
1. 将识别到的设定项归类到对应区块
2. 有冲突的设定 → 列出给用户确认
3. 调用 `设定编辑` 写入

### 剧情数据识别

扫描输入内容，匹配以下模式：

| 模式 | 识别方式 | 映射区块 |
|------|---------|---------|
| 章节标记 | "第X章" / "Chapter X" / "一、" | 剧情大纲 |
| 时间线索 | "XX年后" / "第二天" / "公元XX年" | 剧情大纲 |
| 情节描述 | 事件叙述段落 | 剧情细纲 |
| 分卷标记 | "第一部" / "卷X" / "上篇" | 分卷结构 |

**识别后处理：**
1. 按时间/章节顺序组织剧情点
2. 调用 `剧情编辑` 写入

### 正文内容识别

- 识别到的正文/章节正文内容 → 标记但不自动处理
- 询问用户是否要导入正文（如需要则调用 `基础写作辅助`）

## 执行步骤

### 步骤 1：接收并解析输入

接收用户提供的素材：
- **文件输入**：支持 `.md`、`.txt` 格式，读取全部内容
- **文字输入**：用户直接粘贴/口述的内容
- **多文件**：如有多个文件，逐一读取并标注来源

### 步骤 2：数据扫描与归类

对输入内容执行全量扫描，生成识别报告：

```
📊 数据扫描报告

📁 来源：{文件名/用户输入}（共 {N} 字符）

👤 人物识别：
  已确认 {X} 个：张三、李四……
  待确认 {Y} 个：候选名称A（可能是角色名/地名/其他？）

📐 设定识别：
  已确认 {X} 条：世界观描述（3段）、核心规则（2条）、……

📖 剧情识别：
  已确认 {X} 条：章节标记（5个）、情节描述（12段）、……

📝 正文识别：
  已确认 {X} 段正文内容

⚠️ 模糊项：{N} 个需要用户确认
❌ 缺失项：{N} 个必填字段缺失
```

### 步骤 3：逐项确认模糊项与缺失项

**严格审查规则：**

对每个模糊项，输出候选列表让用户选择或自填：
```
⚠️ 「{原文片段}」无法确定归类，有可能是：
  1. 人物名称 → 创建为该角色
  2. 地名/组织名 → 归类到设定
  3. 都不是 → 忽略
  请选择：
```

对每个缺失项（必填字段），明确询问：
```
❌ 角色「{名称}」缺少「{字段}」，请补充：
  （输入值 / "跳过" / "设为未知"）
```

**严禁**：
- 猜测模糊数据的正确归类
- 为缺失必填项编造默认值
- 在用户未确认前就开始写入

### 步骤 4：建立 WT 项目结构

如当前工作目录下尚无 WT 项目：
1. 询问书名（如能从输入中提取则展示候选）
2. 调用 `创建新书` 技能，建立完整项目结构
3. 如已有项目则跳过

### 步骤 5：调度 WT 技能批量写入

用户确认所有识别结果后，按以下顺序调度：

1. **设定数据** → 调用 `设定编辑`，先写入世界观/核心/其他设定
2. **人物数据** → 调用 `创建人物`，逐个写入角色（含自动双向关系同步）
3. **剧情数据** → 调用 `剧情编辑`，写入章节/分卷结构
4. **正文数据**（可选）→ 调用 `基础写作辅助`，写入 `正文/` 目录

每完成一项，输出进度：
```
🔄 重建进度：{已完成}/{总任务}
  ✅ 设定：已写入 {N} 条
  ✅ 人物：已创建 {N} 个角色
  ⏳ 剧情：处理中……
  ⏸ 正文：待用户确认
```

### 步骤 6：输出重建报告

```
✅ 快速重建完成！

📊 重建报告：
  📁 项目：{书名}
  👤 人物：{N} 个（主要 {X}、次要 {Y}、龙套 {Z}）
  📐 设定：{N} 条（世界观 {X}、核心 {Y}、其他 {Z}）
  📖 剧情：{N} 章/{X} 卷
  📝 正文：{N} 段（已导入/未导入）

⚠️ 未处理项：
  • {模糊项N个} — 用户选择跳过
  • {缺失项N个} — 待后续补充

📝 下一步建议：
  • 补充缺失的人物字段 — 说"编辑人物"
  • 完善剧情细化 — 说"编辑剧情"
  • 开始正文写作 — 说"写正文"
```

## 注意事项

- **严格审查是最核心的原则**，宁可不处理也不擅自猜测
- 如果输入包含大量无法确认的模糊数据（>30%），建议用户先手动整理后再重建
- 输入来源一一标注，确保重建结果可追溯
- 如果输入中已有与 WT 规范冲突的内容，标注冲突并让用户决定如何处理
- 对于特别长的输入（>50000字），分批次处理，每批处理完后汇报进度
- 调度其他技能时使用计划模式，避免一次调用写入过多数据
