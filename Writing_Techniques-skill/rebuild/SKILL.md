# 快速创建

此技能提供**双模式**帮助用户快速建立或重建书籍项目：

| 模式 | 适用人群 | 流程特点 |
|------|---------|---------|
| **手动模式** | 有经验的用户、有明确已有设定 | 逐项确认数据，精确控制每个细节 |
| **自动模式** | 新手用户、快速试写小玩意 | 一次性描述需求，LLM自动推断并执行完整流程 |

## 关联文件

此技能调度其他 WT 技能完成写入，本身不直接操作文件。

| 文件 | 位置 | 用途 | 经由技能 |
|------|------|------|---------|
| `项目信息.json` | `大纲/` | 项目基本信息 + NSFW 偏好 | 创建新书 |
| `润色配置.json` | `大纲/` | 润色模式 | 创建新书 |
| `设定.md` | `大纲/设定/` | 世界观/核心/其他设定 | 设定编辑 |
| `人物存档.md` | `大纲/人物/` | 人物数据 | 创建人物 |
| `剧情大纲.md` | `大纲/剧情/` | 剧情阶段/分卷大纲 | 剧情编辑 |

## 执行模式：计划模式

**调用此技能后，必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出执行方案（含模式选择）
3. 等待用户批准计划后执行
4. **严禁**在计划未被批准前开始任何数据写入或文件夹创建

## 触发条件

当用户表达以下意图时，立即调用此技能：

- "快速创建"、"快速重建"、"帮我快速创建一本书"
- "整理已有设定"、"把XX规范化"、"导入旧小说"、"迁移旧作"
- "我有现成的设定，帮我整理一下"
- "这个文档里有角色信息，帮我提取"
- "把这段文字按WT规范整理"
- 用户**直接粘贴/上传作品设定类内容**且前文中无其他已处理的指令
- 任何表达"用现有资料/已有设定进行重建"或"快速创建一本书"的类似表述

## 入口分流：智能检测

进入此技能后，首先检测用户输入的上下文场景。

### 场景A：用户提供了作品设定内容（粘贴/文件上传）

当用户消息中包含了类似作品设定的内容（如角色描述、世界观、剧情想法、人物列表等），且**前文与提示词中没有其他任何东西**（即无其他已处理的指令、无正在进行的任务）时：

```
📋 检测到您提供了作品相关的内容，是否使用此信息进行快速创建？

  • 是 — 进入快速创建流程
  • 否 — 忽略，返回常规对话
```

- 用户选「否」→ 退出此技能，返回常规对话
- 用户选「是」→ 进入**创建模式选择**

### 场景B：用户直接调用技能（无附带内容）

用户说"快速创建"、"快速重建"等触发词但没有附带任何设定内容：

```
📋 快速创建 — 请选择输入方式：

  • 粘贴/上传已有设定 — 我已有角色、世界观等设定内容
  • 直接描述需求 — 我想快速创建一本新书，手动或自动均可
```

- 选择「粘贴/上传」→ 等待用户提供内容后，进入场景A流程
- 选择「直接描述需求」→ 直接进入**创建模式选择**

# 自动模式

## 概述

自动模式面向**新手用户**或**只想快速写一些小玩意的用户**——用户一次性描述创作需求（至少2项），LLM 自动提取、推断、补全信息，并按顺序自动执行：创建项目结构 → 创建人物 → 写入设定 → 生成剧情大纲。**全流程不再询问用户。**

## 需求收集

进入自动模式后，向用户一次性展示以下提示：

```
🚀 自动创建模式 — 请一次性描述您的创作需求：

  • 有几个角色？（如：主角1个男、配角1个女、龙套若干）
  • 作品类型？（如：玄幻、科幻、言情、悬疑、同人、轻小说 等）
  • 篇幅长度？（如：随笔、短篇、中篇、长篇）
  • 世界观的基础设定？（如：修仙世界、现代都市、末日废土、魔法学院 等）
  • 希望怎么写？（如：轻松日常、热血战斗、悬疑推理、甜宠恋爱 等风格方向）
  • 其他补充？（任何你想补充的内容——书名、具体角色名、剧情走向等）

💡 均为可选项，但**至少填充2项**以上即可开始。
   也可以直接粘贴一段描述性文字（≥50字），由 AI 自行提取信息。
```

### 最少2项约束

- 用户至少需填写2个字段（或提供一段 ≥50 字的描述性文字）
- 如不足2项，提示：
  ```
  ⚠️ 信息太少啦，至少再补充1项吧～比如：作品类型？世界观？人物数量？随便说说就行！
  ```
- 用户补充后继续

## 自动执行流程

用户提供需求后，LLM 按以下顺序**自动执行全流程，不再询问用户任何问题**。

### A1. 解析用户描述

从用户输入中提取所有可识别信息：

| 可提取信息 | 映射目标 | 处理方式 |
|-----------|---------|---------|
| 角色数量、性别、名称、性格简述 | 人物创建 | 明确→直接使用；模糊→LLM推断 |
| 作品类型/种类 | `项目信息.json` → `genre` | 直接使用 |
| 篇幅长度 | `项目信息.json` → `length` | 直接使用 |
| 世界观描述 | `设定.md` → 世界观 | 提取 + LLM补全 |
| 写作风格/方向 | `设定.md` → 核心设定 | 提取 + 推断 |
| 书名 | `项目信息.json` → `book_name` | 有→使用；无→自动生成 |
| 剧情走向 | `剧情大纲.md` → 梗概 | 提取 + LLM推断 |

**自动模式推断原则（与手动模式不同）：**
- 能明确识别的 → 直接使用
- 模糊但有线索的 → LLM 根据上下文合理推断
- 完全缺失的 → LLM 根据已有信息自动生成合理默认值
- **不询问用户确认**，事后由用户自行查看调整

### A2. 自动创建项目结构

调度「创建新书」技能（`outline/SKILL.md`），但**跳过所有交互询问**，LLM 直接决策：

| 决策项 | 默认策略 |
|--------|---------|
| 书名 | 用户提供→使用；否则从世界观/类型中自动生成（如"异界修仙录"） |
| 传播范围 | 默认「个人向」 |
| 润色模式 | 默认「中度」 |
| 路径语言 | 默认中文 |
| 内容分级 | 检测到NSFW关键词→`NSFW`；否则→`一般向` |
| 文件夹命名 | 默认中文路径（大纲/番外/正文） |

直接创建完整项目结构并生成 `项目信息.json`、`润色配置.json`、`设定.md`。

### A3. 自动创建人物

调度「创建人物」技能（`outline/characters/SKILL.md`），批量创建识别到的所有角色：

- **用户明确描述了角色**（名称、性别、性格等）→ 提取填写对应字段，缺失字段LLM合理补全
- **用户只说了数量**（如"3个角色"）→ LLM 根据作品类型/世界观自动生成角色
- **用户未提及角色** → LLM 根据作品类型自动生成 2-3 个核心角色（至少1主1配）
- 优先级分配：明确描述的角色 → 主要角色；自动生成的 → 次要角色
- 人物关系：如有描述则提取，否则LLM根据角色定位自动生成基本关系

### A4. 自动写入设定

调度「设定编辑」技能（`outline/settings/SKILL.md`），自动填充 `设定.md`：

- **基本信息**：从 A2 的项目信息中直接获取
- **核心设定**：从用户描述提取人物/世界/故事走向；缺失部分 LLM 补全
- **世界观**：从用户描述提取分类项（如"魔法体系"、"地理格局"）；用户未提及但类型需要的 → LLM 自动生成1-2个基础分类项
- **简介**：LLM 自动生成对外简介（50-100字）和个人描述

### A5. 自动生成剧情大纲

调度「剧情编辑」技能（`outline/plot/SKILL.md`），生成初始框架：

- **模板选择**：长篇→连载模板（5阶段）；其他→非连载模板（4阶段）
- **梗概**：LLM 根据书名、种类、篇幅、人物、世界观自动生成散文式梗概
- **阶段规划**：LLM 按默认占比自动分配章节范围，每阶段填充 2-4 个关键剧情点
- **合规模式**：默认「标准」
- 不询问分卷（默认不分卷），用户后续可手动调整

### A6. 输出完整项目摘要

全部执行完毕后，输出：

```
✅ 快速创建完成！

📁 项目：「{书名}」
   {项目路径}

📋 项目概要：
  • 类型：{种类}  • 篇幅：{长度}  • 分级：{一般向/NSFW}
  • 人物：{N} 个（主要 {X}、次要 {Y}）
  • 剧情阶段：{N} 个  • 润色模式：中度

📝 已自动生成：
  ✅ 项目结构（大纲/番外/正文）
  ✅ 人物存档 → 大纲/人物/人物存档.md（{N}个角色）
  ✅ 作品设定 → 大纲/设定/设定.md（世界观 + 核心设定）
  ✅ 剧情大纲 → 大纲/剧情/剧情大纲.md（{N}阶段框架）

💡 自动创建的内容为 AI 推断生成，建议查看并按需调整：
  • 查看/修改人物 — 说"编辑人物"
  • 完善世界观设定 — 说"编辑设定"
  • 细化剧情大纲 — 说"编辑剧情"
  • 开始正文写作 — 说"写正文"
```

### 自动模式结束后的处理

- 项目已完整创建，用户可立即开始写作或继续调整
- 如用户选择调整，正常调度对应子技能（手动交互模式）
- 如检测到 NSFW 内容分级，在摘要输出后**追加 NSFW 偏好配置提示**（与 `outline/SKILL.md` 步骤5.5 一致）

# 手动模式

手动模式延续原有流程，适用于有经验的用户或已有完整设定文件需要精确导入的场景。

## 手动模式核心原则

### 原则一：严审模糊项，绝不擅自做主

- **可明确识别的数据** → 直接归类并标注来源
- **模糊/不确定的数据** → 列出所有可能的解读，**询问用户**，等用户确认后再归类
- **缺少的必填项** → 标记为「缺失」，逐一询问用户补充
- **候选匹配**（如识别到一个可能是"角色名"的词，但不确定）→ 列出候选并让用户确认

### 原则二：数据来源可追溯

每个写入的数据项都标注来源，格式：`[来源：{文件名/用户输入}]`

### 原则三：调用而非重复

此技能**不亲自写入文件**，而是调度其他 WT 技能完成：
- `创建新书` — 建立项目结构（如尚未创建）
- `创建人物` — 写入识别到的人物数据
- `设定编辑` — 写入识别到的设定数据
- `剧情编辑` — 写入识别到的剧情数据
- `基础写作辅助` — 对识别到的正文内容进行润色

## 手动模式数据识别规则

### 人物数据识别

扫描输入内容，匹配以下模式：

| 模式 | 识别方式 | 映射字段 |
|------|---------|---------|
| 名称 + 性别 | "张三，男" / "Female: Alice" | 人物名称、性别 |
| 年龄/出生 | "25岁" / "生于XX年" / "年龄：XX" | 年龄/出生日期 |
| 身高体重 | "180cm" / "XXkg" / "身材高大" | 身高/体重/身形特点 |
| 性格描述 | "性格开朗" / "他沉默寡言" / "性格：XX" | 人物性格 |
| 背景故事 | 段落级描述，通常以角色名为中心 | 人物简介 |
| 关系表达 | "A是B的XX" / "A与B：XX关系" | 人物基本关系 |
| 能力描述 | "擅长XX" / "战斗力X" / "精通XX" | 人物能力 |
| XP/性癖 | "XP：XX" / "性癖：XX" / "喜欢XX玩法" | XP（NSFW） |
| 三维 | "XX-XX-XX" / "三围：XX/XX/XX" / "BXX WXX HXX" | 三维（NSFW） |
| 性特征 | "性特征：XX" / "私处描述" / "床上特点" | 性特征（NSFW） |
| X能力 | "X能力：XX" / "耐力：X" / "攻击力：X" / "耐受力：X" | 人物X能力（NSFW） |

**识别后处理：**
1. 对每个识别到的角色，列出所有已提取的字段
2. 标记「已提取」「模糊」「缺失」三种状态
3. 模糊项 → 询问用户；缺失必填项 → 询问用户
4. 用户确认后，调用 `创建人物` 技能逐个写入

### 设定数据识别

扫描输入内容，匹配以下模式：

| 模式 | 识别方式 | 映射区块 |
|------|---------|---------|
| 世界观描述 | "这个世界……" / 背景设定段落 | 世界观设定 |
| 核心规则 | "XX的规则是……" / "在这个世界中XX" | 核心设定 |
| 其他设定 | 不属于以上两类的设定项 | 其他设定 |
| 基本信息 | 书名、作者、类型等元数据 | 项目信息 |

**识别后处理：**
1. 将识别到的设定项归类到对应区块
2. 有冲突的设定 → 列出给用户确认
3. 调用 `设定编辑` 写入

### 剧情数据识别

扫描输入内容，匹配以下模式：

| 模式 | 识别方式 | 映射区块 |
|------|---------|---------|
| 章节标记 | "第X章" / "Chapter X" / "一、" | 剧情大纲 |
| 时间线索 | "XX年后" / "第二天" / "公元XX年" | 剧情大纲 |
| 情节描述 | 事件叙述段落 | 剧情细纲 |
| 分卷标记 | "第一部" / "卷X" / "上篇" | 分卷结构 |

**识别后处理：**
1. 按时间/章节顺序组织剧情点
2. 调用 `剧情编辑` 写入

### 正文内容识别

- 识别到的正文/章节正文内容 → 标记但不自动处理
- 询问用户是否要导入正文（如需要则调用 `基础写作辅助`）

## 手动模式执行步骤

### 步骤 1：接收并解析输入

接收用户提供的素材：
- **文件输入**：支持 `.md`、`.txt` 格式，读取全部内容
- **文字输入**：用户直接粘贴/口述的内容
- **多文件**：如有多个文件，逐一读取并标注来源

### 步骤 2：数据扫描与归类

对输入内容执行全量扫描，生成识别报告：

```
📊 数据扫描报告

📁 来源：{文件名/用户输入}（共 {N} 字符）

👤 人物识别：
  已确认 {X} 个：张三、李四……
  待确认 {Y} 个：候选名称A（可能是角色名/地名/其他？）

📐 设定识别：
  已确认 {X} 条：世界观描述（3段）、核心规则（2条）、……

📖 剧情识别：
  已确认 {X} 条：章节标记（5个）、情节描述（12段）、……

📝 正文识别：
  已确认 {X} 段正文内容

⚠️ 模糊项：{N} 个需要用户确认
❌ 缺失项：{N} 个必填字段缺失
```

### 步骤 3：逐项确认模糊项与缺失项

**严格审查规则：**

对每个模糊项，输出候选列表让用户选择或自填：
```
⚠️ 「{原文片段}」无法确定归类，有可能是：
  1. 人物名称 → 创建为该角色
  2. 地名/组织名 → 归类到设定
  3. 都不是 → 忽略
  请选择：
```

对每个缺失项（必填字段），明确询问：
```
❌ 角色「{名称}」缺少「{字段}」，请补充：
  （输入值 / "跳过" / "设为未知"）
```

**严禁**：
- 猜测模糊数据的正确归类
- 为缺失必填项编造默认值
- 在用户未确认前就开始写入

### 步骤 4：建立 WT 项目结构

如当前工作目录下尚无 WT 项目：
1. 询问书名（如能从输入中提取则展示候选）
2. **NSFW 检测**：如扫描中识别到任何 NSFW 字段（XP/三维/性特征/X能力）或成人内容描述，设置 `content_rating` 为 `NSFW`——调用 `创建新书` 时传入此值，使项目自动触发 NSFW 偏好配置流程
3. 调用 `创建新书` 技能，建立完整项目结构
4. 如已有项目则跳过

### 步骤 5：调度 WT 技能批量写入

用户确认所有识别结果后，按以下顺序调度：

1. **设定数据** → 调用 `设定编辑`，先写入世界观/核心/其他设定
2. **人物数据** → 调用 `创建人物`，逐个写入角色（含自动双向关系同步）
3. **剧情数据** → 调用 `剧情编辑`，写入章节/分卷结构
4. **正文数据**（可选）→ 调用 `基础写作辅助`，写入 `正文/` 目录

每完成一项，输出进度：
```
🔄 重建进度：{已完成}/{总任务}
  ✅ 设定：已写入 {N} 条
  ✅ 人物：已创建 {N} 个角色
  ⏳ 剧情：处理中……
  ⏸ 正文：待用户确认
```

### 步骤 6：输出重建报告


## 注意事项

- **手动模式**：严格审查是最核心的原则，宁可不处理也不擅自猜测
- **自动模式**：LLM 可合理推断补全，但需在完成后明确提示用户查看调整
- 如果手动模式输入包含大量无法确认的模糊数据（>30%），建议用户先手动整理后再重建，或切换到自动模式
- 输入来源一一标注，确保重建结果可追溯
- 如果输入中已有与 WT 规范冲突的内容，标注冲突并让用户决定如何处理（手动模式）；自动模式则优先保留用户原意
- 对于特别长的输入（>50000字），分批次处理，每批处理完后汇报进度
- 调度其他技能时使用计划模式，避免一次调用写入过多数据
- **自动模式的路径**：默认在当前工作目录下以书名创建项目文件夹
