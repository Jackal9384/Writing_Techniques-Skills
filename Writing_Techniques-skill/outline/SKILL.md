# 创建新书

此技能用于创建一本新书的完整项目文件夹结构，收集书籍元数据，并自动生成项目设定文件。

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `项目信息.json` | `大纲/` | 项目基本信息（书名/篇幅/种类等），权威数据源 | 写入 |
| `润色配置.json` | `大纲/` | 润色模式持久化（大纲/正文双轨） | 写入 |
| `设定.md` | `大纲/设定/` | 项目设定初始骨架（世界观/核心/其他） | 写入 |

## 执行模式：计划模式

**调用此技能后，必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出将执行的步骤、将询问的问题、以及最终将生成的文件夹结构和设定文件
3. 等待用户批准计划后，再按计划逐步执行
4. 不要在进入计划模式前直接开始创建文件夹或询问用户问题

## 触发条件

当用户表达以下意图时，立即调用此技能：
- "创建新书"、"开新书"、"新建书籍"
- "写一本新书"、"开始写书"、"开个新坑"
- "新小说"、"创建小说"、"写个新故事"
- 任何表达"开始一本新书/新小说创作"的类似表述

## 执行步骤

### 步骤 1：确认目标目录与润色模式

询问用户三件事：
1. **书籍名称**：这本书叫什么？（如果用户已提供则跳过）
2. **目标路径**：在当前工作目录下创建，还是指定某个路径？
   - 如果用户未指定路径，默认在当前工作目录下创建以书名命名的文件夹
3. **润色模式**：后续创建人物/设定/剧情时，对用户输入内容的加工深度？
```
✏️ 请选择润色模式：
  • 轻度 — 保留用户原话，仅书面化、规范化书写
  • 中度 — 小幅优化用户原话（改动幅度 ≤45%）
  • 重度 — 仅保留原意，完全改写、润色、扩写内容
```

### 步骤 2：收集书籍元数据

逐项向用户询问以下书籍元数据：

**第一项 — 传播范围：**
```
📡 这本书的传播范围？
  • 传播向 — 公开发布，面向广泛读者
  • 个人向 — 自娱自乐，仅个人/小圈子阅读
```

**第二项 — 篇幅长度：**
```
📏 预期篇幅长度？
  • 随笔 — ＜5万字
  • 短篇 — ≤20万字
  • 短篇（连载） — ≤35万字
  • 中篇 — ≤60万字
  • 长篇 — ＞60万字
```

**第三项 — 书籍种类：**
```
📚 书籍种类/类型？
（自由填写，如：玄幻、科幻、言情、悬疑、历史、同人、轻小说 等）
```
- 如用户不确定，可提供常见类型列表供参考，由用户自由输入或自定

- 如果用户在指令中已附带部分元数据，直接提取使用，跳过对应询问
- 每次只问一项，不要一次性列出所有问题

### 步骤 3：确认路径语言

询问用户文件夹命名语言：
- **默认**：使用中文命名（大纲、番外、正文、设定、人物、剧情）
- **可选**：用户可指定其他语言（如 English：outline、extras、body、settings、characters、plot）
- 如果用户在一次指令中已明确指定语言，直接使用，跳过此询问

### 步骤 4：创建文件夹结构

根据用户选择的语言，在目标目录下创建以下结构：

**中文（默认）：**
```
[书名]/
├── 大纲/
│   ├── 设定/
│   ├── 人物/
│   └── 剧情/
├── 番外/
└── 正文/
```

**English：**
```
[书名]/
├── outline/
│   ├── settings/
│   ├── characters/
│   └── plot/
├── extras/
└── body/
```

**其他语言**：用户指定后，按对应翻译创建同样结构。

### 步骤 5：生成项目配置文件

文件夹创建完成后，在 `大纲/` 目录下生成三个文件：

**A. 生成 `项目信息.json`**（位于 `大纲/` 根目录，项目基本信息的唯一权威来源）：

```json
{
  "book_name": "{书名}",
  "distribution": "{传播向 / 个人向}",
  "content_rating": "一般向",
  "length": "{随笔 / 短篇 / 短篇（连载） / 中篇 / 长篇}",
  "genre": "{用户填写的种类}",
  "created_date": "{YYYY-MM-DD}",
  "last_updated": "{YYYY-MM-DD}",
  "nsfw_output_level": "",
  "nsfw_character_tone": "",
  "nsfw_tier_range": {
    "global": "",
    "chapters": {}
  }
}
```

**字段说明：**

| JSON key | 对应元数据 | 取值 |
|----------|----------|------|
| `book_name` | 书名 | 用户输入 |
| `distribution` | 传播范围 | `传播向` / `个人向` |
| `content_rating` | 内容分级 | 默认 `一般向`，用户提及 NSFW 时改为 `NSFW` |
| `length` | 篇幅长度 | `随笔` / `短篇` / `短篇（连载）` / `中篇` / `长篇` |
| `genre` | 书籍种类 | 用户自由输入 |
| `created_date` | 创建日期 | ISO 日期格式 |
| `last_updated` | 最后更新 | ISO 日期格式 |
| `nsfw_output_level` | NSFW输出词级别 | `限制级` / `开放级`，默认空（无 NSFW 内容时不填），由 NSFW 技能首次调用时写入 |
| `nsfw_character_tone` | NSFW角色语气 | `保守` / `中性` / `放荡`，默认空，由 NSFW 技能首次调用时写入 |
| `nsfw_tier_range.global` | 全书色色值域 | 如 `"N3-N4"`，默认空，由 NSFW 技能首次调用时写入 |
| `nsfw_tier_range.chapters` | 章节区域覆盖 | 如 `{"1-10": "N1-N2"}`, 默认 `{}`，由用户后续配置

**文件命名：**
- 中文默认：`项目信息.json`
- English：`project-info.json`
- 其他语言：按对应语言翻译命名

该 JSON 是项目基本信息的**唯一权威来源**，后续技能需要书名、分级等信息时从此读取。

**B. 生成 `润色配置.json`**（位于 `大纲/` 根目录，润色模式的唯一权威来源）：

```json
{
  "大纲": {
    "polish_mode": "{轻度 / 中度 / 重度}",
    "mode_description": "{对应描述}",
    "last_updated": "{YYYY-MM-DD}"
  },
  "正文": {
    "polish_mode": "{轻度 / 中度 / 重度}",
    "mode_description": "{对应描述}",
    "last_updated": "{YYYY-MM-DD}"
  }
}
```

**结构说明：**
- `大纲` — 适用于大纲类文本（剧情大纲、设定编辑、人物创建等），初始值由步骤1用户选择
- `正文` — 适用于正文书写（叙事文本、章节内容），初始值与大纲相同，但正文书写前会再次询问用户是否沿用

**字段对应关系：**

| mode 值 | mode_description |
|---------|-----------------|
| `轻度` | 保留用户原话，仅书面化、规范化书写 |
| `中度` | 小幅优化用户原话（改动幅度 ≤45%） |
| `重度` | 仅保留原意，完全改写、润色、扩写内容 |

**文件命名：**
- 中文默认：`润色配置.json`
- English：`polish-config.json`
- 其他语言：按对应语言翻译命名

该 JSON 文件是润色模式的**唯一权威来源**，所有后续技能必须读取此文件以确定加工强度：
- 大纲类技能（人物创建、剧情编辑、设定编辑）读取 `大纲.polish_mode`
- 正文类技能（基础写作辅助、NSFW写作）读取 `正文.polish_mode`，并在首次正文书写前询问用户是否沿用大纲润色程度

**C. 生成 `设定.md`**（位于 `大纲/设定/`，仅包含世界观设定内容）：

```
# {书名} — 项目设定

> 创建日期：{YYYY年MM月DD日}

## 世界观设定

（待完善）

---

## 核心设定

（待完善）

---

## 其他设定

（待完善）
```

**填写规则**：
- 所有 `{}` 占位符替换为用户在步骤 1~2 中提供的实际内容
- 基本信息已独立存储在 `大纲/项目信息.json` 中，`设定.md` 不再包含基本信息表
- `待完善` 区块预留，供后续世界观设定技能填充
- 日期使用当天日期

### 步骤 5.5：NSFW 项目偏好配置（条件触发）

**仅当** `项目信息.json` 中 `content_rating` 被设为 `NSFW` 时执行此步骤。

项目创建完成后，向用户推荐 NSFW 偏好配置：

```
🔞 检测到本书为 NSFW 向作品。推荐配置 NSFW 写作偏好（可大幅提升后续输出准确性）：

① 本书的整体色色值域在什么挡位之间？（如 N3-N4）
   N1 — 点到为止    N2 — 情色剧情并重    N3 — 情色为主
   N4 — 纯情色驱动  N5 — 纯情色不间断
   也可指定章节区域（如：第1—10章 N1-N2，第11—30章 N3-N4）

② 本书倾向什么级别的 NSFW 输出词？
   A. 词汇开放度：限制级（优雅代称）→ 开放级（直白露骨）
   B. 角色语气：保守（文雅含蓄）→ 中性（自然直白）→ 放荡（粗俗刺激）

（均可跳过，跳过后由 LLM 后续自行判断；随时可说 /nsfw-config 重新配置）
```

- 如用户提供了数据，写入 `项目信息.json` 的 `nsfw_output_level` / `nsfw_character_tone` / `nsfw_tier_range` 字段，并更新 `last_updated`
- 如用户跳过，NSFW 字段保持空值——后续 NSFW 技能首次调用时会再次询问
- 此步骤不影响项目结构创建，仅做偏好预填

### 步骤 6：输出结果并推荐下一步

创建完成后，向用户展示完整的项目结构和设定摘要：

```
✅ 新书项目「{书名}」已创建完成！

📁 项目结构：
  {书名}/
  ├── 大纲/
  │   ├── 设定/
  │   │   └── 设定.md    ← 项目设定文件（已生成）
  │   ├── 人物/           ← 角色设定、人物关系
  │   └── 剧情/           ← 主线剧情、章节大纲
  ├── 番外/               ← 番外篇、外传
  └── 正文/               ← 正式章节内容

📋 项目设定摘要：
  • 书名：{书名}
  • 传播：{传播向/个人向}  • 篇幅：{长度}  • 种类：{种类}  • 润色：{轻度/中度/重度}

📝 建议下一步：完善大纲内容。你想先从哪个方面开始？
  • 人物设定 — 创建主要角色、人物关系图
  • 剧情大纲 — 规划主线剧情、分章大纲
  • 世界观设定 — 充实设定.md 中的世界观内容

请告诉我你的选择，我来帮你继续！
```

### 步骤 7：根据用户选择调度后续技能

根据用户的回答，推荐并调用对应的后续技能：
- 选择**人物** → 调用 `create character` 技能
- 选择**剧情** → 调用剧情大纲相关技能
- 选择**设定** → 读取 `设定.md`，引导用户完善世界观/核心/其他设定区块
- 选择**全部** → 按人物 → 设定 → 剧情的顺序逐步进行

## 注意事项

- 如果目标目录下已存在同名文件夹，提醒用户并询问是否覆盖或在现有目录中继续
- 元数据询问每次只问一项，保持交互节奏轻快
- 如用户在某项元数据上不确定，允许先选默认值后续再修改
- 设定.md 中使用占位符「（待完善）」为后续技能预留扩展空间
- 内容分级默认**一般向**，不例行询问。仅当用户主动提及 NSFW/成人/敏感内容时，才切换为 NSFW 并提示该模式影响人物创建（启用学习资料目录）
- 始终在创建完成后向用户提供清晰的下一步指引
