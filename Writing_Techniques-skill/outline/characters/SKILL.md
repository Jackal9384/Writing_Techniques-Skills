# 创建人物

此技能用于在已创建的新书项目中，按模板创建一个人物角色，并将所有人物统一存储在一个 Markdown 存档文件中，按人物类别分区管理。

## 执行模式：计划模式

**调用此技能后，必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出将执行的步骤，包括：
   - 目标项目确认（定位 `项目信息.json`、`润色配置.json` 和 `人物存档.md`）
   - 读取 `润色配置.json` 确定加工强度（使用 `大纲.polish_mode`）
   - 将询问的字段列表（基础信息、外貌、性格、简介、可选内容；NSFW 仅用户提及时启用）
   - 输出文件路径和写入方式（新建或追加）
3. 等待用户批准计划后，再按计划逐步询问并执行
4. 不要在进入计划模式前直接开始询问用户信息或写入文件

## 核心原则：单文件人物存档

**所有出场人物均存储在一个文件中**，不按人物拆分文件。

- 首次创建：在 `大纲/人物/` 目录下新建 `人物存档.md`
- 后续创建：将新人物直接**追加写入**已有 `人物存档.md`
- 以 `## 人物类别` 划分大区，每个新人物追加到对应类别分区末尾

## 触发条件

当用户表达以下意图时，立即调用此技能：

- "我们开始创建一个新人物"、"创建新人物"、"创建人物"
- "新建角色"、"添加角色"、"写个人物"
- "加一个角色"、"设定一个角色"
- 任何表达"创建/新增一个小说/故事人物角色"的类似表述

## 前提条件

此技能依赖 `new book skill` 已执行完成，即：

- 当前工作目录下应已存在 `大纲/人物/`（或对应语言的 `outline/characters/`）目录
- 如未检测到该目录，提示用户先使用"创建新书"建立项目

## 语言规则

继承 `new book skill` 中设定的路径语言：

- 中文默认：文件名为 `人物存档.md`，内容以中文输出
- English：文件名为 `characters.md`，内容以英文输出
- 其他语言：按对应语言命名和输出
- 如无法确定，默认使用中文

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `人物存档.md` | `大纲/人物/` | 所有人物数据统一存储，此技能唯一输出文件 | 读写 |
| `项目信息.json` | `大纲/` | 内容分级（`content_rating`）、NSFW 输出词偏好 | 只读 |
| `润色配置.json` | `大纲/` | 润色模式（使用 `大纲.polish_mode`） | 只读 |

```

> 创建日期：{日期}
> 最后更新：{日期}

---

## 主要角色

（主要角色条目追加于此）

---

## 次要角色

（次要角色条目追加于此）

---

## 龙套角色

（龙套角色条目追加于此）
```

### 龙套角色简化模板

龙套角色使用极简格式，不展开详细字段：

```
**{人物名称}**：{简介，大致年龄，社会身份/地位，身形特点，性格，简单关系等}
```

**示例**：

> **张三**：李四的发小，约25岁，镇上铁匠铺学徒，膀大腰圆，憨厚老实，与李四是酒友。

> **王婆**：村口卖菜的老妇人，六十出头，驼背但眼神精亮，爱嚼舌根但心肠不坏，常给主角塞菜。

**龙套分区书写规则**：
- 每条龙套一行，条目之间以空行分隔
- 不使用 `---` 分隔线（与主要/次要角色区分）
- 无子标题（不设 `### {人物名称}`），直接以粗体名称开头

## 执行步骤

### 步骤 1：确认输出目录与存档文件

定位目标目录：

- 在当前工作目录下查找 `大纲/人物/`（中文）或 `outline/characters/`（English）或对应语言的目录
- 如存在多个项目，询问用户选择哪个项目
- 如不存在，提示用户先运行 `new book skill` 创建项目

检查存档文件：

- 检查目标目录中是否存在 `人物存档.md`（或对应语言的存档文件）
- **已存在** → 读取现有文件，确定各分区位置，准备追加
- **不存在** → 准备新建，按存档文件结构写入顶部框架

读取润色配置：
- 读取 `大纲/润色配置.json`（或对应语言的 `polish-config.json`）
- 获取 `大纲.polish_mode` 值（轻度/中度/重度）
- 后续交互中依据此模式调整对用户输入的加工程度

### 步骤 2：交互式填充模板（依据润色模式）

逐项向用户询问模板中的**必填字段**。按以下顺序进行，每次只问 1~2 个相关字段。

**润色模式影响**（从 `润色配置.json` 读取 `大纲.polish_mode`）：
- **轻度**：直接记录用户原话，转为书面格式
- **中度**：在用户原话基础上小幅优化表达（≤45% 改动）
- **重度**：仅保留原意，对内容进行改写润色和适当扩写

**第一轮 — 基础信息：**
询问人物类别（主要角色 / 次要角色 / 龙套角色）、人物名称、性别

**此轮后的分支判断：**

- 用户选择「主要角色」或「次要角色」→ 继续第二轮~第五轮完整流程
- 用户选择「龙套角色」→ **跳至龙套快速通道（见下方）**，跳过第二轮~第五轮

**第二轮 — 外貌信息：**
询问年龄/出生年月日期、身高、体重、身形特点

**第三轮 — 内在设定：**
询问人物性格（可提供常见性格类型供参考：外向/内向、理性/感性、积极/消极、稳重/冲动 等）

**第四轮 — 背景故事：**
询问人物简介（角色的出身、经历、在故事中的定位）

**第五轮 — 可选内容：**
询问是否需要填写人物基本关系（如有，请用户描述）
询问是否需要填写人物能力（如需要，请用户对各项能力打分 1~10）

---

#### 龙套快速通道

当用户在第一轮选择「龙套角色」后，使用此简化流程。**不询问外貌、性格详细字段。**

**L1 — 确认名称：**
如第一轮已获取角色名称，跳过；否则询问龙套角色名称。

**L2 — 一句话描述：**
提示用户一句话描述该龙套：

```
✏️ 请一句话描述「{人物名称}」（含大致年龄、社会身份/地位、身形特点、性格、简单关系）：
```

**L3 — 润色描述：**
用户输入后，调用「基础写作辅助」以**大纲档位**润色该描述——龙套数据视为大纲类内容。

润色方式：读取 `body/Core/SKILL.md` 中的规范 1.5（大纲类文本特殊处理），对用户输入做书面化、规范化处理。

**L4 — 拼接简化格式：**
将润色后的描述拼接为龙套简化格式：

```
**{人物名称}**：{润色后描述}
```

### 步骤 3：写入存档文件

根据用户填写的信息，按人物类别将条目追加到存档文件对应分区。

**首次创建（文件不存在）：**

1. 写入存档文件顶部框架（标题、日期、三个类别分区）
2. 在对应类别分区下写入第一条人物条目

**追加写入（文件已存在）：**

1. 读取 `人物存档.md`，定位到 `## {人物类别}` 分区
2. 在该分区末尾（下一个 `##` 或 `---` 分隔符之前）追加新人物条目
3. 更新文件顶部的 `最后更新` 日期

**追加规则：**

- 找到对应类别标题（如 `## 主要角色`）
- **主要/次要角色**：在该分区最后一个条目末尾的 `---` 后、下一个类别标题前，插入新条目；保持各分区之间有 `---` 分隔
- **龙套角色**：以空行分隔追加简化格式条目（单行），不使用 `---` 分隔线，不做子标题

### 步骤 3.5：双向更新人物关系

新人物写入后，如果填写了**人物基本关系**（或龙套的简化描述中隐含关系），必须对所有关联的老角色执行双向更新：

**解析关系：**
- **主要/次要角色**：从「人物基本关系」中提取，格式为 `{角色A}与{角色B}：{关系描述}`
- **龙套角色**：从简化描述中智能提取关系（如"李四的发小"→ 关联李四；"常给主角塞菜"→ 关联主角；"张三的妻子"→ 关联张三）
- 假设新人物为其中一方，另一方为已存在的角色

**更新老角色：**
1. 在 `人物存档.md` 中搜索被关联的角色名称
2. 找到该角色的条目后，在其「人物基本关系」区块追加反向关系
   - 如新角色「张三」写有「张三与李四：师徒关系」
   - 则在「李四」的关系区块追加「李四与张三：师徒关系」
3. 如果老角色原本没有「人物基本关系」字段，则在人物能力之后新增该字段
4. 如果老角色已有关系，将新关系追加到列表末尾

**示例：**
```
创建「张三」（新角色），关系：张三与李四：师徒关系

→ 写入张三条目后，查找李四
→ 在李四条目的「人物基本关系」中追加：
  - 李四与张三：师徒关系
```

**双向更新输出：**
```
🔄 已同步更新以下角色的关系：
  • 李四（次要角色）→ 新增关系：与张三：师徒关系
```

## NSFW 内容规则

NSFW 字段（XP、三维、性特征、人物X能力）统一写入 `人物存档.md`，不独立存储。

**触发方式 — 仅用户主动提及时启用：**
- 正常创建流程**不询问** NSFW 字段，模板中 NSFW 字段仅作为可选项存在
- 用户在创建人物时主动提及 NSFW 内容（如"加个XP"、"补充X能力"），才在对应字段写入
- 用户也可创建人物后追加 NSFW 资料，直接在 `人物存档.md` 中该角色条目下补充

**NSFW 词汇选择协调：**
当用户填写 NSFW 字段时：
1. 读取 `大纲/项目信息.json` 中的 `nsfw_output_level` 和 `nsfw_character_tone`
2. 若已配置 → 参照 NSFW 技能的词汇表，根据 `nsfw_output_level` 选择对应级别的用词写入
3. 若未配置 → 以中性/自然用词写入，同时提示用户可配置 NSFW 偏好以提升一致性：
   ```
   💡 提示：项目尚未配置 NSFW 输出词偏好。配置后所有 NSFW 字段的用词风格将保持一致。
      是否需要配置？（可说 /nsfw-config 随时配置）
   ```
4. 写入 NSFW 字段后，更新 `项目信息.json` 的 `last_updated`

**写入位置：**
- NSFW 字段直接写入人物条目中，标注「（可选，NSFW）」
- XP、三维、性特征 写在身形特点之后、人物性格之前
- 人物X能力 写在人物能力之后

## 注意事项

- 如果用户在指令中已提供部分信息（如"创建一个叫张三的主角"），直接提取使用，跳过对应询问
- 可选字段标记为"（可选）"，允许用户跳过
- NSFW 内容仅在用户主动提及时写入，不纳入例行询问
- 人物能力数值范围 1~10，如用户不确定可留空
- 追加写入时务必保留已有内容，仅在对应分区末尾追加
- 同一人物名称如已存在于存档中，询问用户是更新还是跳过
- 始终以 Markdown 格式（.md）保存文件
- **龙套角色特殊规则**：
  - 龙套角色使用简化模板（单行格式），不询问外貌、性格、能力等详细字段
  - 龙套描述由基础写作辅助以大纲档位润色后写入
  - 龙套条目之间以空行分隔，不使用 `---` 分隔线
  - 龙套不询问 NSFW 字段（大众级内容审查下尤需注意）
