# 创建人物

此技能用于在已创建的新书项目中，按模板创建一个人物角色，并将所有人物统一存储在一个 Markdown 存档文件中，按人物类别分区管理。

## 核心定位

- **单文件人物管理**：所有出场人物统一存储在 `人物存档.md` 中，按主要角色/次要角色/龙套角色三个分区管理——不按人物拆文件
- **类别分流**：主要/次要角色走完整交互式模板（五轮问询），龙套角色走快速通道（一句话描述 → 润色 → 一行写入）
- **双向关系同步**：新人物写入后，自动扫描其人物基本关系，在老角色的关系区块中追加反向关系——保持人物关系网络的对称完整性
- **NSFW 克制**：NSFW 字段（XP/三维/性特征/人物X能力）仅在用户主动提及时才询问和写入，不纳入例行问询

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `人物存档.md` | `大纲/人物/` 或 `outline/characters/` | 所有人物数据统一存储，此技能唯一输出文件 | 读写 |
| `项目信息.json` | `大纲/` 或 `outline/` | 内容分级（`content_rating`）、NSFW 输出词偏好 | 只读 |
| `润色配置.json` | `大纲/` 或 `outline/` | 润色模式（使用 `大纲.polish_mode`） | 只读 |

## 执行模式：计划模式

**调用此技能后，必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出：
   - 目标项目确认（定位 `项目信息.json`、`润色配置.json` 和 `人物存档.md`）
   - 读取 `润色配置.json` 确定加工强度（使用 `大纲.polish_mode`）
   - 将询问的字段列表（基础信息 → 外貌 → 性格 → 简介 → 可选；龙套走快速通道）
   - NSFW 字段是否启用（仅用户主动提及时启用）
   - 输出文件路径和写入方式（新建或追加）
3. 等待用户批准计划后，再按计划逐步询问并执行
4. 不要在进入计划模式前直接开始询问用户信息或写入文件

## 触发条件

当用户表达以下意图时，立即调用此技能：

- "我们开始创建一个新人物"、"创建新人物"、"创建人物"
- "新建角色"、"添加角色"、"写个人物"
- "加一个角色"、"设定一个角色"
- 任何表达"创建/新增一个小说/故事人物角色"的类似表述

## 前提条件

此技能依赖 `创建新书` 技能已执行完成：

- 当前工作目录下应已存在 `大纲/人物/`（或 `outline/characters/`）目录
- 如未检测到该目录 → 提示用户先使用"创建新书"建立项目
- 如检测到多个项目目录 → 询问用户选择目标项目

## 语言规则

继承 `创建新书` 技能中设定的路径语言：

- 中文默认：文件名为 `人物存档.md`，内容以中文输出
- English：文件名为 `characters.md`，内容以英文输出
- 如无法确定，默认使用中文


**龙套书写规则**：
- 每条龙套一行，条目之间以空行分隔
- 不使用 `---` 分隔线（与主要/次要角色区分）
- 无子标题（不设 `### {人物名称}`），直接以粗体名称开头
- 单行描述控制在 60 字以内——保持龙套区的轻量感

**龙套示例**：
> **张三**：李四的发小，约25岁，镇上铁匠铺学徒，膀大腰圆，憨厚老实，与李四是酒友。

## 执行步骤

### 步骤 1：确认输出目录与存档文件

**1.1 定位目标目录**

```
大纲/人物/  →  outline/characters/  →  用户手动指定
```

- 如存在多个项目目录 → 列出供用户选择
- 如不存在 → 提示先运行"创建新书"

**1.2 检查存档文件**

| 文件状态 | 处理 |
|---------|------|
| 已存在 | `Read` 读取现有文件 → 解析各分区位置 → 准备追加 |
| 不存在 | 按存档文件结构写入顶部框架（书名标题 + 日期 + 三个分区标题） |

**1.3 读取上下文**

- `Read` 读取 `大纲/润色配置.json` → 获取 `大纲.polish_mode`（轻度/中度/重度）
- `Read` 读取 `大纲/项目信息.json` → 获取 `content_rating`、`nsfw_output_level`、`nsfw_character_tone`
- 润色模式影响后续所有交互中对用户输入的加工程度
- NSFW 数据用于人物涉及 NSFW 字段时的词汇选择

---

### 步骤 2：交互式填充模板

逐项向用户询问模板中的必填字段。按以下顺序进行，每次只问 1~2 个相关字段。

**润色模式影响**（从 `润色配置.json` 读取 `大纲.polish_mode`）：

| 模式 | 对人物字段的加工策略 |
|------|-------------------|
| `轻度` | 直接记录用户原话，转为书面格式——保留用户的用词习惯 |
| `中度` | 在用户原话基础上小幅优化表达（≤45% 改动）——如将口语化描述转为书面化 |
| `重度` | 仅保留原意，对内容进行改写润色和适当扩写——如将一句话描述扩展为一段文字 |

---

**第一轮 — 基础信息：**

```
👤 人物基础信息

  • 人物类别？（主要角色 / 次要角色 / 龙套角色）
  • 人物名称？
  • 性别？（男 / 女 / 无）
```

**此轮后的分支判断**：

| 用户选择 | 后续流程 |
|---------|---------|
| 主要角色 | 继续第二轮~第五轮完整流程 |
| 次要角色 | 继续第二轮~第五轮完整流程 |
| 龙套角色 | **跳至龙套快速通道**，跳过第二轮~第五轮 |

---

**第二轮 — 外貌信息：**

```
📐 外貌信息

  • 年龄 / 出生日期？
  • 身高？（___cm）
  • 体重？（___kg）
  • 身形特点？（如：纤细/魁梧、肩宽腰窄、梨形身材 等）
```

**年龄写入规则**：
- 用户提供确切日期 → 写入 `XXXX年XX月XX日`
- 用户提供大致年龄 → 写入 `约XX岁`
- 两者都提供 → 写入 `XXXX年XX月XX日（XX岁）`

**身形特点正反例**：

| ✕ 不当写法 | ✓ 正确写法 |
|-----------|-----------|
| "身材很好" | "肩宽腰窄，倒三角身材，手臂线条分明" |
| "长得还行" | "清瘦修长，锁骨突出，常年不见阳光的苍白肤色" |
| "挺好看的" | "娇小圆润，梨形身材，腰细但胯宽，走路带风" |

**第三轮 — 内在设定：**


| "他很善良，很勇敢，也很聪明" | "表面冷言少语，实则心软——看到受伤的猫会绕路去买药但嘴上说'真麻烦'。不擅交际但极重承诺，答应的事拼了命也会做到。" |

**第四轮 — 背景故事：**


**简介描述正反例**：

| ✕ 不当写法 | ✓ 正确写法 |

```
  • 人物基本关系？（与其他角色的关系——如"张三与李四：师徒"）
```

#### 龙套快速通道

当用户在第一轮选择「龙套角色」后，跳过第二轮~第五轮，使用此简化流程。

**L1 — 确认名称**（如第一轮已获取则跳过）：
```
👤 龙套角色名称？
```

**L2 — 一句话描述**：
```
✏️ 请一句话描述「{人物名称}」
（含大致年龄、社会身份/地位、身形特点、性格、简单关系等）

例如：
  "李四的发小，约25岁，镇上铁匠铺学徒，膀大腰圆，憨厚老实，与李四是酒友。"
```

**L3 — 润色描述**：
用户输入后，按 `大纲.polish_mode` 润色该描述——龙套数据视为大纲类内容，应用规范 1.5（大纲类文本特殊处理）。

**L4 — 拼接简化格式**：
将润色后的描述拼接为龙套简化格式：
```
**{人物名称}**：{润色后描述}
```

**L5 — 龙套关系提取**：
从简化描述中智能提取关系（如"李四的发小"→ 关联李四；"常给主角塞菜"→ 关联主角），在步骤 3.5 中触发双向关系同步。

### 步骤 3：写入存档文件

根据用户填写的信息，按人物类别将条目追加到存档文件对应分区。

**3.1 首次创建（文件不存在）**

1. 写入存档文件顶部框架（书名标题 + 日期 + 三个类别分区）
2. 在对应类别分区下写入第一条人物条目

**3.2 追加写入（文件已存在）**

1. `Read` 读取 `人物存档.md`
2. 定位到 `## {人物类别}` 分区
3. 在该分区末尾（下一个 `##` 或 `---` 分隔符之前）追加新人物条目
4. 更新文件顶部的 `> 最后更新：{日期}`

**3.3 追加规则**：

| 人物类别 | 追加方式 | 分隔规则 |
|---------|---------|---------|
| 主要角色 | 完整模板（`### {名称}` ... `---`） | 条目间以 `---` 分隔 |
| 次要角色 | 完整模板（同上） | 条目间以 `---` 分隔 |
| 龙套角色 | 简化格式（`**{名称}**：{描述}`） | 条目间以空行分隔，不用 `---` |

**3.4 同名人物冲突**：

同一人物名称如已存在于存档中：
```
⚠️「{人物名称}」已存在于「{人物类别}」分区。

  • 更新 — 覆盖已有条目（旧数据将丢失）
  • 新建 — 换一个名称重新创建
  • 跳过 — 不做修改
```

---

### 步骤 3.5：双向更新人物关系

新人物写入后，如果填写了**人物基本关系**（或龙套的简化描述中隐含关系），必须对所有关联的老角色执行双向更新。

**解析关系来源**：

| 来源 | 解析方式 |
|------|---------|
| 主要/次要角色的「人物基本关系」 | 从 `{角色A}与{角色B}：{关系描述}` 格式解析 |
| 龙套角色的简化描述 | 智能提取——"李四的发小"→ 关联李四；"张三的妻子"→ 关联张三；"常给主角塞菜"→ 关联主角 |

**更新老角色**：

1. 在 `人物存档.md` 中搜索被关联的角色名称
2. 找到该角色条目后，在其「人物基本关系」区块追加反向关系
3. 如老角色原本没有「人物基本关系」字段 → 在人物能力之后新增该字段
4. 如老角色已有关系 → 将新关系追加到列表末尾（不覆盖已有关系）

**示例**：
```
创建「张三」（新角色），关系：张三与李四：师徒关系

→ 写入张三条目后，查找李四
→ 在李四条目的「人物基本关系」中追加：
  - 李四与张三：师徒关系
```

**双向更新输出**：
```
🔄 已同步更新以下角色的关系：
  • 李四（次要角色）→ 新增关系：与张三：师徒关系
```

**边界情况**：
- 关联的角色不在存档中 → 仅在新角色中保留关系记录，不做反向写入（等该角色创建后再补）
- 关系描述中角色名包含别名 → 尝试模糊匹配，匹配不到时提示用户确认

## NSFW 内容规则

NSFW 字段（XP、三维、性特征、人物X能力）统一写入 `人物存档.md`，不独立存储。

### 触发方式 — 仅用户主动提及时启用

- 正常创建流程**不询问** NSFW 字段——模板中 NSFW 字段仅标记为可选项存在
- 用户在创建人物时主动提及 NSFW 内容（如"加个XP"、"补充X能力"），才在对应字段写入
- 用户也可创建人物后追加 NSFW 资料——直接在 `人物存档.md` 中该角色条目下补充

### NSFW 词汇选择协调

当用户填写 NSFW 字段时：

1. `Read` 读取 `大纲/项目信息.json` 中的 `nsfw_output_level` 和 `nsfw_character_tone`
2. 若已配置 → 参照 NSFW 技能的词汇表，根据 `nsfw_output_level` 选择对应级别的用词：

| nsfw_output_level | 用词风格 | 示例 |
|------------------|---------|------|
| `限制级` | 优雅代称 | 酥胸、玉茎、花径 |
| `开放级` | 直白露骨 | 奶子、大肉棒、小穴 |
| 空（未配置） | 中性/自然用词 | 胸部、阴茎、阴道 |

3. 若未配置 → 以中性用词写入，同时提示：
```
💡 提示：项目尚未配置 NSFW 输出词偏好。配置后所有 NSFW 字段的用词风格将保持一致。
   是否需要配置？（可说 /nsfw-config 随时配置）
```

### 写入位置

- NSFW 字段直接写入人物条目中，标注「（可选，NSFW）」
- XP、三维、性特征 → 写在身形特点之后、人物性格之前
- 人物X能力 → 写在人物能力之后

## 注意事项

- **已提供的信息不重复问**：用户在消息中已附带部分信息（如"创建一个叫张三的主角"），直接提取使用，跳过对应询问
- **可选字段允许跳过**：标记为"（可选）"的字段（人物基本关系、人物能力），用户明确说"跳过"时直接进入下一步
- **NSFW 不纳入例行询问**：正常流程中不出现 NSFW 字段询问——避免非 NSFW 用户感到不适
- **人物能力数值范围 1~10**：如用户不确定可留空
- **追加写入不破坏已有内容**：仅在对应分区末尾追加，不修改已有人物条目
- **同名人物更新需用户确认**：同一名称已存在时，明确告知覆盖风险后等待用户选择
- **龙套角色特殊规则**：
  - 使用简化模板（单行格式），不询问外貌/性格/能力等详细字段
  - 龙套描述按大纲档位润色后写入
  - 龙套条目之间以空行分隔，不使用 `---` 分隔线
  - 龙套不询问 NSFW 字段
- **人物关系延迟同步**：新角色引用了尚未创建的角色时，关系仅在新角色侧写入——待该角色创建后再补反向关系
- **始终以 Markdown 格式保存**：文件名为 `人物存档.md`（中文）或 `characters.md`（English）
