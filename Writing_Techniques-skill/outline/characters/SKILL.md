# 创建人物

此技能用于在已创建的新书项目中，按模板创建一个人物角色，并将所有人物统一存储在一个 Markdown 存档文件中，按人物类别分区管理。

## 核心定位

- **三类三分文件管理**：所有出场人物按类别拆分为三个独立文件——`主要角色.md` / `次要角色.md` / `龙套角色.md`；每个文件仅存对应类别的人物，不再混合存储
- **分卷多目录**：分卷多文件项目（`volumes.enabled=true` 且 `volumes.multi_file=true`），角色文件按 `大纲/人物/卷{N}/` 子目录存放（如 `大纲/人物/卷1/主要角色.md`）；不分卷或单文件模式统一存放于 `大纲/人物/`
- **类别分流**：主要/次要角色走完整交互式模板（五轮问询），龙套角色走快速通道（一句话描述 → 润色 → 一行写入）
- **双向关系同步**：新人物写入后，自动扫描其人物基本关系，在老角色的关系区块中追加反向关系——跨文件的关系同步覆盖所有三类文件
- **跨卷人物引用**：多文件模式下创建新卷人物时，若该角色已在旧卷中存在条目，自动引用旧数据并询问用户需变更的内容——避免重复录入
- **NSFW 克制**：NSFW 字段（XP/三维/性特征/人物X能力）仅在用户主动提及时才询问和写入，不纳入例行问询

## 关联文件

| 文件 | 位置 | 用途 | 读写 |
|------|------|------|------|
| `主要角色.md` | `大纲/人物/`（不分卷）或 `大纲/人物/卷{N}/`（分卷多文件） | 主要角色数据存储 | 读写 |
| `次要角色.md` | 同上 | 次要角色数据存储 | 读写 |
| `龙套角色.md` | 同上 | 龙套角色数据存储（简化格式） | 读写 |
| `项目信息.json` | `大纲/` 或 `outline/` | 内容分级（`content_rating`）、NSFW 输出词偏好、**分卷信息（volumes.*）** | 只读 |
| `润色配置.json` | `大纲/` 或 `outline/` | 润色模式（读 `大纲.polish_mode` + `分卷` 覆盖项，分卷时按角色出场卷取对应卷润色配置） | 只读 |

## 执行模式：计划模式

**调用此技能后，必须首先进入计划模式（EnterPlanMode）。**

1. 使用 `EnterPlanMode` 工具进入计划模式
2. 在计划中列出：
   - 目标项目确认（定位 `项目信息.json`、`润色配置.json` 和角色文件）
   - 读取 `润色配置.json` 确定加工强度（使用 `大纲.polish_mode`）
   - 将询问的字段列表（基础信息 → 外貌 → 性格 → 简介 → 可选；龙套走快速通道）
   - NSFW 字段是否启用（仅用户主动提及时启用）
   - 输出文件路径和写入方式（新建或追加）
3. 等待用户批准计划后，再按计划逐步询问并执行
4. 不要在进入计划模式前直接开始询问用户信息或写入文件

## 存档文件结构

角色数据按类别拆分三文件，每个文件独立管理。文件顶部结构（首次创建时写入）：

**主要角色.md**：
```
# {书名} — 主要角色

> 创建日期：{日期}
> 最后更新：{日期}
{分卷多文件时：> 所属：{书名} / 第{N}卷 / 共{N}卷}

---

（主要角色条目追加于此）
```

**次要角色.md**：
```
# {书名} — 次要角色

> 创建日期：{日期}
> 最后更新：{日期}
{分卷多文件时：> 所属：{书名} / 第{N}卷 / 共{N}卷}

---

（次要角色条目追加于此）
```

**龙套角色.md**：
```
# {书名} — 龙套角色

> 创建日期：{日期}
> 最后更新：{日期}
{分卷多文件时：> 所属：{书名} / 第{N}卷 / 共{N}卷}

---

（龙套角色条目追加于此）
```

### 分卷多目录存储规则

**分卷多文件模式**（`volumes.enabled=true` + `volumes.multi_file=true`）：
- 角色文件按卷存放：`大纲/人物/卷1/主要角色.md`、`大纲/人物/卷1/次要角色.md`、`大纲/人物/卷1/龙套角色.md`
- 每卷角色文件独立，仅收录该卷出场的角色
- 跨卷出场角色：在各卷中均有条目（通过跨卷引用机制同步基础数据）

**不分卷或单文件模式**（`volumes.enabled=false` 或 `volumes.multi_file=false`）：
- 角色文件统一存放：`大纲/人物/主要角色.md`、`大纲/人物/次要角色.md`、`大纲/人物/龙套角色.md`
- 所有卷的角色共存在同一套文件中（通过 `出场卷` 字段区分）

**用户指定"只要一个"**：如用户在分卷时明确说"角色只要一个文件"，则无论 `volumes.multi_file` 如何，角色均使用不分卷路径（`大纲/人物/` 下的三文件）。

### 卷目录自动创建

首次写入某卷角色时，若 `大纲/人物/卷{N}/` 目录不存在 → 自动创建。创建后验证目录存在再写入文件。

### 龙套角色简化模板

```
**{人物名称}**：{简介，大致年龄，社会身份/地位，身形特点，性格，简单关系等}
```

**龙套书写规则**：
- 每条龙套一行，条目之间以空行分隔
- 不使用 `---` 分隔线（与主要/次要角色区分）
- 无子标题（不设 `### {人物名称}`），直接以粗体名称开头
- 单行描述控制在 60 字以内——保持龙套区的轻量感

**龙套示例**：
> **张三**：李四的发小，约25岁，镇上铁匠铺学徒，膀大腰圆，憨厚老实，与李四是酒友。

> **王婆**：村口卖菜的老妇人，六十出头，驼背但眼神精亮，爱嚼舌根但心肠不坏，常给主角塞菜。

## 执行步骤

### 步骤 1：确认输出目录与存档文件

**1.1 定位目标目录**

```
大纲/人物/  →  outline/characters/  →  用户手动指定
```

- 如存在多个项目目录 → 列出供用户选择
- 如不存在 → 提示先运行"创建新书"

**1.2 读取上下文与分卷判断**

- `Read` 读取 `大纲/润色配置.json` → 获取 `大纲.polish_mode` + `分卷` 覆盖项
- `Read` 读取 `大纲/项目信息.json` → 获取 `content_rating`、`nsfw_output_level`、`nsfw_character_tone`、**`volumes`**
- 润色模式影响后续所有交互中对用户输入的加工程度
- NSFW 数据用于人物涉及 NSFW 字段时的词汇选择
- **分卷感知**：根据 `volumes.enabled` + `volumes.multi_file` 判断文件存储路径

**1.3 确定目标文件路径**

根据分卷状态和人物类别确定写入目标：

| 分卷状态 | 人物类别 | 目标文件 |
|---------|---------|---------|
| 不分卷 / 单文件 | 主要角色 | `大纲/人物/主要角色.md` |
| 不分卷 / 单文件 | 次要角色 | `大纲/人物/次要角色.md` |
| 不分卷 / 单文件 | 龙套角色 | `大纲/人物/龙套角色.md` |
| 分卷多文件 | 主要角色（第N卷） | `大纲/人物/卷{N}/主要角色.md` |
| 分卷多文件 | 次要角色（第N卷） | `大纲/人物/卷{N}/次要角色.md` |
| 分卷多文件 | 龙套角色（第N卷） | `大纲/人物/卷{N}/龙套角色.md` |

**1.4 检查目标文件**

| 文件状态 | 处理 |
|---------|------|
| 已存在 | `Read` 读取现有文件 → 准备追加 |
| 不存在 | 按存档文件结构写入顶部框架（书名标题 + 日期 + 卷信息如适用） |
| 卷目录不存在 | 自动创建 `大纲/人物/卷{N}/` 后再创建文件 |

---

#### 步骤 1.5：跨卷人物引用（分卷多文件模式专属）

**仅当** `volumes.enabled=true` 且 `volumes.multi_file=true` 且当前卷号 > 1 时执行。

在用户输入人物名称后，自动搜索旧卷中是否存在同名角色：

1. 扫描 `大纲/人物/卷1/`、`大纲/人物/卷2/` ... `大纲/人物/卷{N-1}/` 下所有三类角色文件
2. 查找同名 `### {人物名称}` 或 `**{人物名称}**` 条目

**找到同名角色时**：

```
🔗 在卷{M}「{卷名}」中发现已存在的「{人物名称}」（{主要/次要/龙套}角色）。

旧卷数据摘要：
  • 性别：{性别}  • 年龄：{年龄}
  • 性格：{一句话概括}
  • 简介：{一句话概括}
  • 关系：{关键关系简述}
  {如有能力} • 能力：{关键能力数值}

是否需要基于旧数据进行变更？
  • 直接引用 — 完整复制旧卷数据（仅更新出场卷标记）
  • 部分变更 — 告诉我哪些字段需要修改（如"性格变了，现在更成熟了"、"能力提升了"）
  • 重新创建 — 当作全新角色从头填写（不引用旧数据）
```

**处理规则**：

| 用户选择 | 处理 |
|---------|------|
| 直接引用 | 复制旧条目全部字段 → 更新 `出场卷` 为当前卷号 → 写入当前卷对应文件；不询问任何字段 |
| 部分变更 | 复制旧条目为底稿 → 按用户指示修改指定字段 → 其余字段保持不变 → 更新 `出场卷` → 写入 |
| 重新创建 | 忽略旧数据 → 进入正常的步骤 2 交互式填充流程 |

**未找到同名角色**：无提示，直接进入正常创建流程。

**跨卷关系继承**：
- 直接引用/部分变更时，旧条目中的 `人物基本关系` 自动带入
- 关系涉及的对方角色如果也在当前卷出场 → 在当前卷的关系同步中处理
- 关系涉及的对方角色如果不在当前卷 → 保留关系记录但标注 `（参见卷{M}）`

### 步骤 2：交互式填充模板

逐项向用户询问模板中的必填字段。按以下顺序进行，每次只问 1~2 个相关字段。

**润色模式影响**（从 `润色配置.json` 读取 `大纲.polish_mode`）：

| 模式 | 对人物字段的加工策略 |
|------|-------------------|
| `轻度` | 直接记录用户原话，转为书面格式——保留用户的用词习惯 |
| `中度` | 在用户原话基础上小幅优化表达（≤45% 改动）——如将口语化描述转为书面化 |
| `重度` | 仅保留原意，对内容进行改写润色和适当扩写——如将一句话描述扩展为一段文字 |

**第一轮 — 基础信息：**

```
👤 人物基础信息

  • 人物类别？（主要角色 / 次要角色 / 龙套角色）
  • 人物名称？
```

| 龙套角色 | 先进入分卷赋值（如项目已分卷）→ 再跳至龙套快速通道 |

**分卷赋值（条件触发）**：

**仅当** `项目信息.json` 中 `volumes.enabled = true` 时执行。

第一轮完成后，询问出场卷：

```
📚 本书已分 {N} 卷（{卷1名} / {卷2名} / ...）。

「{人物名称}」在哪（几）卷出场？
  • 第1卷  • 第2卷  • 第3卷  （可多选）
  • 全卷 — 该角色贯穿全书
  • 暂不确定 — 先不填，后续再补
```

根据用户选择写入 `出场卷` 字段：
- 单选 → `第{N}卷`
- 多选 → `"第1—3卷"` 或 `"第1、3卷"`
- 全卷 → `全卷`
- 跳过 → 留空

**润色模式取用**：
- 如角色仅出现在单一卷，且该卷在 `润色配置.json` → `分卷` 中有独立配置 → 使用该卷润色模式
- 如角色跨多卷或全卷 → 使用全局 `大纲.polish_mode`
- 如无分卷信息 → 使用全局 `大纲.polish_mode`

```
（角色的出身、经历、在故事中的定位。可以是一段话，也可以简要描述）
```

**简介描述正反例**：

| ✕ 不当写法 | ✓ 正确写法 |
|-----------|-----------|
| "他是个很厉害的人，经历了很多事情" | "出身铁匠之家，十岁时村子遭山贼洗劫，父母双亡。被路过的剑客收为弟子，随师学艺八载。十六岁下山，踏上寻找山贼余党的复仇之路——但他更想知道的是，师傅为什么偏偏在那天'路过'。" |

```
  • 人物基本关系？（与其他角色的关系——如"张三与李四：师徒"）
  • 人物能力？（对各项能力打分 1-10——战斗/建造/烹饪/农艺/医疗/社交/智识）
```

- 如用户跳过全部可选内容 → 直接进入步骤 3
- 如填写了人物基本关系 → 在步骤 3.5 中触发双向关系同步

#### 龙套快速通道

当用户在第一轮选择「龙套角色」后，跳过第二轮~第五轮，使用此简化流程。

**L1 — 确认名称**（如第一轮已获取则跳过）：
```
👤 龙套角色名称？
```

**L2 — 一句话描述**：
```
✏️ 请一句话描述「{人物名称}」
（含大致年龄、社会身份/地位、身形特点、性格、简单关系等）

例如：
  "李四的发小，约25岁，镇上铁匠铺学徒，膀大腰圆，憨厚老实，与李四是酒友。"
```

**L3 — 润色描述**：
用户输入后，按润色模式润色该描述——龙套数据视为大纲类内容，应用规范 1.5（大纲类文本特殊处理）。

润色模式取用优先级：出场卷独立配置 → 全局 `大纲.polish_mode`

**L4 — 拼接简化格式**：
将润色后的描述拼接为龙套简化格式：
```
**{人物名称}**（出场：{第N卷/全卷}）：{润色后描述}
```

如项目未分卷，省略 `（出场：...）` 部分。

**L5 — 龙套关系提取**：
从简化描述中智能提取关系（如"李四的发小"→ 关联李四；"常给主角塞菜"→ 关联主角），在步骤 3.5 中触发双向关系同步。

### 步骤 3：写入存档文件

根据用户填写的信息，按人物类别将条目追加到对应类别文件。

**3.1 首次创建（目标文件不存在）**

1. 写入文件顶部框架（书名标题 + 日期 + 卷信息如适用）
2. 写入第一条人物条目

**3.2 追加写入（目标文件已存在）**

1. `Read` 读取对应类别文件（如 `大纲/人物/主要角色.md`）
2. 在文件末尾追加新人物条目
3. 更新文件顶部的 `> 最后更新：{日期}`

**3.3 追加规则**：

| 人物类别 | 目标文件 | 追加方式 | 分隔规则 |
|---------|---------|---------|---------|
| 主要角色 | `主要角色.md` | 完整模板（`### {名称}` ... `---`） | 条目间以 `---` 分隔 |
| 次要角色 | `次要角色.md` | 完整模板（同上） | 条目间以 `---` 分隔 |
| 龙套角色 | `龙套角色.md` | 简化格式（`**{名称}**：{描述}`） | 条目间以空行分隔，不用 `---` |

**3.4 同名人物冲突**：

同一人物名称如已存在于**当前卷的对应类别文件**中：
```
⚠️「{人物名称}」已存在于当前卷的「{人物类别}」文件中。

  • 更新 — 覆盖已有条目（旧数据将丢失）
  • 新建 — 换一个名称重新创建
  • 跳过 — 不做修改
```

**跨卷同名人物**已在步骤 1.5 中处理（跨卷人物引用），此处的冲突检测仅限当前卷文件。

### 步骤 3.5：双向更新人物关系（跨文件搜索）

新人物写入后，如果填写了**人物基本关系**（或龙套的简化描述中隐含关系），必须对所有关联的老角色执行双向更新。

**解析关系来源**：

| 来源 | 解析方式 |
|------|---------|
| 主要/次要角色的「人物基本关系」 | 从 `{角色A}与{角色B}：{关系描述}` 格式解析 |
| 龙套角色的简化描述 | 智能提取——"李四的发小"→ 关联李四；"张三的妻子"→ 关联张三；"常给主角塞菜"→ 关联主角 |

**搜索范围**（分卷多文件模式）：
- 优先搜索**当前卷**的三类角色文件（`大纲/人物/卷{N}/主要角色.md`、`次要角色.md`、`龙套角色.md`）
- 若当前卷未找到 → 搜索**旧卷**的对应文件（`大纲/人物/卷1/`、`卷2/`...）
- 不分卷/单文件模式 → 仅搜索 `大纲/人物/` 下的三个文件

**更新老角色**：

1. 在搜索范围内找到被关联的角色条目
2. 在该角色的「人物基本关系」区块追加反向关系
3. 如老角色原本没有「人物基本关系」字段 → 在人物能力之后新增该字段
4. 如老角色已有关系 → 将新关系追加到列表末尾（不覆盖已有关系）
5. 如老角色位于旧卷文件 → 同步更新该旧卷文件中的条目

**示例**：
```
创建「张三」（新角色，卷2），关系：张三与李四：师徒关系

→ 写入张三条目后，查找李四
→ 李四在卷1的「次要角色.md」中找到
→ 在卷1「次要角色.md」李四条目的「人物基本关系」中追加：
  - 李四与张三：师徒关系（卷2）
```

**双向更新输出**：
```
🔄 已同步更新以下角色的关系：
  • 李四（次要角色，卷1）→ 新增关系：与张三：师徒关系
```

**边界情况**：
- 关联的角色不在任何存档中 → 仅在新角色中保留关系记录，不做反向写入（等该角色创建后再补）
- 关系描述中角色名包含别名 → 尝试模糊匹配，匹配不到时提示用户确认
- 旧卷角色更新时 → 更新 `最后更新` 日期

## NSFW 内容规则

NSFW 字段（XP、三维、性特征、人物X能力）写入对应类别角色文件，不独立存储。

### 触发方式 — 仅用户主动提及时启用

- 正常创建流程**不询问** NSFW 字段——模板中 NSFW 字段仅标记为可选项存在
- 用户在创建人物时主动提及 NSFW 内容（如"加个XP"、"补充X能力"），才在对应字段写入
- 用户也可创建人物后追加 NSFW 资料——直接在该角色的类别文件中补充

### NSFW 词汇选择协调

当用户填写 NSFW 字段时：

1. `Read` 读取 `大纲/项目信息.json` 中的 `nsfw_output_level` 和 `nsfw_character_tone`
2. 若已配置 → 参照 NSFW 技能的词汇表，根据 `nsfw_output_level` 选择对应级别的用词：

| nsfw_output_level | 用词风格 | 示例 |
|------------------|---------|------|
| `优雅级` | 优雅代称 | 酥胸、玉茎、花径 |
| `直白级` | 直白露骨 | 奶子、大肉棒、小穴 |
| 空（未配置） | 中性/自然用词 | 胸部、阴茎、阴道 |

3. 若未配置 → 以中性用词写入，同时提示：
```
💡 提示：项目尚未配置 NSFW 输出词偏好。配置后所有 NSFW 字段的用词风格将保持一致。
   是否需要配置？（可说 /nsfw-config 随时配置）
```

### 写入位置

- NSFW 字段直接写入人物条目中，标注「（可选，NSFW）」
- XP、三维、性特征 → 写在身形特点之后、人物性格之前
- 人物X能力 → 写在人物能力之后

## 注意事项

- **已提供的信息不重复问**：用户在消息中已附带部分信息（如"创建一个叫张三的主角"），直接提取使用，跳过对应询问
- **可选字段允许跳过**：标记为"（可选）"的字段（人物基本关系、人物能力），用户明确说"跳过"时直接进入下一步
- **NSFW 不纳入例行询问**：正常流程中不出现 NSFW 字段询问——避免非 NSFW 用户感到不适
- **人物能力数值范围 1~10**：如用户不确定可留空
- **追加写入不破坏已有内容**：仅在对应分区末尾追加，不修改已有人物条目
- **写入必经成品校验**：角色文件组装完成后，调度 `成品输出校验`（`type: "structured_md"`, `md_category: "角色"`, `file_path`）→ 由校验技能执行字段完整性/双向关系校验后统一落盘。禁止自行 Write
- **同名人物更新需用户确认**：同一名称已存在时，明确告知覆盖风险后等待用户选择
- **龙套角色特殊规则**：
  - 使用简化模板（单行格式），不询问外貌/性格/能力等详细字段
  - 龙套描述按大纲档位润色后写入
  - 龙套条目之间以空行分隔，不使用 `---` 分隔线
  - 龙套不询问 NSFW 字段
- **人物关系延迟同步**：新角色引用了尚未创建的角色时，关系仅在新角色侧写入——待该角色创建后再补反向关系
- **分卷感知**：项目启用分卷后，创建人物时自动询问出场卷；人物条目中写入 `出场卷` 字段；润色模式按出场卷取对应配置
- **分卷多文件角色目录**：分卷多文件模式下，角色按 `大纲/人物/卷{N}/` 子目录存放三类文件，每卷角色独立管理
- **出场卷可留空**：用户选择"暂不确定"时出场卷字段写入空值，后续可通过编辑人物补充
- **跨卷人物引用**：分卷多文件模式下新建人物时自动搜索旧卷同名角色，支持直接引用/部分变更/重新创建
- **三类文件独立存储**：`主要角色.md` / `次要角色.md` / `龙套角色.md` 各自独立，不混合存储
- **始终以 Markdown 格式保存**：中文文件名 `主要角色.md` / `次要角色.md` / `龙套角色.md`；English `main-characters.md` / `supporting-characters.md` / `extras.md`
