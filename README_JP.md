# Writing Techniques — 怠け者のための執筆ツールキット

> アマチュアによる Vibe Coding プロジェクト。プレーンテキストで動作する、怠け者向けの執筆ツールキット。AI 支援で制作し、不定期に専門スキルを追加更新します。

V1.0

## これは何か

Claude Code 上で動作する執筆スキルパック。小説創作の立ち上げから本文執筆までの全プロセスをカバーします。パッケージの内容は Markdown と Json ファイルのみです。

## 推奨構成

- `アウトプット校正` は専用の Agent に任せることを推奨——メイン会話のコンテキストを消費しません
- `プロンプト強化` は全自動モードではなく**アシスト作成モード**の利用を推奨——少なくとも各章・各フェーズで見たい展開を AI に伝えるだけで、ゼロプロンプトの全自動生成よりはるかに高品質になります
- プロンプトエンジニアリングは現段階で AI を導く最良のツール——一章分の良いプロンプトを数分で書く方が、後から本文を何度も修正するより効率的です

## スキル一覧

```
企画/    新規作成 · 人物作成 · プロット編集 · 設定編集 · クイック再構築
執筆/    ルーター（Write-Router）· コア（基本執筆支援）
         専門（戦闘[決闘+戦争サブ項目] · 恋愛 · 長編）
         補助（プロンプト強化 · アウトプット校正）
その他/  学生作文
```

**テンプレートライブラリ（templates/）**：設定系テンプレートのフィールド定義を統一的にスキーマ化（人物/設定/プロット/プロジェクト設定など）——フィールド追加は JSON 一箇所を変えるだけ、生成と検証が同期してズレません。

**規範ライブラリ（body/Core/norms/）**：執筆規範をコンテンツタイプ別にファイルへ分割し、Core が必要に応じて読み込みます——本文執筆の読込量 -50%、規範追加はファイル作成 + 登録一行のみ。

**仕様データ（data/）**：大量データ（内容検出/配信プロトコル/校正チェックリスト/伏線仕様/章の緊張ガイドなど）を外部化し、`data-registry.json` に登録・参照されたものだけが有効——SKILL.md の肥大化を防ぎます。

## 設計思想

- **テンプレートライブラリ駆動**：設定系テンプレートのフィールドを JSON スキーマ化（`templates/`）——フィールド追加は JSON 一箇所、生成と検証が同期
- **データ外部化で肥大化防止**：大量データ（語彙/プロトコル/閾値）は `data/` に外部化し、SKILL.md はルールとフローのみ——`data-registry.json` に登録・参照されたものだけが有効
- **手続き型規範ライブラリ**：Core を「実行エンジン + 規範ライブラリ（オンデマンド読込）」に再構築——コンテンツタイプ別にグループ読み込み、本文執筆の読込量 -50%、アウトラインシーン -75%；規範追加はファイル作成 + 登録一行のみ
- **仕様データの一回読込**：プロトコル/チェックリスト/閾値データは初回ディスパッチ時に作業記憶へ丸ごと読み込み、以降は記憶で実行——仕様変更/新セッション時に再読込
- **フィールド単位の精密さ**：field_name プロトコル検証 + フィールド→加工標準マッピング + `facts` 制約ブロックをデータパケットと共に配信——OOC 制約を執筆前に前倒し
- **本文の張力二重構造**：フェーズ別イベント強度（tension_level L1-L5）+ 章分類別の二次計画（chapter_type 7 種）——張力はイベント配置のみを導き、執筆パラメータには紐づかない；伝導と誘導は分離
- **物語品質の強化**：プロット計画の 6 次元チェックに物語品質次元を追加——波動モデルのソフト誘導 + プロットポイント四要素の強制 + 衝突の二類型 + コスト免除
- **怠け者に優しい**：会話こそ操作——自動化できるものは自動化、推論できるものは質問しない、デフォルトで足りるものは選ばせない
- **適応ルーティング**：自然言語の意図認識 → 対応サブスキルへ自動ディスパッチ、コマンド暗記不要
- **全フローの直列化**：標準執筆パイプラインは Write-Router が単独駆動（ユーザープロンプト → ルーター → Core+専門 → 長編 → アウトプット校正）、各スキルは疎結合で独立

## 標準的な制作フロー

```
新規作成 ──→ 人物作成 ──→ 設定編集 ──→ プロット編集
                                          │
                                          ▼
                                     プロンプト強化
                                          │
                                          ▼
                                  Write-Router（本文執筆）
                                        ├→ Core（一般）
                                        ├→ Combat（戦闘）
                                        └→ Romance（恋愛）
                                          │
                                          ▼
                                 長編専項 → アウトプット校正
```

> フローは強制ではありません——どの段階からでも飛び込めます。既存設定があるなら「クイック再構築」から始めるのが楽です。

## 使い方

Claude Code にインストール後、自然言語でそのまま話しかけるだけです：

**プロジェクト作成**
- 「新しい本を作成」→ プロジェクト起動、メタデータ収集
- 「クイック再構築 / 旧作を移行」→ 既存設定の高速再構築

**アウトライン計画**
- 「キャラクター作成」→ キャラクター追加（モブ快速レーン対応）
- 「プロット編集」→ 三モードでストーリーラインを計画
- 「設定編集」→ 五大セクションで世界観を磨く

**本文執筆**
- 「本文を書く / この文章を磨く」→ Write-Router にルーティング → コンテンツタイプ自動検出 → ディスパッチ
- 「第X章を書く」（プロンプトなし）→ プロンプト強化を自動ディスパッチして指示を生成
- 「戦闘シーンを書く / この戦いを磨く」→ 戦闘描写専項を自動ディスパッチ
- 「戦争 / 会戦 / 攻城を書く」→ 戦闘描写専項の warfare サブ項目を自動ディスパッチ（小から大へ：司令部/参謀部/最前線のシーンを組み合わせる、ソフト誘導）
- 「恋愛シーンを書く / この甘い場面を磨く」→ 恋愛描写専項を自動ディスパッチ

**伏線管理**
- 「これは伏線です」（本文中に注記）→ 自動登録
- 「伏線XXを回収」→ 回収済みに更新
- 「伏線を見る / 未回収はどこ」→ 全書伏線リスト + 状態診断
- 「第X章で何があったか」→ 章をまたぐプロットの回想

**品質チェック・その他**
- 「チェックして / 句読点を検査」→ アウトプット校正（句読点+構造の二重スキャン、違反は自動修正）
- 「作文を手伝って」→ 学生作文モード（小中高）

## プロジェクト構成（作成後）

```
{書名}/
├── Outline/
│   ├── Project_Info.json        ← メタデータ：書名/長さ/ジャンル（権威データソース）
│   ├── Writing_Config.json      ← アウトライン&本文の独立した磨きレベル、分巻上書き対応
│   ├── Settings/Settings.md     ← 世界観/コア設定/サブ設定
│   ├── Characters/Character_Archive.md ← 全キャラクター統一アーカイブ（主要/次要/モブ）
│   └── Plot/Plot_Outline.md + Prompt.md（一括生成の執筆プロンプト）
├── Main_Text/                   ← 正規章（Ch_XX Chapter_Title.md）
└── Extras/                      ← 番外篇（Extra_Title_(X).md）
```
