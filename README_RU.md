# Writing Techniques — Инструментарий для ленивого писателя

> Любительский Vibe Coding проект — инструментарий для письма в ленивом стиле на основе простого текста. Создание с помощью ИИ, время от времени обновляется новыми специализированными навыками письма.

V1.0

## Что это

Набор навыков письма, работающий в Claude Code, покрывающий весь процесс создания романа — от запуска проекта до итогового текста. Пакет навыков состоит только из Markdown и JSON файлов.

## Рекомендуемая настройка

- Поручите `Вычитку готового текста` отдельному Agent, чтобы не тратить контекст основного диалога
- Используйте `Улучшение промптов` в **режиме ассистируемого создания**, а не полностью автоматическом — хотя бы скажите ИИ, что вы хотите увидеть в каждой главе или на каждом этапе; качество вывода намного выше, чем при полностью автоматической генерации без промпта
- Инженерия промптов остаётся лучшим инструментом управления ИИ на этом этапе — несколько минут на хороший промпт для главы эффективнее, чем многократные правки текста после

## Список навыков

```
Планирование/   Новая книга · Создание персонажа · Редактирование сюжета · Редактирование сеттинга · Быстрое воссоздание
Письмо/         Роутер (Write-Router) · Ядро (Базовая помощь в письме)
                Специализированные (Бой [дуэли + подгруппа война] · Романтика · Длинная форма)
                Вспомогательные (Улучшение промптов · Вычитка готового текста)
Другое/         Школьное сочинение
```

**Библиотека шаблонов (templates/)**: Определения полей шаблонов сеттинга (персонаж/сеттинг/сюжет/конфигурация проекта и т.д.) единообразно схематизированы — добавление поля касается одного JSON-файла, генерация и валидация остаются синхронизированными.

**Библиотека норм (body/Core/norms/)**: Нормы письма сгруппированы по типу контента в отдельные файлы, загружаются Ядром по требованию — загрузка прозы -50%, добавление нормы = один файл + одна строка в реестре.

**Спецификации данных (data/)**: Объёмные данные (определение контента / протокол распределения / чеклист вычитки / спецификация форшэдоуинга / гайд по напряжению глав и т.д.) вынесены сюда, зарегистрированы через `data-registry.json` и действительны только при обращении — не даёт SKILL.md разрастись.

## Философия дизайна

- **Управление библиотекой шаблонов**: поля шаблонов сеттинга схематизированы в `templates/` — добавление поля = правка одного JSON, генерация и валидация синхронны
- **Внешние данные против раздувания**: объёмные данные (словари/протоколы/пороги) живут в `data/`, в SKILL.md только правила и потоки; файлы данных действительны лишь будучи зарегистрированными в `data-registry.json`
- **Процедурная библиотека норм**: Ядро переработано в «движок выполнения + библиотеку норм по запросу» — групповое чтение по типу контента, загрузка прозы -50%, сцен плана -75%
- **Одноразовая загрузка спецификаций**: протоколы/чеклисты/пороги загружаются в рабочую память один раз при первом запуске, далее выполняются по памяти; перечитываются только при изменении спецификации или новой сессии
- **Точность на уровне полей**: валидация протокола field_name + маппинг поле→стандарт обработки + блоки ограничений `facts`, доставляемые вместе с пакетами данных — ограничения OOC переносятся до начала письма
- **Двойная структура напряжения глав**: интенсивность событий на уровне этапов (tension_level L1-L5) + вторичное планирование типов глав (chapter_type, 7 типов) — напряжение управляет только расстановкой событий и никогда не привязывается к параметрам письма; проведение и управление разделены
- **Повышение качества повествования**: шестимерная проверка сюжета получила измерение качества повествования — мягкое управление волновой моделью, обязательные четыре элемента сюжетной точки, двойной тип конфликта, освобождение от цены
- **Ленивость**: диалог как действие — автоматизируй что можно, угадывай что можно, используй значения по умолчанию где можно
- **Адаптивная маршрутизация**: распознавание намерения на естественном языке → автоматическая отправка в нужный суб-навык, не нужно запоминать команды
- **Сквозной конвейер**: стандартный конвейер письма полностью управляется Write-Router (промпт пользователя → роутер → Ядро+специализированные → длинная форма → вычитка готового текста); навыки слабо связаны

## Типичный рабочий процесс

```
Новая книга ──→ Создание персонажа ──→ Редактирование сеттинга ──→ Редактирование сюжета
                                                                      │
                                                                      ▼
                                                              Улучшение промптов
                                                                      │
                                                                      ▼
                                                             Write-Router (Письмо)
                                                                   ├→ Ядро (общее)
                                                                   ├→ Combat (бой)
                                                                   └→ Romance (романтика)
                                                                      │
                                                                      ▼
                                                    Длинная форма → Вычитка готового текста
```

> Рабочий процесс не обязателен — входите на любом этапе. Если уже есть готовый сеттинг, начните с «Быстрого воссоздания».

## Как использовать

После установки пакета навыков в Claude Code просто общайтесь на естественном языке:

**Создание проекта**
- «Создать новую книгу» → запуск проекта, сбор метаданных
- «Быстрое воссоздание / перенести старую работу» → быстрая миграция существующего сеттинга

**Планирование плана**
- «Создать персонажа» → добавить персонажей (с быстрой полосой для эпизодических)
- «Редактировать сюжет» → планирование сюжетной линии в трёх режимах
- «Редактировать сеттинг» → проработка мира в пяти разделах

**Написание текста**
- «Написать текст / отполировать этот отрывок» → маршрутизация в Write-Router → автоопределение типа контента → распределение
- «Написать главу X» (без промпта) → автоматическое привлечение «Улучшения промптов» для генерации инструкций
- «Написать боевую сцену / отполировать этот бой» → автоматическая отправка в специализированный навык «Бой»
- «Написать войну / сражение / осаду» → автоматическая отправка в подгруппу warfare навыка «Бой» (от малого к большому: командный пункт / штаб / фрагменты сцен на передовой, мягкое управление)
- «Написать романтическую сцену / отполировать этот флирт» → автоматическая отправка в специализированный навык «Романтика»

**Управление форшэдоуингом**
- «Это форшэдоуинг» (отмечено в тексте) → автоматическая регистрация
- «Разрешить форшэдоуинг XX» → обновить статус на «разрешён»
- «Показать форшэдоуинги / что ещё не раскрыто» → полный список с диагностикой статусов
- «Что было в главе X» → воспоминание сюжета между главами

**Проверка качества и прочее**
- «Проверить / проверить пунктуацию» → вычитка готового текста (двойное сканирование: пунктуация + структура, автоматическое исправление нарушений)
- «Помогите написать сочинение» → режим школьного сочинения (1-11 класс)

## Структура проекта (после создания)

```
{Название книги}/
├── Outline/
│   ├── Project_Info.json        ← Метаданные: название / объём / жанр (авторитетный источник)
│   ├── Writing_Config.json      ← Независимый уровень полировки для плана и текста, поддержка переопределений по томам
│   ├── Settings/Settings.md     ← Мироустройство / ключевые настройки / второстепенные настройки
│   ├── Characters/Character_Archive.md ← Единый архив всех персонажей (основные / второстепенные / эпизодические)
│   └── Plot/Plot_Outline.md + Prompt.md (сгенерированные промпты)
├── Main_Text/                   ← Основные главы (Ch_XX Chapter_Title.md)
└── Extras/                      ← Побочные истории (Extra_Title_(X).md)
```
